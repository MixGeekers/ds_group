## E1：宿主选 Web；浏览器和核心生命周期分开

**上游声明，已阅读：**[CLI reference](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/apps/cli/reference/README.md>)描述 `dsh web --no-open`、默认 `127.0.0.1:3080`、具体地址绑定、profile / home / CLI patch 覆盖次序。生产 Web 需要已构建产物。第一次停止信号最多给插件树 5 秒；SIGTERM 退出 0、SIGINT 退出 130；第二次强退。public-url 只是公告地址。该资料同时说明 Session 额外日志贡献和 OTel 上传是不同路径。

**设计结论：**专用 DSH_HOME / Web profile / 固定插件清单，主机本地 FS；关闭浏览器后仍由同一 DSH 进程承载核心。识雨 drain 目标 4 秒。macOS 首验证依赖用户登录与唤醒；若要求无人登录持续运行，迁移同样的 Web 宿主到 Linux systemd，仍保持 A 的单核心。不选一次性 headless 或缺少完整审批设施的 sdk-minimal 作常驻替代。

**适配限制：**远程设备不能全局替换主 Web 的 fs/subprocess provider。SSH provider 对路径和 UI 的限制由[设备适配证据](<设备执行面.md>)维护；独立执行 scope 不成立时采用设备区的受限 OpenSSH wrapper。本文没有运行这些命令或配置 LaunchAgent。

## E2：Agent 建立前收紧作用域；Session 不是业务账本

**上游声明，已阅读：**[core API](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/docs/subsystems/core.md>)的 `ctx.agents.create / resume` 支持 setup，在 Agent 发布与首个 prompt 前安装作用域注册；失败清理创建过程。Agent.whenIdle 只表示运行状态，不能证明特定输入已完成。[Session 文档](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/docs/subsystems/session.md>)提供显式 flush 持久化边界。

**设计结论：**独立 shiyu-dialogue / core / worker preset；输入先进入领域 inbox，不能先经过宽权限通用 Agent 的工具循环。setup 注册 role allow-list、Guard 和 pre-step；恢复也重新核对当前策略。Session 用于推理记录，Task、世代、授权和完成回执在领域库。跨 Session 与领域库通过幂等投影和恢复核对连接，不声称跨库原子。

## E3：工具作用域是受信代码边界，不是隔离容器

**上游声明，已阅读：**[tools.md](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/docs/subsystems/tools.md>)明确 ToolRestriction 过滤继承注册，本 scope 的 own 注册随后覆盖且豁免；deny-only 允许后来未列名工具。Guard 只能进一步拒绝。自定义 executor 可以自行执行，不必经过默认 pipeline。defineTool / raw JSON Schema 只支持宿主声明的子集，未知关键字拒绝。

**源码交叉核查：**协作 agent 静态阅读 [tools registry / dispatcher](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/core/tools/src/index.ts>) 的 view、execute、guard 路径，见[情绪人格能力证据](<情绪人格能力.md>)；本分工直接阅读上述文档，未将协作核查冒称自己重读了全文件。

**设计结论：**插件与 executor 固定准入；只读 replyer 默认 tools=[]；worker 只拥有具名 broker 工具。工具注册检查与调用时 Mandate / actor / resource / fence 检查同时存在。EffectDispatcher 在外部动作前再授权。MCP 服务和同进程插件视为受信代码；任意恶意插件并非本边界可抵御。不信任扩展进入独立受限进程。领域契约用 Ajv 2020-12，转换为 DSH 工具 schema 时显式适配，不能直接宣称兼容所有关键字。

## E4：DSH 存储公开接口不足以做领域状态 + outbox 的跨表事务

**源码静态核查：**

| 文件 | 已核查事实 | 影响 |
|---|---|---|
| [storage/src/backend.ts](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/storage/storage/src/backend.ts>) | KvUnit 公开 loadAll、putRecord、deleteRecord、deleteRecords、setGlobal、close；无通用 transaction 回调或连接借用 | 不能把多次领域写调用自动视为一笔事务 |
| [storage-domain/src/domain.ts](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/storage/storage-domain/src/domain.ts>) | 每 domain 排队写入；先后端持久化，再更新内存和发 domain/changed；deleteMany 是同表批删；注释明确 changed 是提交后通知 | 通知处理器再写 outbox 存在崩溃窗口；事件总线不是 outbox |
| [storage-sqlite/src/index.ts](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/storage/storage-sqlite/src/index.ts>) | 一个 private DatabaseSync 连接并维护 open-unit 表；导出 backend，不提供领域事务句柄 | 不反射或借用私有连接，避免升级破坏与并发不明 |

**上游声明，已阅读：**[storage-sqlite README](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/storage/storage-sqlite/README.md>)说明内部原子性覆盖单记录、批删和格式版本更新；同步 driver 会阻塞 JS 线程，没有 busy-wait / 重试策略，未知回滚状态需关闭后重开核对。这不能扩展成任意领域写集的保证。

**设计结论：**识雨专用一个 SQLite 数据库和薄 Repository / UnitOfWork；同一短事务写状态、commitSeq、事件、回执与 outbox。各领域保留命令规则，CoreCommitService 只提供受控提交入口。DSH 自有 Session/config 留在宿主存储。网络、模型和文件下载不在数据库事务内。不得用双库两次 commit 或 domain/changed 冒充原子事务。

**集成补充：**数据分工依据 [Node v24 worker_threads](<https://nodejs.org/docs/latest-v24.x/api/worker_threads.html>) 核查稳定线程 API，采用同进程专用 DB WorkerThread 承载 DatabaseSync 和 UoW；受控命令经单 MessagePort 进入，线程内验证授权版本与 CAS，禁止传任意 SQL / 函数。该选择避免同步 busy 等待冻结主事件循环，不能提供 OS 隔离或更高磁盘吞吐。基线同库 FTS5 / search_docs 随权威聚合与相关水位同事务更新，分词准备在事务外；详见[数据证据](<数据空间.md>)和[索引方案](<../../架构与设计/A方案全景/06-预留空间/05-索引与缓存/README.md>)。这些为集成后的设计建议，不是本轮新增运行实测。

**验收：**V14 注入 state 写完但 outbox 前的错误；两者必须共同提交或共同回滚。V24 检查真实进程中断、writer 串行、恢复核对和 Session 投影重放。若 dedicated adapter 不满足，冻结主动派发并改换成熟 SQLite driver；不降低事务语义。

## E5：调度可复用，但持久受理与执行必须另有回执

**上游声明，已阅读：**[schedule README](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/schedule/schedule/README.md>)指出：依赖宿主持续运行；重启只投递最近一次遗漏的周期事件；Session flush 与 schedule receipt 是分开提交，崩溃可重复。receipt 证明输入持久化，不保证执行；优雅 dispose 可丢弃已排队输入。失败没有自动 retry loop，后续操作、唤醒或重启可重试。管理范围是 Host-wide，没有任务级授权；按次新 Session 可并发。

**设计结论：**复用 Cron/RRULE 和宿主唤醒；外围 wrapper 限定可操作 schedule ID、授权和幂等键 `scheduleId + occurrence`。首次受理先写业务 inbox，业务执行另受 TaskService 并发与预算。到期 Goal 使用索引扫描作为确定性恢复动作，默认 30 秒 / 每批 100；不是新造持久调度引擎，也不逐秒调用模型。

## E6：模型路由与重试复用宿主，预算和外发由识雨约束

**上游声明，已阅读：**[LLM streaming](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/docs/subsystems/llm-streaming.md>)定义 adapter、流与模型能力注册；模型目录不等于 adapter 一定存在。[llm-retry](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/llm/llm-retry/README.md>)说明原生 adapter 单次调用、禁用 SDK 重试；normal 默认最多 5 次重试，always 无有限上限；原始 stream 调用本身不提供完整 Agent 重试流程。

**设计结论：**先以一个已有授权的原生 DeepSeek 路由服务三个角色；具体 provider/model 在验证清单解析固定，无凭据先用替身。备用路由必须提前批准同等用途与数据范围。normal 最大重试覆写为 2，全部尝试计预算；不叠加外层完整重试循环。总模型并发 3，后台 core+worker ≤2，显式对话保留 1；core 自动评估并发 1，worker Assignment 最多 2；设备资源另行独占。真实 provider 启用前必须有费用、调用次数、总时间和最大输出 token 四项可执行限额。

**外发控制：**模型必要输入与额外日志上传分别检查。关闭额外 DeepSeek Session 贡献和 OTel 上传是本方案默认，不是本机已生效事实；有效配置受多层覆盖，需 V13/V24 检查实际网络目的地和载荷。具体价格取验证当天官方表，不固定长期价格，也不新增未授权供应商。

## E7：Node / SQLite 版本门槛及成熟 driver 备选

**官方版本证据：**[Node 版本表](<https://nodejs.org/en/about/previous-releases>)及[24.22.2 下载归档](<https://nodejs.org/en/download/archive/v24.22.2>)支持选择 24 LTS 线的固定候选。标签源码 [deps/sqlite/sqlite3.h](<https://github.com/nodejs/node/blob/v24.22.2/deps/sqlite/sqlite3.h#L149-L155>)声明 SQLite `3.53.4`；[doc/api/sqlite.md](<https://github.com/nodejs/node/blob/v24.22.2/doc/api/sqlite.md>)在该标签将 node:sqlite 标为 Stability 1.2、Release candidate，不能称完全稳定。标签是静态来源，不证明之后下载的二进制实际链接结果。

**SQLite 官方限制：**[WAL 文档](<https://www.sqlite.org/wal.html#walreset>)记载 WAL-reset 修复从 3.51.3 起，3.44.6 / 3.50.7 有回补；WAL 需同机本地文件系统。设计要求实际检查 sqlite_version、compile_options 和事务/备份 API；默认接受 ≥3.51.3，低版本只有确证回补才例外。数据区管理 WAL、checkpoint、单 writer、FULL 同步和备份；本轮未运行任何 SQLite 查询。

**备选：**若 node:sqlite 的 API 或发布状态在 V24 造成明确阻碍，评估 [better-sqlite3 README](<https://github.com/WiseLibs/better-sqlite3/blob/master/README.md>) 提供的同步事务 driver，固定其版本、预编译产物和 SQLite 版本后复用相同 Repository 契约；其[许可证](<https://github.com/WiseLibs/better-sqlite3/blob/master/LICENSE>)为 MIT。该备选未选定版本、未安装，不能直接依赖浮动 master 上线；其触发条件清楚，主基线无需等待它完成。
