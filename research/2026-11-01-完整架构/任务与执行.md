## 1. 主方案与收益判断

**建议基线：DSH 执行适配 + SQLite 事务账本 + 识雨必要的薄 TaskService。** SQLite 提供事务与约束，DSH 提供模型、Session、工具和插件生命周期。识雨只定义授权、领域状态迁移、结果证据和受控提交规则，不自建数据库、通用 Agent loop 或分布式编排平台。

DSH-Superagent 是固定源码的参考实现，不作为可直接安装的完整任务层；识雨需要非 GitHub 任务、多设备副作用、内部只读边界和删除生命周期，现有原型并不自动满足这些要求。可在未来实现阶段逐段移植经许可审查的事务 / 回执适配代码与测试案例，届时保留 MIT 版权声明并补识雨语义测试；本轮未复制其源码进入产品目录。

## 3. DSH 宿主接口限制

同轮[宿主专题](<宿主与依赖.md>)静态核查固定 DSH `ce7073d51254c26cd63b22a60835b8f948deb447`：

- [storage-domain/domain.ts](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/storage/storage-domain/src/domain.ts>) 暴露逐记录操作及同表 deleteMany；[storage/backend.ts](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/storage/storage/src/backend.ts>) 的 KvUnit 未提供任意跨记录事务接口。不能用多个调用保证 Task + Effect + outbox 原子性。
- 宿主代理创建阶段的 setup、工具 restrict 和 guard 可用作角色接点；scope 自有工具 / 自定义 executor 仍需准入，最终 Broker 不能只信继承白名单。精确调用方式和限制以宿主专题证据为准。
- 因此选择专用 SQLite 事务 Repository 是补足领域一致性边界，不是重造存储引擎；优先沿用宿主的 Node 运行时、生命周期与已验证驱动。

## 4. 成熟基础设施资料

| 官方来源（2026-11-01 阅读） | 来源支持的事实 | 设计推论及限制 |
|---|---|---|
| [SQLite 事务保证](<https://www.sqlite.org/transactional.html>) | SQLite 提供原子、一致、隔离与耐久事务，并有故障模拟回归测试 | 用于本地权威账本；远端网络动作不属于 SQLite 的同一事务，具体文件系统 / 配置需在验证阶段检查 |
| [SQLite Transaction](<https://www.sqlite.org/lang_transaction.html>) | 允许多个读事务、一个同时写事务；BEGIN IMMEDIATE 可在入口遇到 SQLITE_BUSY；savepoint 支持嵌套处理 | 使用短事务、有限等待和单写入通道；网络和模型调用留在事务外，不把长业务流程包进一个写事务 |
| [Temporal Workflow](<https://docs.temporal.io/workflows>) | Workflow 用持久事件历史重放并要求确定性；外部动作由 Activity 承担 | 若确需多中心长流程，优先评估成熟 Temporal；当前 A 单中心不默认增加服务与另一套派发权。不能用工作流重放本身推导任意外部动作恰好一次 |
