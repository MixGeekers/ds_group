## 设计选择与复用收益

- **DSH 复用：**推理、Session 生命周期、工具和事件沿用宿主接口。识雨只新增自身领域规则与适配层，不造第二套 Agent loop。
- **事务复用：**采用成熟 SQLite 原子性，参考 Superagent 将领域变更与持久待执行记录一起组织的方式。识雨新增 CAS、权限和身份约束，因为它的状态、设备及只读外层与编码原型不同。
- **校验复用：**协议以 JSON Schema 2020-12 + Ajv 8 为基线；只编译受信的随插件发布的 Schema，禁止模型提供动态 schema、正则或代码。DSH 的工具参数子集另作适配。不得因 JSON 校验成功便省略授权和领域不变量检查。
- **视图复用：**短读事务、纯程序投影和派生索引即可表达首版读视图；不引入单独模型、CQRS 平台、缓存集群或新的状态数据库。

## 属于识雨自己的建议，不能归因于上游

CoreCoordinator / CoreCommitService / ViewService 的组合、六域职责、双序号、Proposal readSet、authEpoch 和删除强失效、主动节流、静默、预算参数，以及 V01 / V04 / V06 / V09 / V23 验收门槛，均是本轮架构建议。上游没有替识雨验证这些语义。

尤其不从 SQLite 的单写性质推出跨模型决策天然无冲突；不从读快照推出 viewId 可长期复用；不从角色接口类型推出恶意同进程插件被隔离；不从有 outbox 推出消息或设备动作必然恰好一次。
