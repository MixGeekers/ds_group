## 2. 方案选择与未采用项

| 问题 | 建议基线 | 暂不采用的路线与重新比较条件 |
|---|---|---|
| 情绪与感受（后续修订） | 优先联合复用Ombre情绪记忆/feel/dream；短时状态非默认 | 独立情感 Agent、用户情绪识别模型、心理量表引擎；仅当规则基线不能满足经验证的交互需求时再比较 |
| 稳定人格（后续修订） | Ombre I候选＋小型Profile受控映射，复用DSH prompt入口 | 持续训练、自动重写人格；只有稳定配置不能覆盖已测需求且收益足够才评估 |
| 工具与设备能力 | DSH 工具与 MCP 执行，能力定义 + 实例健康 + 验证记录分别管理 | 自建通用工具总线、另建多 Agent 运行框架；现有扩展点被明确验证无法满足要求时再讨论 |
| 技能复用（后续修订） | 直接用DSH ctx.skills、filesystem provider、tool-skill，追加批准内容绑定 | 新技能运行时、自动下载并执行任意脚本；格式不兼容时先作为只读手册使用 |
| 状态校验 | 宿主 schema 子集与内部 CAS / 字段白名单；需要时用成熟标准校验器 | 自研 schema 语言、以自然语言提示代替权限校验 |

默认数值、半衰期、验证有效期、发布样本数和收益门槛都属于**设计建议**，没有研究论文或本轮实测为其背书。它们用于使验证计划可以执行，并允许下一阶段依据结果调整。没有证据证明独立人格 / 情绪模型对当前识雨任务带来足够收益，因此不将其列为首期依赖。

## 3. 跨模块约束

- Proposal 统一使用 `proposalId/schemaVersion/actor/sourceRefs/baseStateVersion/readSet/policyVersion/commands/idempotencyKey/expiresAt`；CAS 按涉及实体的 expectedVersion 判断，不因无关状态更新而全部失败。
- `commitSeq` 随业务事务递增，`stateVersion` 仅内层状态变更递增，各实体 `revision` 独立。只读衰减不会改变任何这些序号。
- ReadView 使用统一 scopeHash、authEpoch、tombstoneWatermark 等失效信息，删除 / 撤权强制失效；状态新鲜度不是访问授权。
- 记忆与认知提供 sourceRefs / dependencyRefs / EvidenceRevoked；明确用户偏好与模型推断分开，删除传播不留下可重识别摘要。
- 能力领域维护定义、发布和验证标准；DeviceGateway 维护设备实例、健康、租约与路由，二者通过 capabilityId + version + deviceId 关联。
- 运行健康事实与人格 / 情绪 / 正式能力声明分开，不以每次心跳更新整个人格或记忆。
