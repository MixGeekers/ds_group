## 逐模块决策

| 模块 | 主复用路径 | 必要的识雨适配 | 应从原规划删除的重复建设 |
|---|---|---|---|
| providers | 配置 DSH 的 API-key/account provider 或 llm-pi-ai；直接调用既有 LlmRuntime | provider/model 到角色的批准映射、用途与费用预算、外发范围 | 自建模型 SDK、多厂商网关、模型目录缓存、SSE 转换器 |
| model-session | ctx.agents.create/resume、Agent.model.select、Session flush、llm-retry、BlockAssembler | 业务 ID 绑定、角色提示与工具配置、预算计数 | 第二 Agent loop、独立会话日志、模型切换状态机、重试/流拼接器 |
| tool-policy | ToolsService 注册、restriction、Guard、native executor、宿主权限/审批设施 | 注册来源准入、当前 Mandate/资源/fence 判断、Effect 提交入口 | 第二工具 registry、通用执行器、重复审批界面、重新实现 DSH schema 子集 |
| event-schedule | DSH Schedule 的持久定时和管理 API；直接 import util-time 的 Cron/RRule | schedule 与业务输入关联、幂等、任务权限及到期 Goal 查询 | 自写 cron/RRULE/时区库、另一套通用持久调度框架 |
| persistence | node:sqlite + Superagent Store.atomic/afterCommit 局部复制适配；DSH 自身数据继续用原存储 | 识雨命令/schema、事务失败补丁、DB线程消息边界 | 从零编写嵌套事务/提交回调内核；通用 ORM/存储后端框架 |

## 1. providers：优先配置已有路由

**已阅读官方包说明：**[API-key provider](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/llm/llm-deepseek-api-key/README.md>)注册 `deepseek-official`；[account provider](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/llm/llm-deepseek-account/README.md>)注册 `deepseek-account`。两者调用 [llm-deepseek](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/llm/llm-deepseek/README.md>) 的共享传输，不能只挂载传输库就认为完成身份/路由注册。API-key 缺凭据失败，account 不自动回落到 API-key；模型发现可能发请求并定期刷新，必须纳入外发盘点。

**直接使用：**已获授权的 API-key 或 account 路由中择一作为 logical primary；在清单固定具体 provider/model。其他供应商用 [llm-pi-ai](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/llm/llm-pi-ai/README.md>) 已有 profile 配置，复用其凭据解析、目录、模型能力、错误分类和流转换。[包清单](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/llm/llm-pi-ai/package.json>)声明 MIT，依赖 @earendil-works/pi-ai ^1.3.0，实际版本由 DSH 锁文件固定，不另建 SDK 版本树。

**替代与验收：**无授权路由先替身；某协议不满足才增薄 LlmAdapter，不能为一个配置字段另造网关。V13/V24 检查有效 endpoint、模型发现流量、额外日志与实际推理外发。目录未列模型不一概等于禁止调用，真正准入由配置与角色允许清单决定。

## 2. model-session：调用公共 Agent，不复制驱动

**源码静态核查：**[llm/src/index.ts](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/llm/llm/src/index.ts>)提供 LlmRuntime、registerAdapter、prepareCall/stream，并导出 BlockAssembler；[agent/model-selection.ts](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/core/agent/src/model-selection.ts>)的 AgentModel.select 将选择追加为 model/selection，不维护第二份状态。[Agent README](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/core/agent/README.md>)要求新消费者依赖 dsh-agent 而非内部 agent-loop；agent/request 已废弃，不用于新路由代码。

**直接使用：**创建/恢复接口、setup、agent.model.select、AgentOptions.maxTokens 与 Session flush。需要低层流组装时直接 import BlockAssembler；正常角色推理由 Agent 完成，无需复制 assembler。

**重试已读源码：**[llm-retry/src/index.ts](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/llm/llm-retry/src/index.ts>)注册 agent/request-error、会话重试投影及可取消退避；配置本身为空，retryPolicy 属于各 provider。直接配置 normal/有限次数，不把 maxRetries 写进 llm-retry 的 Config。识雨只补每次尝试预算、角色并发与停止条件；所有重试仍受更小的单次评估调用上限限制。

**V14/V24：**选择落盘后恢复一致；取消退避不再发请求；重试用量计入同一业务预算。缺口是业务任务/授权而非通用会话运行能力。

## 3. tool-policy：原生执行管线 + 产品权限判断

**已静态核查完整 registry 文件：**[core/tools/src/index.ts](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/core/tools/src/index.ts>)中的 register/restrict/resolve/guard/checkGuards/setExecutor/execute 已提供注册、作用域选择、条件工具与释放。view 过滤继承工具后合入 own 注册；execute 委派所选 executor。直接使用这些 API 和默认 native executor，不因作用域并非硬沙箱而重写一份工具系统。

产品补充只判定当前 actor、Mandate、resource、budget、fence，并在 Effect 执行入口复核；工具 schema 转换使用宿主现成 DSL/validator，领域 JSON Schema 单独验证。同进程可信代码仍需包准入，不安装未经批准的 executor/MCP server；该边界不抵御恶意宿主插件。

**替代：**需要不可信代码才复用成熟进程 sandbox；不是所有角色默认另起执行框架。V04/V14/V24 覆盖正常动作、own注册、custom executor和agentless路径；这些测试验证适配，没有要求改上游默认逻辑。

## 4. event-schedule：Schedule可直接用，纯时间库可独立用

**已静态核查：**[schedule/src/index.ts](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/schedule/schedule/src/index.ts>)公开 create/list/view/history/run/edit，内部复用 storageDomain 与 ScheduleRuntime。既有服务持久保存日历与发生次序，识雨只将允许的 schedule 绑定到专用输入 Session，接收去重后落业务 inbox。管理是 Host-wide，因此工具 wrapper只授予本业务ID；不复制整个 ScheduleService。

**直接包替代路线：**如果不需要原生会话投递，直接依赖 [dsh-util-time](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/util/time/README.md>)：Cron.parse / RRule.parse 返回 rule.next / resolve；canonicalizeTimeZone、parseOffsetInstant 等解析边界均现成。该库无存储/计时器/ctx。[包清单](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/util/time/package.json>)为0.2.2-alpha.2、MIT，直接依赖 @js-temporal/polyfill 0.5.1 与 rrule 2.8.1；根入口会载入二者，不能假装只复制零依赖函数。

**保留自有：**持续 Goal 的 reviewAt 查询、输入幂等与授权限流属于业务，采用现有SQL索引查询和宿主timer。V14/V24 验证错过周期、重复发生次序、暂停及恢复；不能将 Schedule 的投递回执当业务执行成功。

## 5. persistence：真实比较三条路线，选局部复用而非重造事务

### 可直接成立的 DSH 路线

[Domain.table.update](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/storage/storage-domain/src/domain.ts>)在 domain 写链内读取旧记录并执行同步转换，后端 putRecord 原子替换单条记录。**把一个聚合及其 pendingEvents 放在同一条 JSON 记录里，能够直接原子保存该聚合状态与出箱意图；DSH 不是完全不能持久业务状态。** 可在 update 回调校验记录版本，重送扫描嵌入事件，成功后再原子删除已确认项。独立小状态应优先此接口。

这条路线的边界是跨聚合预算/授权/关系约束与全文投影：若一次命令必须同时修改多个独立记录，公开 API 不提供通用事务；将全部权威状态合为单记录也可正确，但每次JSON编码和恢复装载随总状态增长，跨对象查询/FTS 需另外投影。它是低数据量可验证备选，不能仅因为原方案喜欢单库就拒绝。当前完整方案已有多聚合提交、撤权/删除屏障与全文查询，推荐共享SQL事务；V14可用同一用例比较，而不是偷换可靠性要求。

### 选定的局部复用主线

已读取 [Superagent src/app/store.ts 1–175](<https://github.com/deepseek-ai/dsh-superagent-prototype/blob/6337fc823ce20251c8de8085948165c81aaa701e/src/app/store.ts#L128-L162>)。**计划局部复制 depth/committed、atomic、afterCommit 的约35行事务骨架**，替换报错前缀、接入识雨的线程内 DatabaseSync 与具名命令。该闭包只有 db.exec、report回调、层级与回调数组；不需要整个 Store 的 Ticket/Thread/Settings/migration/Versions/storeReads，也不需要 proper-lockfile 或 zod。持久 Effects/Outbox 复用范围由[任务核查](<任务执行.md>)统一维护，afterCommit只做可丢失的内存唤醒。

**复制前必改的明确缺口：**原 atomic 在 try 外建立 SAVEPOINT，此时失败会留下已递增depth；ROLLBACK TO/RELEASE异常会覆盖原异常并缺少连接隔离。适配需保证事务入口失败清理层级、丢弃该层回调；回滚结果不明进入隔离、保留原错误及回滚错误；禁止异步 operation 把网络等待带进事务。参考已读 [DSH SqliteKvUnit.write](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/storage/storage-sqlite/src/unit.ts#L147-L175>) 的 isTransaction/unknown-state/错误聚合处理。后者私有且带unit版本戳，不能直接作为公共UoW调用，只局部复制相关错误处理，保留其MIT声明。

**不复制部分：**[DSH schema.ts](<https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/storage/storage-sqlite/src/schema.ts>)的 openDatabase 会建立宿主特有 units/unit_globals 并使用自身 user_version；它不是通用打开函数，不应原样写入识雨领域库。可参考owner-only创建/版本拒绝的边界，实际SQL schema由领域模块持有。不存在“借用private DSH连接”的计划。

### 验收与切换

V14 注入 SAVEPOINT、业务SQL、RELEASE、ROLLBACK TO失败及afterCommit抛错；嵌套成功/失败仅正确运行已提交回调。V06/V15/V24 验实际SQLite、跨聚合状态+outbox+FTS一起提交/回滚、忙等与线程失败。失败先修小范围适配，若局部复制维护成本高于现成driver事务API，再评估固定版better-sqlite3 transaction；不自行发展通用事务框架。
