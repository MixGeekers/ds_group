# 记忆、关系、认知：直接复用与局部复制核查

日期：2026-11-01（America/Caracas）。覆盖模块：`memory`、`relationship`、`cognition`。证据级别：官方说明与固定源码静态核查；未安装、未运行、未复制代码到产品。本记录按[核查约定](<核查约定.md>)调整先前过早限定为“机制参考”的结论，不表示用户已采用具体后端。

## 1. 结论与复用清单

**优先验证 Ombre 完整服务承担记忆与情绪痕迹；Mem0 是可直接调用的完整替代后端；Letta 的筛选/回顾规则选择局部改编。** SQLite/FTS5 保留为可运行对照与失败退路，不再是提前胜出的唯一主方案。身份绑定和证据判断保留小范围产品规则，不能因为服务与原单库方案不同而排除服务。

| 模块 | 直接使用 | 局部复用计划 | 必要补充与旧方案变化 |
|---|---|---|---|

### 2.1 对 Ombre 读取副作用的精确限定

普通 search/surface 在当前版本不因命中自动 `touch`；`feel.py` 主读取分支取桶、检索、排序、渲染，也未调用 touch。`dream` 记录见证与 offer，应作为内部整理命令。**启用可选 `them` 会改变边界**：`surface()` 调 `recall()`，后者清除待阅改名/纠错通知并 `_touch_person`；呈现时还检查失效依据。不能从普通记忆搜索无强化推导所有工具只读。

具体来源：[feel.py 82–153](https://github.com/P0luz/Ombre-Brain/blob/115d831d979bf67efc7150f976e2cb34c333c935/src/tools/breath/feel.py#L82)、[them/service.py 940–983](https://github.com/P0luz/Ombre-Brain/blob/115d831d979bf67efc7150f976e2cb34c333c935/src/ombrebrain/them/service.py#L940)、[surface→recall 1026–1033](https://github.com/P0luz/Ombre-Brain/blob/115d831d979bf67efc7150f976e2cb34c333c935/src/ombrebrain/them/service.py#L1026)。初始比较关闭 You/them；以后启用时由 core 执行并形成只读快照，不把原始 MCP 工具授予 replyer。

## 3. 记忆权威、来源与恢复：最小完整服务方案

不双写两套记忆权威：

- **Ombre 权威**：普通记忆正文、情绪坐标、feel、其原生整理/衰减状态与获准 I 条目。MemoryRecord 是统一读取 DTO 和引用目录，不要求再复制一份正文到 SQLite。
- **识雨权威**：已授权输入事件及原始证据、身份/权限、命令回执、`backendId + nativeId` 映射、`sourceRefs/dependencyRefs`、独立 Claim 的证据判断。事件接收不自动等于长期记忆；内容是否在两处保存由各自明确保留政策决定，不能隐性额外保留。
- **派生**：检索索引、ReadView、用于筛选的标题/版本目录。目录不是源事实。服务无法返回完整来源字段时，通过命令回执和逐条 nativeId 关联补齐；没有可靠映射的桶不可导出为“已核验事实”。
- **稳定引用**：`MemoryRef{backendId,nativeId,observedRevision,sourceRefs,scope}`。Ombre 原生版本不足以承担跨服务 CAS 时，在单写者门面保存已观察版本/摘要用于冲突检测，不宣称其天然具备全局事务；隔离 Dashboard/Obsidian 等写旁路，或将外部修改标为需核对后再纳入。

控制流程为：持久批准命令 → 调服务 → 读回/核对结果 → 登记应用回执并推进内层可见版本 → 发布 ReadView。外部后端失败前后保留 `approved / dispatching / applied / unknown / rejected` 等明确执行状态（最终枚举由公共契约统一）；服务写成但回执丢失属于 unknown。只有服务支持幂等键，或可按稳定操作标识证明既有结果，才能自动重试写入；否则停止该重试并进入核对任务，不生成“刚才成功/失败”的猜测。

跨库不再承诺正文、任务账本、六部分状态一次 SQL 原子提交。若同一观察触发记忆、关系和认知变更，先确认记忆引用，再提交引用该结果的 Claim/关系；中间状态明确标 pending，外层不能看到伪造的全完成回执。SQLite 对照模式才保留现有 UnitOfWork 同库方案。

恢复使用共同 manifest 关联控制库快照、Ombre 原生备份、backend 版本、命令范围及最新删除水位；恢复隔离期核对 unknown 命令、丢失 nativeId、服务中未登记条目和派生版本。不能用导出 Markdown 替代服务 SQLite、原文证据和队列的一致备份。先应用删除/撤权再开放读取；恢复验证失败回退隔离，不从空库重新开始后宣称恢复成功。

普通归档不满足清除要求。最小接入先用 tombstone 阻断读和派生使用，另评估服务端清除补丁/管理适配：桶、原文证据、向量/历史、缓存、备份逐项有回执。未补齐前只允许合成数据验证，不能宣称真实数据擦除已解决。Ombre 原文只写不读的问题优先由识雨已有证据服务解决，不为恢复回读再复制一套内容寻址系统。

## 4. Mem0：从影子候选改为可接入备选

`Memory.add(..., infer=False)`让 core 决定保存内容，复用 Mem0 的 embedding、存储、检索和显式更新/删除，不必拆开其私有 `_add_to_vector_store`。这比先复制整段抽取管线更接近公共接口复用。默认 infer=True 也可作为单一后端完整评测，只是接收会话就可能保存 messages；两种模式分别列入数据清单，不能混为一谈。

它的局限是准确的适配工作，而不是“第二库不能用”：native UUID 与识雨 operationId 要持久映射；检索按授权 user/agent/run 范围配置并回查删除；显式 update 不提供识雨 readSet 协议时由单写门面先核对；删除函数仍向 SQLite history 写 `prev_value`，因此清除还需覆盖历史。验证失败可替换为 Ombre 或 SQLite 对照，但不能让三个后端长期同时写正式记忆。

直接接口核查：[add/infer=False 760–917](https://github.com/mem0ai/mem0/blob/753496cf1435d76c3a711f3af51303f7fdcb6420/mem0/memory/main.py#L760)、[get 1222](https://github.com/mem0ai/mem0/blob/753496cf1435d76c3a711f3af51303f7fdcb6420/mem0/memory/main.py#L1222)、[search 1393](https://github.com/mem0ai/mem0/blob/753496cf1435d76c3a711f3af51303f7fdcb6420/mem0/memory/main.py#L1393)、[delete保留prev_value 2121–2146](https://github.com/mem0ai/mem0/blob/753496cf1435d76c3a711f3af51303f7fdcb6420/mem0/memory/main.py#L2121)。search/get_all 的范围参数位于 filters；get 按ID不自带识雨授权检查。infer=False验证只用纯文本并关闭vision加工，防止把跳过记忆抽取误写为所有加工都跳过。基础依赖含qdrant-client、Pydantic、OpenAI、httpx、PostHog、pytz、SQLAlchemy、protobuf；[遥测](https://github.com/mem0ai/mem0/blob/753496cf1435d76c3a711f3af51303f7fdcb6420/mem0/memory/telemetry.py#L14)默认启用，验证配置记录MEM0_TELEMETRY=False。

仅需抽取提示时，复制计划限定为 [prompts.py 468–958 的 ADDITIVE_EXTRACTION_PROMPT](https://github.com/mem0ai/mem0/blob/753496cf1435d76c3a711f3af51303f7fdcb6420/mem0/configs/prompts.py#L468)与[961–1064的generate_additive_extraction_prompt及格式化闭包](https://github.com/mem0ai/mem0/blob/753496cf1435d76c3a711f3af51303f7fdcb6420/mem0/configs/prompts.py#L961)。后者只依赖json/datetime，可按接口移植TypeScript，由DSH调用模型，不复制私有写入函数。保留Apache-2.0、来源和修改说明；将尽量多抽取改成获准范围，补sourceRefs/主体/生效时间，显式传观察日期，linked_memory_ids不当作身份或独立证据。此路径只节省提示设计，不继承Mem0整包效果。具体入口与复制边界记录于[Mem0候选](<../../技术候选/Mem0.md>)。

## 5. 关系：哪些可用，哪些确实要补

Ombre `them` 已有 `Person` 多名称、revision、认识条目及证据；`ThemClaim` 直接继承 `YouClaim`，可复用同一服务内的数据结构而不再建一套“人物印象库”。但工具明确只记人的特点，不描述关系；模型名称归并也不等于渠道账号认证。其读取有上一节列出的真实写作用，隐私可见性又受 known_via 产品规则控制。

采用顺序：验证主体来自已有渠道 → 映射 entityId → 若开启 them，建立 entityId↔person_id 引用 → 通过 core 调原服务写/撤回认识 → 只读视图附其依据与限制。IdentityBinding、跨渠道合并证明、可撤销 split 及“甲说乙”归属仍是识雨必要增补。认识可以由服务保存；已验证绑定不能被名称/熟悉度替代。初版不为此新增图数据库。

若希望全部认识在识雨界面可审阅，需要明确 them 展示/导出适配，不能仅开其 Dashboard 后声称一致。内部类局部抄取的依赖包含 `you.models/service`、storage/letter/source、utils、ThemStore、安全规则；已不是单独 Person 函数的小闭包，所以优先服务接口，失败时退回普通有来源 Claim，而不是抄整套私有模块。

来源：[Person 与 YouClaim 依赖](https://github.com/P0luz/Ombre-Brain/blob/115d831d979bf67efc7150f976e2cb34c333c935/src/ombrebrain/them/models.py)、[工具边界及参数](https://github.com/P0luz/Ombre-Brain/blob/115d831d979bf67efc7150f976e2cb34c333c935/src/tools/them/core.py)、[service 解析与写依赖](https://github.com/P0luz/Ombre-Brain/blob/115d831d979bf67efc7150f976e2cb34c333c935/src/ombrebrain/them/service.py)。Mem0 旧 OSS graph 教程不作为当前现成承诺，其迁移说明把 graph 能力移至 Platform；当前不增加付费平台或图服务来填一个模块名。

Mem0 [entity_extraction.py 731–778](https://github.com/mem0ai/mem0/blob/753496cf1435d76c3a711f3af51303f7fdcb6420/mem0/utils/entity_extraction.py#L731)提供类型+实体文字候选，未提供跨账号身份绑定和可撤销合并；依赖[spaCy英语模型](https://github.com/mem0ai/mem0/blob/753496cf1435d76c3a711f3af51303f7fdcb6420/mem0/utils/spacy_models.py)，缺失时可能下载，加载失败会空候选。因此不为中文身份层复制该整段启发式；可保留作检索信号，不担任权威解析器。

## 6. 认知：局部复制的明确范围

首选复制计划是 Letta `reflection-v2.md` 的 Trajectory review（27–37行）与 `maintaining-core-memory/SKILL.md` 中“明确指示/稳定模式、纠正、假设需后验验证、层次检索入口”规则，**不是执行这些仓库文件给出的操作指令**。它们是被评估的资料。实施时保留 Apache-2.0、源提交、适用版权/归属及修改声明，且不复制品牌素材。

改编范围固定：移除 Bash/Edit、MEMORY_DIR/Git 提交和直接改 system prompt 的路径；输出结构化 Claim/RevisionCandidate 和 sourceRefs；把“最新证据胜出”改为核对主体/有效期/来源后决议；原文与来源仍由证据层维护，不能照搬正文不记来源且只在 Git 保存依据的假设。由既有 DSH 模型执行，core 批准后写入选定服务或 Claim 记录，不再开发独立 reflection runner。

Letta 另有已公开导出的 `@letta-ai/letta-code/memory-constraints`：`validateMemoryTreeConstraints`、`parseMemoryConstraintsConfig`。主函数仅依赖提供的 reader 和标准语言能力，文件头另重导出 `memory-frontmatter`；若未来确需 Markdown 导入/导出验证，可局部复制该函数闭包、移除不需要的重导出，并保留同版相关测试用例。它检查索引、字符额度、只读文件变更，不检查事实、身份或权限。当前 Ombre 服务路线不为用这个函数而新增 MemFS 层；`memory-confinement` 则依赖 sandbox/permission launcher，不属于独立几行路径检查，不能盲拷。
