# 情绪、人格与能力：复用核查

日期：2026-11-01。覆盖模块：`emotion / personality / ability`。依据[核查约定](<核查约定.md>)；证据等级为官方资料与限定源码静态核查，未运行、安装、复制产品代码或接入真实设备。Ombre 仍是优先待验证候选，不写为已采用。DSH 已由用户选择为宿主，具体插件组合尚待验证。

## 1. 逐模块结论与撤回项

| 模块 | 优先路线 | 识雨必须保留的薄逻辑 | 替代路线与条件 |
|---|---|---|---|
| emotion | 与 memory 共用一个 Ombre 服务，直接调用 `hold(feel=True)`、`feel(query)`、`dream`，复用记忆 V/A、情绪检索和衰减 | core 受控写、来源/权限投影、删除传播、当前表达是否采用某段感受 | 若整包边界成本未过门槛，局部复用情绪距离函数和记忆衰减公式；不先造三维实时情绪系统 |
| personality | Ombre `I` 负责自我认知候选及跨日沉淀；DSH `systemPrompt.section/context` 装配身份和风格投影 | 稳定名称/语言/风格配置，用户明确偏好优先，I结论映射白名单、版本回退 | Ombre 不可用时固定 Profile；暂不做自学习，不另引人格模型 |
| ability | DSH `ctx.tools`、`ctx.skills` 与现成 filesystem/provider/tool-skill；外部能力用 DSH MCP client | 对宿主对象追加批准版本、来源、验证与 Mandate 范围元数据，执行前复核 | 动态发现未验证时固定工具及技能版本；需要新来源时才实现一个 SkillProvider |

**修订：**撤回旧文档将三维 `valence/activation/strain`、分钟级半衰期和事件数值表列为首验默认的安排；它们没有证明优于现有情绪记忆。短时 ToneView 仅在明确体验问题及对照收益成立后另行提出。撤回另一套通用 `registry.list/resolve`、技能发现器、目录缓存与加载器的实现暗示；现成 DSH 已提供这些能力。六部分是逻辑责任，不要求六套数据库或服务。

## 3. 接入边界、失败与撤回

- memory与emotion/personality共用Ombre单一记忆权威；事件、feel、I正文不再双写识雨状态库。SQLite只保留授权、命令回执、外部bucket引用、来源依赖与独立的稳定Profile配置。感受/I ReadView可重建且受版本和删除水位裁剪。
- core独占写工具及dream；worker仅提交提案，replyer仅读已裁剪视图。Ombre内部后台衰减/索引与归档仍存在，需纳入服务状态观察，不能声称所有变化都由本地SQLite事务发出。
- 跨服务命令采用memory约定 `approved→dispatching→applied/unknown/rejected`；确认后更新本地版本，超时unknown先核对，不能把重复hold或promote当天然幂等。备份共同manifest与删除水位，不宣称跨库原子。
- I的3日门槛是沉淀节奏，不是证据独立性或事实证明。将I映射到稳定Profile需引用仍有效的来源并通过字段白名单；用户明确持久偏好与模型候选分开。权限策略从不由人格内容决定。
- Ombre不可用时提供明确过期/缺失标记和固定Profile，不制造新feel/I；向量服务失效使用其字面降级。候选最终不通过时，导出并完成停写/切换验证后换后端，不能双主并行。
- DSH技能get会重新读取正文，目录未变不代表内容未变。记录provider+scope+name+内容摘要；加载结果与获准摘要不一致则不把正文交模型，重新验证。优先受信固定bundle避免为了防覆盖另造registry。guard覆盖自定义executor、skill工具结果后置校验的具体挂点须由宿主验证确定，不能假称已有完整摘要授权功能。
