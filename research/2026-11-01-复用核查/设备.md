# 设备执行面复用核查

日期：2026-11-01。覆盖 `device-gateway`、`desktop-device`、`other-device`、`robot`。证据为 GitHub 固定提交/版本的公共接口、限定源码与许可证核查；未安装、运行、连接真实设备。设计仍处于验证前。遵循[核查约定](<核查约定.md>)；此前[设备证据](<../2026-11-01-完整架构/设备执行面.md>)保留平台与协议背景。

## 结论与修正

**先复用 DSH 已有 SSH、MCP、浏览器和 Computer Use 接入；再按设备需要接现成 CLI、MCP 或 Appium/ROS SDK。**不把识雨完整 DeviceCommand 协议变成所有工具接入的先决条件，也不要求每台设备安装自研全机客户端。

本轮发现原方案遗漏 DSH 自带的 `browser-use-playwright-mcp`、`browser-use-runtime`、`cua/cua-macos` 和 Cua Driver 适配，现已修正。前两者已有每 Session 资源生命周期、调用串行和隔离浏览器启动；macOS CUA 已有应用/窗口对象、授权与撤销、截图入库、取消后不重放。它们明确属于 experimental，须固定组合验证，不能写成生产成熟保证。它们仍比重建同类框架更适合首轮比较。

### 1. device-gateway：配置/调用现成接口

- **DSH MCP**：[packages/mcp/mcp-client/src/index.ts](https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/mcp/mcp-client/src/index.ts) 已核查 `apply(ctx, config)`、`StdioConfig`/`StreamableHttpConfig`、`createMcpToolDefinition`导出。每实例一个server，公开工具名为server限定命名；依赖Cordis scope、tools、MCP SDK及现有connection/result投影。直接挂载插件；不复制`connection.ts`自写重连。stdio启动子进程，HTTP建立连接，发现工具会改变模型可见目录，均须受批准配置控制。连接存在与能力授权分离；重连恢复通信，不重放未知写操作。
- **DSH SSH**：[ssh/src/index.ts](https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/ssh/ssh/src/index.ts) 已核查 `SshConnection.ready/request/connectStream/dispose`、固定helperHash、严格host key、禁agent forwarding、心跳/lease和POSIX client限制。对业务优先调用provider公开接口，不直接依赖私有helper RPC。
- **文件与进程**：[fs-ssh/src/index.ts](https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/ssh/fs-ssh/src/index.ts) 已有 `resolve/stat/streamText/readByteRange/writeText/editText/deleteFile/moveFile`；[subprocess-ssh/src/index.ts](https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/ssh/subprocess-ssh/src/index.ts) 已有runtime与handle的 `done/waitForExit/streamsClosed`。文件写入与进程启动确有副作用；断连不能判定未发生。复用整包的fs/ssh/schema/output依赖闭包，不摘取单函数重造远端路径guard或输出协议。
- **宿主兼容**：DSH文件与子进程provider必须每设备独立scope，不能覆盖主Web profile的本地上下文。若V18证明作用域无法隔离，回退系统OpenSSH固定入口；Windows用微软OpenSSH与PowerShell入口，不能运行DSH POSIX helper。系统OpenSSH复用已安装发行版，精确build及发行许可由V26记录，不声称本轮锁定各OS二进制。

**协议分层调整**：DeviceCommand首先是插件内部的执行封套，不要求Peekaboo、Playwright、Appium等理解全部识雨字段。中心gateway在调用原工具前校验身份、授权、fence和资源；工具结果映射回Effect。没有远端持久gate的能力标记`supportsDedup=false`/相应恢复等级，只允许单次派发、禁离线新增和自动重放，未知结果锁住资源，旧执行资格未确认退出不改派。需要远端持续执行、排队或跨中心重启继续的副作用，才要求端侧校验世代/fence与持久effect账本，优先使用目标系统已有作业ID/状态API。不能把“中心检查”宣传成“设备已阻断旧进程”；不能为了接入完整性让每个只读工具都安装自研守护进程。

验收：V18双设备同路径100次无串机、scope隔离/健康目录失配；V19断线及旧fence各100次，未知动作不重放，工具仍列出时available为false；V23集成；V26核实真实helper/OS/密钥范围。

### 3. other-device：现成会话、浏览器和移动驱动

**DSH浏览器接入为第一比较基线**：[provider源码](https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/experimental/browser-use-playwright-mcp/src/index.ts)已确认launch自动`--isolated`、清空继承`PLAYWRIGHT_MCP_*`、固定Chromium；[runtime/mcp.ts](https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/experimental/browser-use-runtime/src/mcp.ts)已有`mountSessionMcp`、SessionResources、工具归属校验、调用串行、关闭回收和禁自动重连。直接配置provider，不自行实现这些机制。仅补Task→Session、origin/动作白名单、业务提交核对及资源状态映射。

**版本不能混写**：DSH [package.json](https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/experimental/browser-use-playwright-mcp/package.json)固定`@playwright/mcp=0.0.80`；[上游0.0.80](https://github.com/microsoft/playwright-mcp/blob/v0.0.80/package.json)再固定Playwright `1.63.0-alpha-2026-08-31`、Node≥18，许可[Apache-2.0](https://github.com/microsoft/playwright-mcp/blob/v0.0.80/LICENSE)。上一轮审阅`be26c080...`对应0.0.84与Playwright1.65 alpha，属于备选版本，**不能当DSH已兼容的依赖**。优先原组合，需升级则先做独立schema/图像/取消/生命周期回归，补丁最多是provider依赖及兼容适配，失败回滚原锁定组合。

DSH此provider仅Chromium、reload/resume不恢复cookies/pages；attach只有provider实例内独占，其他进程仍可能修改页面。会话启动/导航/登录/提交/下载均有各自副作用。确定步骤可直接Playwright公开API，探索步骤用现成MCP；需要Firefox/WebKit或持久账户状态而原provider不支持时才采用独立上游执行器。上游公开`createConnection(config, contextGetter)`已于0.0.84 [index.d.ts](https://github.com/microsoft/playwright-mcp/blob/be26c080edfae7c761db1e757c4aff9f6453b4d7/index.d.ts)核查，不能将其当DSH0.0.80已验证接口。无须复制Playwright内部引擎。

**Android**：官方ADB复用配对与shell/sync功能；应用UI直接接Appium **UiAutomator2 v8.7.3**的W3C WebDriver会话、元素、输入和截图。[README](https://github.com/appium/appium-uiautomator2-driver/blob/v8.7.3/README.md)、[driver.ts](https://github.com/appium/appium-uiautomator2-driver/blob/v8.7.3/lib/driver.ts)、[element.ts](https://github.com/appium/appium-uiautomator2-driver/blob/v8.7.3/lib/commands/element.ts)、[Apache-2.0](https://github.com/appium/appium-uiautomator2-driver/blob/v8.7.3/LICENSE)。Appium3、Android≥8/API26、Android SDK/JDK；Node`^20.19.0 || ^22.12.0 || >=24`与npm≥10。必须显式deviceId→`appium:udid`，`deviceName`不选择设备；不能选第一台在线机。Appium服务在端侧或既有测试主机，非DSH内部重建移动客户端。会话建立可安装测试服务/启动应用，非只读probe。

**iOS**：日常用户触发Shortcuts继续优先；应用UI使用Appium **XCUITest v12.22.8**。[driver.ts](https://github.com/appium/appium-xcuitest-driver/blob/v12.22.8/lib/driver.ts)、[element.ts](https://github.com/appium/appium-xcuitest-driver/blob/v12.22.8/lib/commands/element.ts)、[Apache-2.0](https://github.com/appium/appium-xcuitest-driver/blob/v12.22.8/LICENSE)。完整能力以macOS/Xcode/Appium3/匹配WDA为基线，真机须信任、Developer Mode、UI Automation与provisioning；会话可能安装WDA/改变键盘偏好，须在V26记录变更。存在[非macOS有限支持](https://github.com/appium/appium-xcuitest-driver/blob/v12.22.8/docs/guides/non-macos-hosts.md)：iOS/tvOS≥18真机、RemoteXPC前提、预装/外部管理WDA、显式udid，无模拟器/自动选设备/xcodebuild。因此不是完全不支持Win/Linux，亦不意味着绕过签名。只映射授权、设备会话、effect和回调，不复制Appium/WDA源码。

V20/V26沿用20项网页场景，补充验证DSH重载不恢复浏览器状态、0.0.80原依赖兼容、双udid不串机、驱动初始化实际变更、取消不重放；仅协议替身通过时不宣称已支持移动真机。

### 4. robot：直接使用ROS动作客户端

rclpy **7.1.12**（Jazzy发行索引对应版本），[Apache-2.0 LICENSE](https://github.com/ros2/rclpy/blob/7.1.12/LICENSE)。[action/client.py](https://github.com/ros2/rclpy/blob/7.1.12/rclpy/rclpy/action/client.py)已核查`ActionClient.wait_for_server/send_goal_async(goal, feedback_callback, goal_uuid)`与`ClientGoalHandle.get_result_async/cancel_goal_async`，直接指定既有effect映射的goal UUID；[package.xml](https://github.com/ros2/rclpy/blob/7.1.12/rclpy/package.xml)依赖rcl/rcl_action/rmw和生成消息等发行栈，不摘单文件脱离ROS。

现有Action处理目标接受/反馈/结果/取消，无需自研ROS客户端。缺口确实存在：client goal handles为内存weakref；[server.py](https://github.com/ros2/rclpy/blob/7.1.12/rclpy/rclpy/action/server.py)默认result_timeout=900秒，并非无限持久账本。因此识雨只补effect→UUID持久映射、必要结果摘要、授权与物理范围及本地停止状态核对。cancel只请求取消，不认证真实制动。已有厂商Action/SDK直接调用；已有rosbridge可以继续复用受限桥，无需强加ROS MCP层。

V20加结果超过保留期、客户端重启丢handle、相同UUID重复与取消拒绝；无法核对就unknown，不凭新UUID重发。原10类状态、100次重复和本地模拟停止时限继续有效；V26才确认真实设备停止链路、OS/ROS/vendor版本及物理范围。
