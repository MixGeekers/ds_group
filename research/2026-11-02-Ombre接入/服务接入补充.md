# 真实服务接入补充

日期：2026-11-02。固定版本仍为 3.6.14 / `115d831d979bf67efc7150f976e2cb34c333c935`。本文将静态接缝判断与本次[隔离服务实验](../../测试/2026-11-02-Ombre服务验证/实验计划.md)分开；实际执行与清理以实验结果为准，不继承为正式 Runtime 接入或候选采用决定。

## 固定依赖与受控路径

官方锁文件实际固定 `mcp==1.29.0`，`requirements.txt` 中生产 1.28.1 的注释滞后。实验采用 Python 3.12.16 和原锁文件 `--require-hashes`，不是按注释安装。锁文件 SHA256 为 `ae0255bd41e5ceb45694244017a9b0b2dc1e4c445ab027cec1f7183ad969700a`。[固定锁文件](https://github.com/P0luz/Ombre-Brain/blob/115d831d979bf67efc7150f976e2cb34c333c935/requirements.lock.txt)

完整元数据 `grow(items=[...], test_data=true)` 可绕过普通 analyze 与 merge 路径，适合空 vault 单桶合成验证。`hold` 即使给全元数据仍调用 analyze；两条路径都不能据此宣称无生命周期工作。Decay 无总关闭开关，启动后先执行一轮再等待；background_indexing=false 只关闭后台索引队列，不禁止同步 embedding。关闭生成 key、不继承外部凭据，使生成 API 客户端不建立。实验使用回环代理独立统计 embedding/生成路径，不把“没有 key”单独当作实测零请求证据。[grow](https://github.com/P0luz/Ombre-Brain/blob/115d831d979bf67efc7150f976e2cb34c333c935/src/tools/grow/core.py)、[dehydrator](https://github.com/P0luz/Ombre-Brain/blob/115d831d979bf67efc7150f976e2cb34c333c935/src/dehydrator.py)

精确 ID 查询先于语义检索，但 ID 缺失可继续普通检索；调用者必须检查真正返回的 ID，不能把任意匹配当作目标仍存在。认证 Web `GET /api/bucket/{id}` 与 `GET /api/export` 可补充独立读取和原生备份证据；Web 登录 cookie 与 MCP token 不是同一认证。归档仍保留正文，hard_delete 只允许创建时标明的测试桶。[搜索](https://github.com/P0luz/Ombre-Brain/blob/115d831d979bf67efc7150f976e2cb34c333c935/src/tools/breath/search.py)、[Web 桶接口](https://github.com/P0luz/Ombre-Brain/blob/115d831d979bf67efc7150f976e2cb34c333c935/src/web/buckets.py)

## 正式写入仍需的服务扩展

Ombre 公共写工具没有可直接满足 MemoryOperation 的持久 operationId 与原子 CAS；grow/hold 的标题、batch ID、搜索命中、正文 hash 和 `isError=false` 均不是一次写操作的完整可信回执。普通自动合并还可能改变旧 nativeId 及来源闭包，不能包装为只创建一个新对象。

下一切片应优先评估一个限定的服务扩展：严格创建，保存操作与命令摘要的可核查关联，独立 nativeId 原文/版本回读，以及明确的修改和删除策略。底层继续复用 Ombre 的桶、索引和锁；控制库只保存引用、来源、授权与回执。是否实现该扩展须按其实际维护范围决定，不借测试桶写入证明普通记忆协议已经满足；不为消除差异而维护第二份可变记忆正文。

## Harrier 适配的最小范围（静态方案，未实施）

原版 Ombre 所有查询和文档共用 `_generate_async`，API 请求发送 `text[:2000]`。用户既有 Harrier 评测对 query 加指令、document 不加，直接使用相同模型名和 1024 维并不等价。[embedding_engine.py](https://github.com/P0luz/Ombre-Brain/blob/115d831d979bf67efc7150f976e2cb34c333c935/src/embedding_engine.py)

建议在 Python embedding 边界做小补丁，继续使用上游检索、存储和 outbox；TS 客户端没有现成 Python 注入入口，另加跨进程桥接反而扩大维护范围。限定改动为：

- 独立固定 Harrier profile，区分 query/document 输入；缓存包含 profile 指纹、角色和实际输入摘要。若保留 Ombre 的 2,000 字符规则，先截正文再加指令，明确其与 TS 当前整段输入策略不同。
- 固定权重身份、1024 维、last pooling/L2；拒绝空、零范数、非有限及错误维度，不沿用上游自动改维度的行为。
- 空库初始化 profile；非空索引缺少或不匹配指纹时返回 reindex_required，停止语义读写。首个补丁可拒绝在线切换，无需同时重写迁移网页。将来开放 reindex 再覆盖 checkpoint/staging 身份，以及 content 和 meaning 两种向量。
- 显式 loopback、禁止代理/重定向和 SDK 自动重试，不回落云端。不采用 `local/ollama` 配置，因为启动钩子可能管理本机 Ollama；保留受限 openai_compat 通道。[自动管理入口](https://github.com/P0luz/Ombre-Brain/blob/115d831d979bf67efc7150f976e2cb34c333c935/src/web/ollama_local.py#L567)

必要验证为输入模板/缓存隔离、维度及数值拒绝、profile 不匹配、故障单次请求、网络目的地与重新构造的一致限制。真实召回质量另按既有合成小集核对；这份静态方案不计为新的质量结果。
