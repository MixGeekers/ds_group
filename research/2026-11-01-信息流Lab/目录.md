# 信息流 Lab 工具核查

日期：2026-11-01。证据层级：**官方文档阅读**；未下载运行源码、安装工具或调用模型。以下为最少必要的能力摘要，原文以来源为准。

[实验计划](<../../测试/2026-11-01-信息流Lab/实验计划.md>) · [既有验证方法](<../2026-11-01-完整架构/验证方法.md>)

| 官方来源 | 本轮核得内容 | 使用边界 |
|---|---|---|
| [Promptfoo TypeSafe](https://www.promptfoo.dev/docs/providers/typesafe/) | 已有 `typesafe:<model>` provider，可将 Jev 问题作为被测对象；文档提醒固定模型版本 | 先复用内置适配，不预设需要自写；示例版本不代表最新模型 |
| [Promptfoo OpenAI Decisions](https://www.promptfoo.dev/docs/providers/openai-decisions/) | 已有 `openai:decisions`，调用独立 Decisions 接口并支持问题配置 | 适合离线候选比较；不证明识雨运行时 DSH provider 已接通 |
| [Promptfoo JavaScript provider](https://www.promptfoo.dev/docs/providers/custom-api/) | 自定义 provider 通过 id/callApi 接口接外部服务 | 只有内置适配不能满足所需接缝时才补薄适配；不自建评测平台 |
| [k6 open / closed models](https://grafana.com/docs/k6/latest/using-k6/scenarios/concepts/open-vs-closed/) | arrival-rate 将迭代到达与先前处理完成解耦；闭环输入可能随响应变慢而降低 | 用于存在可测入口后的持续信息流；注入端掉速必须另报，不直接证明业务完成 |
| [Node test runner](https://nodejs.org/api/test.html) | 内置测试工具提供 MockTimers，可推进计时器和日期 | 适合受控代码的时间语义；不虚拟远端服务、不代替实际性能时钟；按选定 Node 版本确认 API |

推论与建议：Promptfoo 承担模型评测，Node 测试工具承担确定性协议检查，接口阶段按需使用 k6；识雨只补领域场景、状态接缝与独立判定。工具文档存在不代表本机版本已支持，正式执行需固定并核对版本。

本次没有调用模型、运行候选或复现厂商效果；未提出这些工具已经被用户采用。首个切片仍可先做本地假模型与假渠道，不依赖收费模型账户。
