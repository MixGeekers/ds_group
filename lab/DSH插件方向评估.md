# DSH 插件基座与多路径任务验收

2026-11-01。用户在 Lab 实施中提出方向修正：考虑 DSH 基座、插件形态、Agent 评分、多种合理完成路径及工作区管理。本文件为证据核查与设计建议；未安装、启动或迁移到 DSH。已有独立服务是可复用验证原型，不能当成最终形态已经确认。

## 判断

推荐将目标形态调整为 **DSH 原生 Lab 插件**：复用 DSH 的 Agent/Session、模型、工具、工作区与 UI，Lab 专注公司模拟、实验编排、独立效果记录及验收。插件仍通过 Web UI 呈现；“Web”与“插件”分别是界面载体和运行集成方式。

此前独立服务方案有利于快速验证协议和故障域，但把它作为唯一产品形态会重复承担宿主已有的 Agent 与工作区管理。故障测试可采用管理/被测两个 DSH 实例，不必据此否定插件基座。

## 推荐的组织方式

```text
DSH 管理实例
  Lab 插件
    公司与场景、外生输入驱动、运行与产物管理
    职员演员：脚本 + 按需 Agent
    Judge Agent：独立 Session，读取封存证据
    Lab UI：时间线、工作区、成果、评分与比较
  被测接缝
    普通联调：连接本实例的识雨测试实例
    宿主故障专项：连接另一 DSH 进程/实例
```

管理侧的模拟员工和 Judge 是 Lab 的角色；被测识雨自己的 core / worker / replyer 仍由识雨组织，Lab 不能代替被测 core 派工并把完成记给识雨。

按公司数据集建立模板，每次 run 派生新的业务工作空间，内部按部门/项目共享获准资料；无需给每个人完全复制一家公司。个人消息/记忆、公共工作文件、运行证据、评分材料分别记录拥有者和可见范围。跨日场景明确继承哪些状态；不同候选从相同初始条件开始。

DSH 工作目录变化只影响该 Session 后续基于目录的操作，既有终端保留自身目录，sandbox 根仍锚定原项目。工作区分组不自动形成读写隔离，Lab 的快照也不能只复制目录就声称冻结了数据库、在途消息和服务。见[Working Directory](https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/docs/subsystems/working-directory.md)。

普通功能实验可以同一宿主运行。测试“宿主崩溃后识雨恢复”时，Lab 管理宿主与被测宿主必须分开，才能保留观测、驱动和世界效果；若要测管理宿主自身崩溃，再保留极薄外部探针。不要求为了普通功能测试默认启动多个完整宿主。

## 验收从固定产物模板改为任务结果

当前参考科目强制 `outputs/Txx/result.json`、固定文件集合和部分表格列/短语，适合作为工具接缝自检，但会限制自然职员任务。新架构分开两种测试：

- **协议/组件测试**：继续使用固定字段、操作身份、故障屏障，验证确定性接口与实际效果。
- **职员行为测试**：给业务目标、可用资料、必要要求和截止条件，由识雨选择工具与步骤；按实际成果及世界变化验收。

工作任务改为业务目标、必要约束、可接受交付、完成条件和当前世界。目标自行声明成果引用，Lab 再验证引用对应的文件、业务记录或实际送达。返回声明可由接缝从交付中抽取，不强迫识雨额外制造标准答案 JSON。

例如“给我本周经营情况，指出异常”：识雨可读表计算、写脚本、查询业务服务或调用现有报表工具，再交付表格、文档或受任务允许的正文。若职员明确要求 XLSX，则文件格式是业务要求；若未指定，就不能因为文件名或工具顺序不同判失败。数值可独立重算；摘要是否解释异常、是否便于使用由 Judge 查看实际成果和上下文。

供应商方案允许不同合理推荐，除非用户明确给出唯一优化目标。维护允许不同有效修复方法，以真实行为恢复、必要范围和复核为准；不强制调用某个“修复”工具或复现参考配置。内部调度不要求固定 worker 数、固定回复句式或每条群聊都进入 core。

## Agent 评分与事实验证

Judge 通过 DSH 使用只读证据工具，查文件、表格、世界状态、消息送达和当时可见上下文。输出维度、理由和证据引用，支持复评及人工分歧复核。任务是否完成、完成质量、协作分寸、资源消耗分别报告。

程序仍负责数值核对、效果次数、实际收件人、超时/错误、文件能否打开及服务健康。模型判断用于语义理解和多种有效解的质量，不允许根据目标自己说“完成了”直接给通过。证据不足保留不可判定；新格式尚无可靠解析器时，标 Lab 评审覆盖不足，不自动判目标失败。

按最终轨迹评分与按决定当时评分分包。负责人已承接后静默、无人承接时直接 @ 都可合理；不将后来的回应倒推为之前提醒不合理。演员和 Judge 用不同 Session/上下文，员工只能使用自己知道的事实；评分答案不进入目标或演员上下文。

Agent 承载不能把每条噪声都变成一次模型调用。确定性到达计划、计数与事件账本仍由程序执行；演员在有业务互动时按需唤醒，Judge 默认封存后运行，并单列 Lab 额外费用。

## 原型保留与后续调整

保留合成资产、公开协议自检、输入驱动、工具/效果账本、反例测试和独立评分理念。React 领域组件可复用，但独立 Vite bundle 不能直接假定可嵌进宿主；DSH 入口需使用其 React 与扩展接口。

调整 Agent 创建/调用到 DSH，工作区与角色会话绑定到宿主管理，HTTP Judge 改为 DSH Judge 适配之一；外部评分端点仍可保留可选支持。固定路径验收器保留为自检，职员测评增加成果发现/声明、格式适配与语义验收。

下一项实施应先验证固定 DSH 版本的 Lab 插件入口、创建独立评分 Session、绑定测试工作目录和只读证据工具，再迁移领域组件；本轮评估没有执行这些迁移。
