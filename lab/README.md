# 识雨健身房 · Lab

多部门工作模拟与 Agent 测评系统。2026-11-01 用户先批准“测试系统先行”，指定实现放在 `lab/`，随后明确要求实现 DSH 插件并命名“识雨健身房”。本目录包含原型和原生插件；识雨产品内核仍独立推进，既有识雨工作台保持原样。

**当前版本：DSH 原生插件 0.3.0；独立原型保留。** 在原有实验、成果验收和评分之上，增加房间聊天、文件分享、手动任务、自定义剧本和模型设置页。安装与实际验证状态见[插件实施记录](<插件实施记录.md>)；程序事实和 Agent 意见分开保存。

## DSH 插件使用

在 DSH 侧栏打开 **识雨健身房**：

1. 默认创建“自由会话”，等待外部识雨接入，不自动调用模型。可在用户与识雨私聊或所在群聊中发言、分享附件和发布任务；职员私聊供观察。
2. 在工作区上传资料、查看内容或下载文件。上传不等于向被测 Agent 分享；发送附件或将资料加入任务后，它才可以读取。
3. 在“设置”中分别配置被测 Agent 与 Judge 的模型和思考强度。默认跟随 DSH；独立选择复用 DSH 已配置的模型目录、凭据和该模型实际支持的强度。设置仅影响新 Session，不修改宿主全局选择或正在进行的运行。
4. 明确点击“启动 DSH 测试 Agent”开展业务练习；或生成接入口令，让已有 DSH 会话或外部客户端加入。这是测试接入，不表示真实识雨内核已经实现。
5. 需要无模型自检时，在创建房间的“高级”中选择“参考自检”与内置工作日。可检查任务、公开过程、实际产物及事实验收。
6. 在“剧本”中复制内置剧本，或新建角色、会话、资料及任务事件；保存为独立副本，已有房间保留创建时的剧本快照。
7. 房间封存后，可明确启动独立只读 Judge，或导入评分 JSON。评分使用宿主模型额度，每次复评保留新记录。业务验收允许不同合理步骤和成果格式；有效提交数不冒充业务满分。

原生插件不另开HTTP服务，复用当前DSH的认证连接。独立运行数据位于 `runtime/gym/`；停止/卸载会取消关联模型工作，重启只恢复历史，不自动重放。

开发与分发：`npm ci`、`npm run build:plugin`、`npm run test:plugin`。通过 DSH 的 `plugin_manager install_bundle` 安装本目录，不手写profile配置。已安装包的代码更新按宿主安装结果要求重载或重启，不承诺仅改源码即可热更新。

本机通过 `link:` 安装时，更新后先完成构建，再到 DSH“插件 → 识雨健身房”关闭并重新启用；若宿主提示需要重启，则正常退出并重新打开 DSH。仅刷新页面可能让新界面连接旧后台，曾导致创建房间时报“config 包含不支持的参数”；0.3.0 界面会识别旧后台并提示重新加载。

## 独立原型启动（保留）

环境：Node.js **24.19 或更新的 24.x**、npm。依赖由锁文件固定。

```sh
cd lab
npm ci
npm run build
npm start
```

打开 **http://127.0.0.1:4318**。服务只监听本机，不注册常驻服务；终端按 Ctrl+C 停止。已经安装依赖并构建过时只需 `npm start`。开发界面可另开终端运行 `npm run web:dev`（4173，API 仍为 4318）。

## 可以做什么

- 选择多部门工作日、高噪声工作日、异步协作与故障、记忆纠正与后续协作四种场景。
- 调整随机种子、噪声数量、播放速度、worker 并发、工具暂时故障或回执丢失。
- 观察 12 名职员、6 部门、3 家供应商、22 个会话中的持续输入；独立输入驱动不会等待 worker 完成。
- 执行经营报表、对账、文档、文案、供应商比较、交付安排、系统巡检和系统维护八科；生成真实 XLSX、DOCX、CSV、Markdown、JSON 文件。
- 查看任务、事件、产物下载、独立事实验收、Agent 评审与两个运行的比较。
- 停止注入并排空，或停止实验；服务重启后保留历史及中断证据，不自动重放未知效果。

**参考执行器**用于检查 Lab 本身。它是确定性代码，产生 core / worker / replyer 参考轨迹；完成率不是识雨的智能测评分数。**外部 Agent**模式使用同一世界和验收器，允许接入实际被测对象。

巡检与维护操作的是每次运行独立、可复位的有状态服务替身。配置变化与探测由 Lab 工具实际执行并记录，不改真实服务器。此独立原型不会自动连接 DSH 或模型；原生插件的模型接入需明确启动。两种形态均不连接真实公司账号或生产设备。

## 使用顺序

1. 先用“参考执行器”启动多部门工作日，检查任务、产物和验收；可以打开 XLSX / DOCX 检查实际文件。
2. 换高噪声场景或故障配置，查看相同业务的交付、输入延迟及恢复轨迹。不同条件的对比不自动归因为模型差异。
3. 选择“外部 Agent”，启动后复制本次 runId / targetToken，按 [接入协议](<协议.md>)连接。令牌只用于该运行，不写入日志或评分包。
4. 封存后导出证据包，交给独立 Agent 评审；或者配置评分服务并从界面发起评分。重评保留新的 reviewId，不覆盖旧结果。

## 测试与命令行

```sh
npm run typecheck
npm test
npm run smoke
npm run test:ui
npm run test:plugin:ui
npm run lab -- list
npm run lab -- run mixed-office
npm run lab -- evidence <runId>
```

`npm test` 包含本机 HTTP 服务测试。`npm run smoke` 真实跑完五组参考工作流，并保存 [自检摘要](<artifacts/smoke-summary.json>)。浏览器测试使用 Playwright 和本机 Chrome；配置中的 `LAB_CHROME_PATH` 可指定已安装浏览器，或按测试配置使用 Playwright 自带 Chromium。

所有 CLI / UI 运行均保存在 `runtime/`，可以重新打开服务查看。`runtime/`、`node_modules/`、`dist/` 和浏览器临时结果不纳入 Git；源码、合成 fixture、锁文件、测试及必要验证摘要纳入 Git。不要把真实数据和凭据放入 fixtures。

## 结构与边界

```text
lab/
  src/          运行控制、独立世界、参考执行、API、验收和评分适配
  web/          React 控制台
  fixtures/     合成业务资产及公开交付契约
  tests/        单元、协议、反例与浏览器测试
  artifacts/    可审阅验证摘要与截图
  runtime/      本地运行索引、证据、产物与评审（忽略）
```

运行链：场景与固定种子 → 独立输入驱动 → 被测对象 → 工作工具/实际效果 → 独立事件账本 → 事实验收 → Agent 评审。Web 读取观察结果；浏览器关闭不取消实验。

程序事实验收读取实际成果、来源数据和送达记录，不将 `task.update(completed)` 当作成功证据。内层六域目前提供观测接口与记忆纠正场景，真实后端、长期情绪/人格和自主 core 能力保持**未验证**。状态上报不能冒充独立证明。

本机 DEV 运行允许开发者访问源代码和全部资料，**不是盲测隔离环境**。被测 API 不提供未来事件和评分材料，但同一操作系统用户仍可能读取开发文件；正式保留集测试须另做受限进程/容器与独立角色凭据。
