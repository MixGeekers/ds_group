# 外部被测 Agent 与评分 Agent 接入

协议版本 1。运行后 `/api/protocol` 也提供 JSON 说明。Lab 是本地 DEV 测试系统；这些接口不表示真实 DSH 已接通。

## 被测 Agent

在 Web 中选择“外部 Agent”并开始实验，获得 runId 和 targetToken。输入持续独立到达，结束输入后仍会等待已接纳工作；最长运行时限到达则保存中断状态和未完成项。

请求头：`Authorization: Bearer <targetToken>`。令牌按运行隔离，只能访问对应 `/target/runs/:id`，不能将其他运行的令牌混用。观察者界面/API 仅适用于本地开发，正式盲测须额外隔离目标进程。

| 请求 | 返回/用途 |
|---|---|
| `GET /target/runs/:id` | 状态、人员、会话、已注入任务；没有未来任务和评分答案 |
| `GET /target/runs/:id/inputs?after=0` | 已发生输入；按返回最大 seq 更新游标，重复轮询须按 event.id 去重 |
| `POST /target/runs/:id/actions` | `{ "operationId": "stable-operation-id", "action": {...} }`；执行工具或上报观察 |

每次动作具有稳定身份。超时或回执未知时，先用**同一 operationId 和同一内容**重试核对；同 ID 改内容会拒绝。重放返回原结果，不重复产生效果。只读探测若希望取得新状态，使用新的操作身份。

动作清单：

| type | 字段 | 语义 |
|---|---|---|
| `file.read` | path | 读取运行 workspace 下获准 inputs/outputs 文件 |
| `file.write` | taskId, path, content, encoding? | 在 outputs/taskId 中实际写入；二进制用 base64，文本用 utf8 |
| `task.update` | taskId, status, detail? | queued/running/waiting/completed/failed/cancelled；仅是目标上报状态 |
| `message.send` | channelId, text, taskId?, toActorId? | 在世界中实际送达并记录回执；演员在支持的互动分支回应 |
| `service.inspect` | taskId? | 返回此运行服务的当前配置、健康与版本 |
| `service.configure` | taskId, maxConnections, maintenance | 改变测试服务并记录独立效果 |
| `state.record` | domain, key, value, sourceRefs | 上报 memory/relationship/cognition/emotion/personality/capability 观察，不冒充已独立验证的内层写入 |
| `observe` | role, text, taskId?, data? | 记录 core/worker/replyer/memory 的可公开摘要；不要求隐藏推理 |

工具统一返回 `{ok, data?, error?, retryable?, unknown?}`。`ok:false` 不一定代表无效果；unknown 要核对。未支持的演员互动记录 lab_unsupported，不能当作目标能力失败。

任务包含所需输入路径和交付清单。`inputs/output-contracts.json` 是公开的机器验收格式，不包含正确答案；业务事实从各任务自己的数据文件取得。JSON 结果、可用文件和实际交付都需要完成。发送最终交付应在对应文件写入之后。不能仅回复“已完成”或修改任务状态。

## 评分 Agent

程序事实报告先独立生成。评分 Agent 可以评价协作、表达、成果实用性和主动判断，但不能覆盖程序发现的错误。当前评分包是**最终轨迹评审**，不是决定当时的盲评；评价早期动作时须按该事件前已可见证据，不因后来发生的事情倒推。

两种接入：

1. **HTTP 服务**：启动 Lab 前设置 `LAB_JUDGE_URL`，可选 `LAB_JUDGE_TOKEN`。操作员在界面发起评分时，Lab POST 一个 EvidencePacket，收取 JSON；无自动付费调用。
2. **文件导入**：`GET /api/runs/:id/evidence` 导出封存包，独立 Agent 评审后，通过界面或 `POST /api/runs/:id/reviews/import` 导入 `{review: ...}`。

HTTP 服务可由现有 Agent 框架或独立进程实现；端点是否实际使用工具由提供者负责，Lab 不把普通 HTTP 文本评审冒称工具型 Agent。令牌放在环境变量，URL 中不得带账号密码；远程端点用 HTTPS，本机可用 HTTP。请求超时、响应过大或 JSON 无效均保留 judge_error。

```json
{
  "dimensions": [
    {
      "name": "协作推进",
      "status": "scored",
      "score": 4,
      "reason": "说明具体依据和不足。",
      "evidenceRefs": ["替换为证据包内实际存在的引用"]
    }
  ],
  "needsHumanReview": true
}
```

scored 必须是 1–5 的整数并引用有效证据。`not_applicable` / `insufficient_evidence` 保留理由，不填 score。缺少证据、未知引用、越界分数均不能成为有效成绩。每次评审有新 ID，旧事实和意见不被覆盖；同类模型多数票不构成独立事实证明。

## 时间与费用

场景业务时钟按 speed 缩放，性能指标使用真实单调时间；二者分别记录。噪声数量变化会同时改变消息总量，不能直接解释为纯语义精度对照。参考执行器不调用模型；外部 Agent 与评分器可报告 usage，未报告时费用未知，不填零。
