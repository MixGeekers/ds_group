# 外部被测 Agent 与评分 Agent 接入

协议版本 1 保留给独立原型；原生插件增加下述 DSH 接入层与 outcome 成果模式。两种入口的认证不能混用。当前实现与验证范围见[插件实施记录](<插件实施记录.md>)。

## 识雨健身房原生插件

插件使用当前 DSH 的认证连接，不另开端口。界面与管理工具 `shiyu_gym` 共用服务：

- `snapshot`：公司/场景、运行、宿主模型能力及角色绑定。
- `create`：`driver=reference|dsh|external`，`config` 为运行参数；必填稳定的 `idempotencyKey`。DSH 默认业务成果模式，使用当前宿主模型；reference不调用模型。
- `get`：`runId/after/limit`，返回运行摘要及独立的 `eventPage`；`run.events`仅为末尾100条，不得当完整账本。
- `control`：`drain|stop`；`cancel_agent`：取消指定run的target或judge。停止和取消不删除已经发生的效果。
- `judge`：封存后明确发起独立只读评分，必填新的 `idempotencyKey`。相同请求重试复用旧key，复评使用新key。
- `preview/evidence/import_review`：读取真实成果、发现封存证据及保存新评分；旧事实报告不被覆盖。
- `probe_host`：只创建、检查并释放受限宿主Session，不向模型发送请求，用于接入核查。
- `settings_get`：读取健身房的 target/Judge 选择、revision 和当前有效模型；模型目录由 DSH 公共 `session.modelCatalog()` 提供。
- `settings_save`：携带 `settings/expectedRevision/idempotencyKey`；每个角色使用 `{mode:"follow_host"}` 或 `{mode:"explicit",model:{provider,model,reasoningEffort?}}`。保存与新 Session 启动都通过 DSH `llm.resolveCallConfig` 校验，不创建 provider、写密钥或改变宿主全局选择；省略强度表示模型默认。

管理HTTP入口为同源 `POST /api/shiyu-gym`，正文与工具参数一致。错误返回非2xx和明确message。`GET /api/shiyu-gym/artifact?runId=...&path=...`仅下载本次登记且完整的产物；`GET /api/shiyu-gym/evidence?runId=...`下载封存证据包。

### 0.3.0 房间、资料和剧本

创建自由会话使用 `driver=external`、`config.scenarioId=free-chat`、`evaluationMode=outcome`、`keepOpen=true`。它在剧本消息结束后继续接收输入，直到明确排空、结束或达到 `maxDurationMs`；默认界面时限为 600 秒，不是无限常驻。

| 动作 | 主要参数与效果 |
|---|---|
| `chat` | `runId/channelId/after/limit`，分页返回真实送达消息、附件及参与者；不能把普通模型最终回复当作已投递 |
| `send_message` | `runId/channelId/text/attachments/idempotencyKey`，以 HUMAN 身份向其所在会话发言 |
| `publish_task` | `runId/channelId/title/text/paths/idempotencyKey`，发布通用业务任务，验收不套用内置参考答案 |
| `workspace/workspace_read` | 查看房间文件清单，按 `path/offset` 分页读取；管理侧可见尚未分享资料，目标侧仅可见已引入资料 |
| `workspace_upload` | `runId/path/content/encoding/idempotencyKey`，文件在 `inputs/` 下，单次上限 1 MiB；上传后须通过附件或任务明确分享 |
| `scenarios/scenario_get` | 列出剧本、读取 `scenarioId`；内置剧本不原地修改 |
| `scenario_save` | `scenario/expectedRevision/idempotencyKey`，首次保存生成 `user-` ID，后续修改必须匹配 revision，防止覆盖并行修改 |
| `attach_target` | `runId/driver=dsh/idempotencyKey`，仅对活动 outcome 房间启动独立 DSH 模型；不能与另一个目标同时占用 |
| `connection` | `runId/idempotencyKey`，生成新接入口令并立即撤销旧口令；明文不写入持久请求账本 |

所有写请求重试使用原 `idempotencyKey` 和原内容。房间创建后保存独立公司/剧本快照，后续编辑不改变历史房间。`GET /api/shiyu-gym/workspace?runId=...&path=...` 是管理侧的工作区下载入口；它继承 DSH 的认证，不能替代目标接口。

### 已有 DSH 会话加入房间

在目标 DSH 会话中调用管理工具 `shiyu_gym` 的 `target_connect`，携带 `runId/targetToken/clientName`。Host 从工具执行上下文获取真实会话身份，不接受请求正文伪造 caller。成功后令牌立即消耗，后续用该会话身份调用：

- `target_inputs`：`runId/after/waitMs`，读取持续到达的输入。
- `target_action`：`runId/request`，request 与下方目标接口一致；普通聊天回复须通过 `message.send` 实际投递。
- `target_disconnect`：`runId`，断开本会话。管理界面的取消也会撤销旧连接和令牌。

已连接会话在 `shiyu_gym` 内仅可使用本房间的目标动作；这不是对该会话其他宿主工具或操作系统的全面沙箱。需要仅暴露专用工具的独立 Session 时使用“DSH 测试 Agent”。

### 外部协议客户端

从插件创建external运行获得runId/targetToken。调用 `POST /api/shiyu-gym/target` 时，**既需要DSH已认证连接，也需要正文中的运行令牌**；targetToken不是DSH登录凭据。

```json
{"runId":"本次运行ID","targetToken":"仅本次令牌","request":{"action":"inspect"}}
```

`request.action` 可为 `connect`、`inspect`、`inputs`（after/waitMs）、`act`（operationId/operation）、`preview` 或通用 Office 写入。HTTP 请求会记录实际外部参与者连接状态，拒绝与已接入的 DSH 目标争用房间。目标只可见已经到达的任务与明确分享的资料。模型内置目标也通过相同服务执行，但运行绑定由 Host 提供，不把明文令牌交给模型。

### 业务成果模式

`evaluationMode=outcome` 的任务包含 `businessRequirements` 与 `deliveryPolicy`；不要求参考文件名或result.json。文件写入 `outputs/<taskId>/` 后明确提交：

```json
{"action":"act","operationId":"delivery-T01-v1","operation":{"type":"task.deliver","taskId":"T01","paths":["outputs/T01/经营分析.xlsx"],"text":"本周经营情况与异常分析见附件。"}}
```

允许正文的任务可使用空paths和实际成果正文。单纯“收到”“已完成”、普通message.send或task.update不能代替明确提交。系统核对任务归属、实际文件、摘要和送达；未知结果按同ID同内容重试。

原生模型工具还提供通用 `write_spreadsheet`（rows）和 `write_document`（paragraphs），生成实际Office文件；不替模型计算业务答案。目标 `file.read` 每页至多24000字符，明确返回offset/nextOffset/truncated；续页通过新的操作身份和相应offset读取。二进制不把base64塞入模型上下文，使用 `preview` 按实际Office内容读取。Judge只使用 `gym_review`：overview/read/events/submit，不获得文件写入、系统Shell或管理权限。没有可靠内容解析时保留insufficient_evidence。

## 独立原型：被测 Agent

在 Web 中选择“外部 Agent”并开始实验，获得 runId 和 targetToken。输入持续独立到达，结束输入后仍会等待已接纳工作；最长运行时限到达则保存中断状态和未完成项。

请求头：`Authorization: Bearer <targetToken>`。令牌按运行隔离，只能访问对应 `/target/runs/:id`，不能将其他运行的令牌混用。观察者界面/API 仅适用于本地开发，正式盲测须额外隔离目标进程。

| 请求 | 返回/用途 |
|---|---|
| `GET /target/runs/:id` | 状态、人员、会话、已注入任务；没有未来任务和评分答案 |
| `GET /target/runs/:id/inputs?after=0` | 已发生输入；按返回最大 seq 更新游标，重复轮询须按 event.id 去重 |
| `POST /target/runs/:id/actions` | `{ "operationId": "stable-operation-id", "action": {...} }`；执行工具或上报观察 |

每次动作具有稳定身份。超时或回执未知时，先用**同一 operationId 和同一内容**重试核对；同 ID 改内容会拒绝。重放返回原结果，不重复产生效果。只读探测若希望取得新状态，使用新的操作身份。

动作清单：

| type | 字段 | 语义 |
|---|---|---|
| `file.read` | path | 读取运行 workspace 下获准 inputs/outputs 文件 |
| `file.write` | taskId, path, content, encoding? | 在 outputs/taskId 中实际写入；二进制用 base64，文本用 utf8 |
| `task.update` | taskId, status, detail? | queued/running/waiting/completed/failed/cancelled；仅是目标上报状态 |
| `message.send` | channelId, text, taskId?, toActorId? | 在世界中实际送达并记录回执；演员在支持的互动分支回应 |
| `service.inspect` | taskId? | 返回此运行服务的当前配置、健康与版本 |
| `service.configure` | taskId, maxConnections, maintenance | 改变测试服务并记录独立效果 |
| `state.record` | domain, key, value, sourceRefs | 上报 memory/relationship/cognition/emotion/personality/capability 观察，不冒充已独立验证的内层写入 |
| `observe` | role, text, taskId?, data? | 记录 core/worker/replyer/memory 的可公开摘要；不要求隐藏推理 |

工具统一返回 `{ok, data?, error?, retryable?, unknown?}`。`ok:false` 不一定代表无效果；unknown 要核对。未支持的演员互动记录 lab_unsupported，不能当作目标能力失败。

任务包含所需输入路径和交付清单。`inputs/output-contracts.json` 是公开的机器验收格式，不包含正确答案；业务事实从各任务自己的数据文件取得。JSON 结果、可用文件和实际交付都需要完成。发送最终交付应在对应文件写入之后。不能仅回复“已完成”或修改任务状态。

## 评分 Agent

程序事实报告先独立生成。评分 Agent 可以评价协作、表达、成果实用性和主动判断，但不能覆盖程序发现的错误。当前评分包是**最终轨迹评审**，不是决定当时的盲评；评价早期动作时须按该事件前已可见证据，不因后来发生的事情倒推。

两种接入：

1. **HTTP 服务**：启动 Lab 前设置 `LAB_JUDGE_URL`，可选 `LAB_JUDGE_TOKEN`。操作员在界面发起评分时，Lab POST 一个 EvidencePacket，收取 JSON；无自动付费调用。
2. **文件导入**：`GET /api/runs/:id/evidence` 导出封存包，独立 Agent 评审后，通过界面或 `POST /api/runs/:id/reviews/import` 导入 `{review: ...}`。

HTTP 服务可由现有 Agent 框架或独立进程实现；端点是否实际使用工具由提供者负责，Lab 不把普通 HTTP 文本评审冒称工具型 Agent。令牌放在环境变量，URL 中不得带账号密码；远程端点用 HTTPS，本机可用 HTTP。请求超时、响应过大或 JSON 无效均保留 judge_error。

```json
{
  "dimensions": [
    {
      "name": "协作推进",
      "status": "scored",
      "score": 4,
      "reason": "说明具体依据和不足。",
      "evidenceRefs": ["替换为证据包内实际存在的引用"]
    }
  ],
  "needsHumanReview": true
}
```

scored 必须是 1–5 的整数并引用有效证据。`not_applicable` / `insufficient_evidence` 保留理由，不填 score。缺少证据、未知引用、越界分数均不能成为有效成绩。每次评审有新 ID，旧事实和意见不被覆盖；同类模型多数票不构成独立事实证明。

## 时间与费用

场景业务时钟按 speed 缩放，性能指标使用真实单调时间；二者分别记录。噪声数量变化会同时改变消息总量，不能直接解释为纯语义精度对照。参考执行器不调用模型；外部 Agent 与评分器可报告 usage，未报告时费用未知，不填零。
