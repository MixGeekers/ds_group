# Lab 测试系统实施与验证

2026-11-01。用户已明确要求“把 Lab 做出来，测试系统先行”，随后明确指定“放在 lab 里”。本轮实施根为工作区 `lab/`，覆盖代码、依赖、构建和运行数据；该指定优先于一般探索脚本的 `测试/` 约定。本轮范围是独立本地 Lab，包含合成公司、八类实际工作资产、运行引擎、参考执行器、外部 Agent 接口、独立验收与 Web UI；不实现识雨产品内核，不改动已有资料工作台。

## 可判定的完成条件

- 一条命令启动本机 Web；可以选场景、配置噪声/并发、启动、停止、查看历史与成果。
- 业务输入按独立计划持续注入，不以模型/任务完成作为下一条输入的条件。
- 八类工作具备合成输入和实际文件/服务状态产出；验收独立读取成果，不信任“完成”自述。
- 参考执行器用于 Lab 自检，报告与 UI 明确标识，不据此报告识雨能力通过。
- 外部 Agent 使用受限 run token 读取已发生输入、访问测试工具、提交状态/产物；评分材料不进入此输入协议。
- 程序事实报告与可接外部 Agent 的评分分开；评分失败保持明确错误，不默认通过。
- 测试包括完成、损坏/虚假完成、持续噪声、取消、工具异常、历史恢复与接口访问边界。

## 环境与文件

代码、依赖、构建及运行数据均在本目录。`runtime/` 保存 SQLite 索引、逐次 manifest、JSONL 事件、工作文件和评审；忽略可重建环境与运行数据。`artifacts/` 保留必要验证摘要。使用当前 Node 24.19.0，依赖版本由 package-lock 固定。仅本地合成数据，无真实公司账号或设备；外部模型调用须由用户配置端点并主动运行。

## 实施选择与证据

TypeScript + Node + Fastify、React + Vite；SQLite 使用 Node 24 内置接口并做本机测试。官方参考：[Fastify](https://fastify.dev/docs/latest/Reference/Server/)、[Vite](https://vite.dev/guide/)、[Node SQLite](https://nodejs.org/docs/latest-v24.x/api/sqlite.html)。这些是接口依据，实际兼容性以本轮测试记录为准。

开发服务按需启动；不注册开机服务。验证后停止测试服务器，保留可启动代码与必要结果。长期能力与被测 DSH 接入分别标记，不把接口就绪记为产品实现。
