## 一句话判断

## 2026-11-02 限定服务实测

已在独立 Python 3.12.16 环境按固定源码与带 hash 的锁文件启动原版服务。单个 `test_data` 合成桶的唯一 grow、精确 ID/正文回读、一次正常服务重启、认证原生导出、归档/恢复与测试桶清除已验证；清除后认证 GET 返回 404。生成接口关闭，回环代理观察到生成 POST 为 0；Harrier 本地请求可用，但前缀差异和首轮 base64 维数误读均单独记录，不能继承原 embedding 质量评测。

首次脚本把优雅停止后的 SIGTERM 返回值误判为失败；保留原证据，只继续同一已确认 ID 的未完成步骤，没有第二次 grow。另用独立空 vault，让产品 TypeScript 私有 stdio 客户端与薄适配器调用一次 readI 并关闭，真实协议接线通过。它没有在 DSH Session 中装载，也没有接入正式记忆链路。过程、修正、证据与清理见[实验结果](<../测试/2026-11-02-Ombre服务验证/结果.md>)，后续严格写入和 Harrier profile 适配见[接入补充](<../research/2026-11-02-Ombre接入/服务接入补充.md>)。

这次试验支持继续复用服务，但普通记忆的严格创建、操作回执、CAS、真实清除和多受众权限仍需扩展；测试桶的可清除属性不用于绕开真实记忆政策。正式候选采用状态没有因试验成功自动升级。

## 它是什么，为什么关注

Ombre Brain 是通过 MCP 给模型使用的长期情绪记忆服务。记忆主体以兼容 Obsidian 的 Markdown 与 YAML 元数据保存，另配 SQLite 等派生状态、关键词 / 向量检索及 Web 管理界面。

它与我们的“遗忘、翻阅、梦境”设想直接相关：不是每次加载全部历史，而是区分哪些应当主动想起、哪些按需查询、哪些逐渐淡出，以及怎样回顾经历并留下新的理解。

项目定位与工具概览见 [项目说明](<https://github.com/P0luz/Ombre-Brain/blob/115d831d979bf67efc7150f976e2cb34c333c935/README.md#L15-L92>)。

## 可借鉴的机制

| 机制 | 实际作用 | 对识雨的启发 |
|---|---|---|
| `breath` | 带回核心准则、未解决事项及近期记忆 | 开始会话时恢复必要上下文，不把全部历史塞进工作记忆 |
| `hold` / `grow` | 记录事件或整理长内容，附带元数据 | 让经历成为可保存、可整理的记录 |
| 衰减与归档 | 降低不活跃记忆的权重，移出日常浮现 | 区分“当前在意”“可以翻阅”与“用户要求清除” |
| `dream` | 组织近期经历、相关记录、待办和自我候选 | 给回顾提供材料，再由模型决定是否形成新的理解或修订 |
| `I` | 候选自我描述经跨日回顾后显式晋升，并支持取代旧观点 | 不让一次临时判断立即成为长期规则；保留修订路径 |
| 正文与索引分离 | Markdown 先落盘，向量索引作为可重试的派生工作 | 不让网络或模型接口故障导致已经写入的记忆丢失 |

普通 `hold` 在打标服务失败时会保留正文并明确说明降级；这比“加工成功才算记住”更稳健。依据：[写入降级实现](<https://github.com/P0luz/Ombre-Brain/blob/115d831d979bf67efc7150f976e2cb34c333c935/src/tools/hold/core.py#L51-L110>)、[写后索引实现](<https://github.com/P0luz/Ombre-Brain/blob/115d831d979bf67efc7150f976e2cb34c333c935/src/bucket_manager.py#L947-L1013>)。

## 能力边界与不宜照搬之处

以下主要是产品语义与接入边界差异，不等于项目漏洞或无法适配。当前版本的普通搜索与默认浮现已不因命中而强化记忆，不能沿用“读即自强化”作为拒选理由；`dream` 仍会记录见证，应由内部整理任务调用。情绪坐标实际参与记忆评分与检索，不只是展示标签，详见本轮复评中的固定源码。

全架构复用核查进一步限定：启用them时，其surface/recall会改变待阅状态、人物触碰和无效依据，不能把基础search“不touch”推广为所有组合读取纯只读。初验You/them保持关闭；后续由内部任务生成可审阅快照。原生SourceStore/MediaStore和导出可直接复用，组合恢复另需组件清单；512MiB导入/导出限制先按小夹具验证。详见[记忆核查](<../research/2026-11-01-复用核查/记忆关系认知.md>)与[恢复核查](<../research/2026-11-01-复用核查/恢复备份.md>)。

### 1. 回顾接口不是自主改进循环

`dream` 筛选、组织材料并返回给调用模型；后续反思和写回仍需模型另行完成。`plan` 是待办与承诺记录，新事件的检查可以提出完成建议，但不负责执行计划，也不自动完成代码修改、测试或训练模型。

依据：[dream 入口](<https://github.com/P0luz/Ombre-Brain/blob/115d831d979bf67efc7150f976e2cb34c333c935/src/tools/dream/__init__.py#L30-L103>)、[计划完成建议实现](<https://github.com/P0luz/Ombre-Brain/blob/115d831d979bf67efc7150f976e2cb34c333c935/src/tools/_common.py#L1353-L1428>)。

**适配判断：**若用于识雨，还需要“回顾 → 改进提案 → 授权范围内试验 → 验证 → 保留或回滚”的闭环。记忆写入和自我描述变化不等于模型权重更新，也不等于能力已经提高。

### 2. 三次见证不等于三次验证

`I` 的见证计数是：候选正文实际出现在 `dream` 返回文本中，按服务端三个不同日历日期各记一次；达到门槛后仍须显式晋升。它并不检查模型是否认真完成反思，也不代表获得了三条独立证据。

依据：[按日记录见证](<https://github.com/P0luz/Ombre-Brain/blob/115d831d979bf67efc7150f976e2cb34c333c935/src/tools/i/core.py#L420-L454>)、[晋升门槛](<https://github.com/P0luz/Ombre-Brain/blob/115d831d979bf67efc7150f976e2cb34c333c935/src/tools/i/core.py#L303-L336>)。

**适配判断：**可以借鉴候选与正式条目的区分，但应另外记录依据、反例、置信程度和用户纠正，不能把重复出现当作真实性证明。

### 3. 普通记忆可读，但完整原文证据没有 MCP 回读入口

项目刻意将另存的原文证据层设为 MCP 只写不读，用于备份等用途，不参与日常回忆。这与普通记忆正文的读取是两回事。

依据：[原文证据边界](<https://github.com/P0luz/Ombre-Brain/blob/115d831d979bf67efc7150f976e2cb34c333c935/README.md#L104-L111>)。

**适配判断：**识雨应在授权范围内支持从判断追溯来源、核对和纠错，而不是只保留无法复核的整理版本。

### 4. 真实记忆的“删除”是归档，不是擦除

常规删除保留真实记忆正文并移至归档。物理删除路径仅允许明确标记为可擦除测试数据的桶，不能满足用户对真实信息的彻底清除要求。

依据：[归档式删除实现](<https://github.com/P0luz/Ombre-Brain/blob/115d831d979bf67efc7150f976e2cb34c333c935/src/bucket_manager.py#L3094-L3139>)、[硬删除限制](<https://github.com/P0luz/Ombre-Brain/blob/115d831d979bf67efc7150f976e2cb34c333c935/src/bucket_manager.py#L2719-L2740>)。

**适配判断：**应把“自然淡忘”和“撤回保存许可”分开；后者还需处理原文、索引、派生记录及备份副本。

### 5. 可选认识模块不完全向用户展示

`You` 默认关闭，但开启后用户面板仍不展示其中的认识、证据与历史；`them` 的展示范围也有刻意限制。这是产品取舍，不应直接称为权限漏洞。

依据：[You / them 可见性说明](<https://github.com/P0luz/Ombre-Brain/blob/115d831d979bf67efc7150f976e2cb34c333c935/README.md#L94-L102>)。

**适配判断：**与识雨“可检查、可纠正、受用户指引”的方向不同，不直接采用关于用户的不可审阅判断层。

### 6. 本地存储不等于所有处理都在本地

配置远程整理或向量服务时，相应文本会发往服务商；本地模型是可选路线。GitHub 同步与本地导出包含可读原文，完整性校验不等于加密保护。

依据：[向量请求实现](<https://github.com/P0luz/Ombre-Brain/blob/115d831d979bf67efc7150f976e2cb34c333c935/src/embedding_engine.py#L230-L258>)、[原文与备份隐私提醒](<https://github.com/P0luz/Ombre-Brain/blob/115d831d979bf67efc7150f976e2cb34c333c935/README.md#L104-L111>)。

**适配判断：**试验前明确数据去向、模型服务、费用、访问权限与备份策略；候选收录不授权上传我们的对话。

## 产品实施增量（3E，限定路径已验）

既有 3D 试验保持原范围。当前产品在固定未修改上游之上增加[受控服务](<../plugins/shiyu/service/ombre/README.md>)：普通 dynamic 桶保存唯一正文，操作 journal 只存元数据；私有 create/status/get 经共享授权与独立核验，再形成本地读取资格。Runtime 已接线显式保存、精确读取及本地撤回，535 全量模块、37 Python 通过，后增 gate 16 与分批 UI 结果独立记录；[真实 DSH 证据](<../plugins/shiyu/artifacts/memory-host-validation.json>)核对一次 97 字节普通记忆的保存、精确读回、有序重载再读和本地撤回，原生文件保留。撤回不等于原生删除；语义搜索、普通清除/CAS、自主整理及六域 ReadView 均未完成。实施进展不自动把整个候选改为正式采用，证据见[本体记录](<../plugins/shiyu/实施记录.md>)。
