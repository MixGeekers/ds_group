## 核心判断

**值得参考，尤其能为识雨的 replyer、worker 通信、外层调度与长会话管理提供具体工程案例。** 内部记忆的中断恢复与技能提案流程也有借鉴价值。

DS-Bot 以多个可长期工作的 Bot 组成团队；每个 Bot 可以对话、使用工具并维护记忆。识雨则要求外层对内部状态只读，并包含记忆、关系、情绪、认知、人格、能力六部分。两者的权限划分不同，Main Bot、普通 Bot 和群管理员不能直接映射成已经确认的 core / worker / replyer。

当前建议直接复用其可分离的 replyer 与幂等实现子集；不整套作为识雨内核或外层依赖。本轮核查没有形成它能覆盖识雨完整内层的证据。原项目其他模块的记忆写入能力不是拒绝这些子集的理由。

## 值得借鉴的机制

### 1. 侧边对话：读取主任务快照，独立回答

**已静态核查：**`sideAsk` 从主会话取得历史、模型路由及事件位置快照，单独发起模型调用。侧边问答不写回主 Session；模型生成工具调用时，宿主不分发执行，重试一次后仍调用工具则将回答标为失败。主任务可继续运行。

这接近识雨 replyer 的一个可行起点：在内部工作时，基于某个状态版本回答“现在做到哪了”“为什么这样判断”，而不必接管内部任务。

**适配限制：**这里的快照是主会话材料，不是按识雨权限裁剪后的内部视图；请求仍带原工具 schema，禁止执行由旁路调用路径保证。侧边问答另存到 `side/<botId>.json`，不能将“不写主会话”解释成“不保存任何数据”。识雨仍需定义视图范围、版本、过时处理和临时数据保留规则，也需另外设计外 → 内的输入通道。

依据：[快照与模型调用](<https://github.com/Fei2411/DS-Bot/blob/f823773b07ec6ca29d60b31c31af30218a68000d/ds-bot/src/host/btw.js#L141-L179>)、[工具调用结果处理](<https://github.com/Fei2411/DS-Bot/blob/f823773b07ec6ca29d60b31c31af30218a68000d/ds-bot/src/host/side.js#L223-L250>)、[侧边数据落盘](<https://github.com/Fei2411/DS-Bot/blob/f823773b07ec6ca29d60b31c31af30218a68000d/ds-bot/src/host/side.js#L69-L95>)。

### 2. 派工有明确语义：补充信息、排队、回传与去重

**已静态核查：**`message_bot` 区分 `when: now` 与 `when: queue`。前者可在正在运行的任务下一步送入补充信息；后者在当前工作结束后作为后续任务处理。结果异步回到请求者。任务记录带父子关系，支持等待下级任务结果，较长结果另存文件以供恢复。

命名请求还提供较完整的重复投递处理：

- `request_id` 与调用 Bot、会话范围及请求内容指纹关联；同名同内容返回已有回执，不再投递。
- 同名不同内容明确拒绝。
- 投递前先保存受理记录；重启后若无法确定此前结果，则报告 `uncertain`，不直接再次派工。

**对识雨的价值：**为双工通信中的任务身份、接收回执、结果回传及未知状态提供参考，减少重复执行和上下文混用。

**限制：**`request_id` 是可选参数；该机制约束命名消息的投递，不能外推成任意工具动作或整个系统的“恰好一次执行”。任务取消也不撤销已经产生的外部副作用。

依据：[消息模式与派工路径](<https://github.com/Fei2411/DS-Bot/blob/f823773b07ec6ca29d60b31c31af30218a68000d/ds-bot/src/host/tools.js#L143-L267>)、[请求受理与未知结果](<https://github.com/Fei2411/DS-Bot/blob/f823773b07ec6ca29d60b31c31af30218a68000d/ds-bot/src/host/requests.js#L19-L137>)、[父子任务与结果](<https://github.com/Fei2411/DS-Bot/blob/f823773b07ec6ca29d60b31c31af30218a68000d/ds-bot/src/host/handoffs.js#L93-L172>)。

### 3. 对话顺序与后台工作分别调度

**已静态核查：**群聊按发言槽依次调用成员；管理员模式下，普通用户消息默认先交给管理员，明确 @ 再选择其他成员。成员开始较长工具工作后，轮次可继续，成员在自己的群 Session 中完成任务，再回传结果。代码还区分等待批准、工作中、失败、未回应与主动跳过，支持停止某个成员或整个群的工作。

Bot 互相接力达到群上限后，会暂停待续而非无限循环。该上限只控制接力次数，不是全局 token 或并发资源预算。

**对识雨的价值：**外层可以维持有序表达，同时让独立工作并行；“谁能发言”和“谁正在工作”可以有不同状态。无需为每条输入唤醒全部角色。

依据：[工作期间让出轮次](<https://github.com/Fei2411/DS-Bot/blob/f823773b07ec6ca29d60b31c31af30218a68000d/ds-bot/src/host/groups.js#L298-L341>)、[状态与接力控制](<https://github.com/Fei2411/DS-Bot/blob/f823773b07ec6ca29d60b31c31af30218a68000d/ds-bot/src/host/groups.js#L458-L554>)、[选择发言者](<https://github.com/Fei2411/DS-Bot/blob/f823773b07ec6ca29d60b31c31af30218a68000d/ds-bot/src/host/groups.js#L775-L791>)。

### 4. 长会话管理：按任务状态压缩或换段

**已静态核查：**context steward 使用当前会话的模型路由另做一次小范围判断，根据最新消息选择：工作仍在进行则压缩成 checkpoint；到达停顿点则带交接材料切到新段。它是单独的模型调用，不是已经训练好的专用记忆模型。

checkpoint 除总结外，另保留预算内的近期输入原文及消息锚点；超长文本仍可能裁切，旧消息可从日志和 SQLite FTS5 索引查询。写交接笔记失败时，未到硬上限可保留原段稍后再试，到了硬上限则走降级换段路径。

**对识雨的价值：**可以分别管理当前工作上下文、可回查的原始经历、内部选取的长期记忆，降低连续“总结的总结”丢失约束与未完成事项的风险。

**限制：**完整历史可回查意味着保存了历史；识雨仍需约定原始日志的保存与删除。阈值、摘要准确性、延迟和额外模型开销均未在本轮验证。

依据：[steward 与 checkpoint 规则](<https://github.com/Fei2411/DS-Bot/blob/f823773b07ec6ca29d60b31c31af30218a68000d/ds-bot/src/host/steward.js#L20-L51>)、[原文保留与模型调用](<https://github.com/Fei2411/DS-Bot/blob/f823773b07ec6ca29d60b31c31af30218a68000d/ds-bot/src/host/parts.js#L449-L561>)、[换段降级](<https://github.com/Fei2411/DS-Bot/blob/f823773b07ec6ca29d60b31c31af30218a68000d/ds-bot/src/host/parts.js#L883-L930>)。

### 5. 记忆提交的可恢复性，比具体 Markdown 格式更值得借鉴

**已静态核查：**记忆分 Bot、群、团队范围；条目带来源、日期，修改日志保留前后内容。写入串行化，并先保存 `pending.json`，再修改正文、主题索引和 journal。中断后重放未完成步骤，日志按操作 ID 避免重复记录；待处理记录损坏时停止相关读取或写入，而非当成没有发生过。

**对识雨的价值：**内部一次记忆变更可能牵涉多份状态；需要知道“是否受理、哪些步骤完成、是否可对外确认”，这可以成为 core 控制提交的工程参考。

**限制：**这是进程内串行与文件恢复方案，未验证跨进程故障、断电耐久性或生产规模；本轮不能称为通用数据库事务。`recall` 的 `settled` 路径会先恢复待完成写入，所以该读取入口也不是严格无写入副作用的接口。

依据：[提交、恢复和串行读取](<https://github.com/Fei2411/DS-Bot/blob/f823773b07ec6ca29d60b31c31af30218a68000d/ds-bot/src/host/memory.js#L630-L675>)、[来源与写入工具](<https://github.com/Fei2411/DS-Bot/blob/f823773b07ec6ca29d60b31c31af30218a68000d/ds-bot/src/host/memory.js#L1052-L1144>)、[recall 路径](<https://github.com/Fei2411/DS-Bot/blob/f823773b07ec6ca29d60b31c31af30218a68000d/ds-bot/src/host/memory.js#L1194-L1205>)。

### 6. 工作经验先形成技能提案

**已静态核查：**长任务后、团队空闲时，learning 模块检查是否有值得保留的可复用经验，提出创建或更新 skill、修订项目规则的候选。提案等待用户处理；拒绝项进入后续评估上下文，更新时核对基础内容，避免覆盖提案产生后的新修改。

**对识雨的价值：**为“能力”中的经验整理提供一个有形对象：提出什么改进、依据是什么、是否已经应用。可进一步研究“提案 → 隔离验证 → 保留或撤回”的流程。

**限制：**当前核查证明的是生成、审阅与应用提案的流程，不是能力提升已经被验证，也不是模型权重学习。DS-Bot 的提案批准政策只描述该项目，不自动成为识雨的最终自动化策略。

依据：[技能筛选标准](<https://github.com/Fei2411/DS-Bot/blob/f823773b07ec6ca29d60b31c31af30218a68000d/ds-bot/src/host/learning.js#L58-L81>)、[提案处理](<https://github.com/Fei2411/DS-Bot/blob/f823773b07ec6ca29d60b31c31af30218a68000d/ds-bot/src/host/learning.js#L630-L648>)、[更新冲突检查](<https://github.com/Fei2411/DS-Bot/blob/f823773b07ec6ca29d60b31c31af30218a68000d/ds-bot/src/host/learning.js#L691-L716>)。

## 与识雨边界不一致的部分

1. **对话 Bot 有记忆写权限。** `remember` / `forget` 直接进入记忆写入链；自动 memory review 在会话 idle 后触发，模型提出 add / edit / remove 后经程序检查执行。群管理员还可写团队记忆。这不是识雨已经明确的外层只读。借鉴时需把决定和提交放回内部，不能只把 Bot 改名为 replyer。[权限与操作](<https://github.com/Fei2411/DS-Bot/blob/f823773b07ec6ca29d60b31c31af30218a68000d/ds-bot/src/host/memory.js#L693-L719>)、[自动应用](<https://github.com/Fei2411/DS-Bot/blob/f823773b07ec6ca29d60b31c31af30218a68000d/ds-bot/src/host/memory.js#L1535-L1567>)。
2. **独立群会话不是完全的信息隔离。** `groupSessionFor` 创建普通成员的群 Session 后，会调用 `ownChatBrief` 带入其与用户私聊的近期摘要，提示它只分享群需要的内容；群内提示还包含该 Bot 自有记忆和团队记忆。因此不能照抄 README 的隔离表述。0.2.4 另有明确的 private Bot 机制，且禁止 private Bot 入群；这是另一条边界，不应混淆。[群初始化](<https://github.com/Fei2411/DS-Bot/blob/f823773b07ec6ca29d60b31c31af30218a68000d/ds-bot/src/host/groups.js#L198-L230>)、[私聊摘要](<https://github.com/Fei2411/DS-Bot/blob/f823773b07ec6ca29d60b31c31af30218a68000d/ds-bot/src/host/chat-index.js#L282-L289>)、[private Bot 限制](<https://github.com/Fei2411/DS-Bot/blob/f823773b07ec6ca29d60b31c31af30218a68000d/ds-bot/src/host/privacy.js#L329-L348>)。
3. **forget 不代表彻底清除。** 条目从现用文件移除，journal 仍保留原内容；删除 Bot 的记忆移动到 archive。识雨若承诺清除，还需要覆盖日志、快照、派生索引等范围的独立路径。[删除实现](<https://github.com/Fei2411/DS-Bot/blob/f823773b07ec6ca29d60b31c31af30218a68000d/ds-bot/src/host/memory.js#L828-L875>)。
4. **部署与替换成本依赖 DSH。** 当前 Session、工具、模型流、权限和会话压缩依赖 DSH 服务；这里不是可单独替换的记忆引擎。仓库含桌面、容器、浏览器等广泛功能，本轮未审查这些完整执行链。存储在本地也不说明模型处理全部本地，实际数据去向取决于模型路由。[包依赖](<https://github.com/Fei2411/DS-Bot/blob/f823773b07ec6ca29d60b31c31af30218a68000d/ds-bot/package.json>)、[运行时组成](<https://github.com/Fei2411/DS-Bot/blob/f823773b07ec6ca29d60b31c31af30218a68000d/ds-bot/index.js>)。

## 适配位置与现有基线

| 识雨问题 | 本候选增加的参考 | 尚未解决 |
|---|---|---|
| replyer 读内部视图 | Side chat 的快照、独立回答、宿主不执行工具调用 | 视图授权、最少暴露、双工协议、版本失效 |
| worker 委派与外层队列 | now / queue、任务父子关系、接力限制、命名请求回执 | worker 层级、提交权、全局资源限制、实际行动的恢复 |
| 长期运行 | checkpoint / 新段、原文锚点、历史索引 | 原始记录保留、摘要质量和延迟预算 |
| 内部记忆 | 作用域、写入日志、pending 恢复、读视图快照 | 保存决策可靠性、无副作用只读、彻底清除 |
| 能力改进 | 从经历形成可审阅技能提案、冲突检查 | 改进效果验证、回退、自动提交条件 |

当前识雨仍是设计文档；局部复制方案尚未接入。DS-Bot 为 replyer 和命名请求提供具体实现基线，其余机制按独立模块继续比较；不据静态阅读作效果排名。
