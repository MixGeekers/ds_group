# 跨服务器 Bot 工作授权与交付

2026-11-04，起点 `0d0ed79`，实施分支 `codex/dscord-cross-server-bot`。本切片复用原 Bot、所有者、节点目录、NodeStore、TaskService 和 DSH。治理、身份和前端由各自实施线拥有；本切片没有改动旧识雨、工作台或健身房。

## 已实现的执行路径

节点以原 Matrix ID 同步外服房间。公开 `/api/bootstrap` 保持匿名本地名册；携带 Bot 范围节点凭据的 `/internal/bots/:botId/rooms/:roomId/directory` 只返回本房间中实际加入且获准的成员，不公开全局准入名单或其他 Bot 的私有说明。

所有者通过 `GET/PUT /api/bots/:botId/work-grants` 管理精确房间、完整请求者 ID 与四种文件工具。该接口核对当前有效人类登录和既有 `bot.ownerId`，使用 revision CAS。治理管理员的 `botPolicies` 是额外限制，不能产生所有者授权。初始没有外服授权。

节点接纳时从自己的归属 Matrix 服务读取真实事件、当前成员、实际策略 state 和 power levels。策略统一为 `org.dscord.work_policy`、空 state key，固定发送者及 `issuerId` 必须是 `@dscord-control:<已登记authority>`，并具有当前成员身份及足够的 state 权限。来源服本地成员以实际成员关系准入，外部成员必须在显式名单中；归属服仍核对自己的外部准入及所有者完整 requesterId。工具取所有者、归属服 Bot/房间限制、来源房间 state、实际节点工具和任务范围的交集。

授权成功后，在附件读取等步骤之前立即保存到原 inbox 请求。每次原生模型步骤、文件工具执行、附件读取（包括缓存）、成果上传及最终发送重新核对当前授权。相关规则变化使旧接纳失效。策略哈希对对象键排序，规则数组及当前观众保留明确语义；同语义对象键序变化不制造新授权域。

跨服工作复用普通 DSH 原生 Session，每个 Bot/来源服/房间/授权安全绑定有持久独立 Session。原 DS-Bot 身份和私人主 Session 不变；不复制原私聊、私人记忆或其他房间的 Session。只有本房间当前获准成员的历史和明确引用的文件进入该域。当前工具为 `read`、`write`、`edit`、`read_image`，路径必须位于当前任务目录，拒绝穿越及符号链接。终端、后台作业、技能、会话/记忆读取及外服委派未开放。

输入附件以真实 `{roomId,eventId,senderId,attachmentId,contentUri,sha256,size}` 为证明，经原 Bot 的归属 Matrix 媒体接口读取，并验证实际字节。外服 attachmentId 不访问本服同名媒体索引。输入上限取当前归属服上传限制与实际节点上限的较小值；缓存按授权域隔离，命中前仍复验。成果经原 Bot 的归属 Core 上传，回到原房间、原事件和原完整人类 ID。当前不创建新的外服私聊；原本即两人的获准会话可原地交付。

原生工具回执、上传附件和 Matrix outbox 分别保存。撤权不抹去先前已知效果；上传已取得有效回执但观察失败时保留附件并标记 observationPending。迟到结果、未知发送和撤权后的观察另留审计；重试保留原 upload ID 和 Matrix transaction。旧未授权结果不能升级成新的外服成果。

## 本轮证据

`npm run check` 的 320 项模块检查、JS 语法和 Web/Admin TS7 类型检查通过。新增回归覆盖完整 ID、固定 issuer、当前权限、六层能力交集、所有者 CAS、每阶段撤权、稳定策略哈希、独立连接恢复、提前持久化授权、下载失败及接纳前重启、已知上传保留、未知发送和冻结重试。

真实 DSH 宿主使用 localhost 脚本 provider，8 项检查通过，10 次脚本生成，0 次远端模型。实测包括原生读写及目录外读取拒绝、原私人 Session 排除、两房间历史隔离、同域复用、撤权后下一次写入被拒、已有文件保留、重启绑定和已完成请求去重。此层的工作授权服务为合成夹具，不算真实联邦 Bot 验收。

前三次原生运行失败来自夹具误选 DSH 追加的运行上下文消息；第四次暴露将异步授权放入同步 `tools.guard` 的错误，隔离宿主退出。修复使用异步 `tools/execute` 后通过，原始失败和源码哈希保留在 [历史失败](native-runtime-failures.json)，当前成功见 [原生验证](native-runtime-validation.json)。
