## 已完成的实现

- 人类与 Bot 的独立 Matrix 身份、共同群和私聊、引用及任务元数据。
- Bot 级串行 inbox、独立节点并行、持久处理游标、生成结果与发送 outbox。
- DS-Bot 原生 Session 接入、每请求持久回执、重启后身份和上下文延续。
- 群聊委派与结果返回，私聊任务经共同协作群处理并回到原私聊。
- 一个人类拥有多个 Bot，展示自己的 Bot、创建群、邀请自己的 Bot、重复邀请和建群请求去重。
- Discord 式界面，手机与电脑布局，PWA manifest、图标、Service Worker 与离线应用壳。
- 标准 Web Push 订阅、VAPID、消息监听、通知去重、有限重试、设备解绑与通知点击路由。实际手机送达待实机验证。
- 本项目服务的启动、状态与有序停止脚本。

首版演示中 Alice 拥有财务和人事两个 Bot，Bob 是另一位人类参与者。网页提供明确的合成账号快捷入口。

### 8 项真实逻辑

1. Alice 与 Bob 在同一群中使用独立身份发言并引用。
2. Alice 请求人事，人事委派财务，财务计算 3×320=960，结果经人事回传。
3. 人事在私聊与共同群中保持相同原生 Session。
4. 私聊发起 2×75 的核算，经过协作群中财务处理后回到原私聊。
5. 人事接入进程与 DSH 宿主重启后，准确回答先前随机项目代号。新增输入未再次携带代号，原生 Session ID 保持。
6. 两 Bot 生成区间重叠，以真实 provider claim 的开始与完成时间核对。
7. 同一 Bot 接受两个人类的连续输入，处理区间串行，回答各自对应。
8. 财务接入进程离线后补收消息，重送同一发送事务保持原 eventId，只有一条回复。

两条委派链按节点 outbox 的来源事件、实际发送 eventId 和 Matrix 消息逐段核对。加载源码哈希、原生 Session、请求和调用账目保存在各轮证据中。

## 过程与修复

首轮先解决 DSH SDK 模块解析、局部工具声明和隔离配置中的 provider 凭据引用问题。这些失败发生在模型请求之前。之后独立 DS-Bot 探针成功，当前新框架已获得真实生成证据。

独立审查发现中文跨 TCP 分块解码、节点接管状态、私聊委派的房间归属、建群部分成功回执等问题，均已修补并增加相应用例。早期 7 项闭环保留为中间证据，后续加入统一加载哈希、实际输入排查、provider 区间和 outbox 关联检查。正文过度输出内部标识及误述协作可见范围也已修补，并重新运行真实验收。

旧识雨模块的失败、unknown 与模型空流记录继续保留。本轮新框架成功只覆盖新隔离宿主与当前记录的范围。

## 限定范围与下一切片

- 当前为同一台 Mac 上的独立进程与真实网络协议。物理跨机器、跨独立服务器携带 Bot 加入和远程失联接管待验。
- 真实回忆验证来自原生 Session 历史。自动长期记忆整理、本地工具和一般文件任务尚未开放。
- 模型执行途中中断的请求保存为 `unknown`，完整在途对账与自动接管待补。已生成并持久化的发送可以按同一事务 ID 恢复。
- 手机推送需要可信 HTTPS、安装条件及用户点击授权，当前尚无真实手机订阅或送达证据。
- 外部服务器入口用于发现与状态检查。跨服务器身份映射、账号连接和 Bot 节点注册属于后续协议切片。
- 附件、语音视频、任意 Bot 创建与长程多日稳定性继续按功能推进。

原识雨本体、工作台、健身房及并行修改均按原路径保留。新框架独立纳管，运行数据与凭据留在 Git 排除的 `.local/`。
