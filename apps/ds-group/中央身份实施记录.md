# DSCord 中央身份与默认归属服务

日期：2026-11-04（America/Caracas）。分支：`codex/dscord-central-identity`，基线：`5078ab2bf81fe50631a13208366cc3e58d61dd7d`。范围为中央身份、默认归属、账号兼容与独立客户端接入；共享架构、正式客户端、独立管理认证与联邦准入由对应并行切片整合。

## 已接通的产品入口

首切片复用归属 Synapse 的真实密码认证和设备会话。中央 Core 附加账号主体映射、默认归属配置、公开发现和客户端 Origin 策略。它不实现新的密码数据库，也不是 OIDC issuer。

| 入口 | 实际行为 |
|---|---|
| `GET /.well-known/dscord/client`、`GET /api/client-config` | 公开版本化认证、Core/Matrix 归属和凭据用途；无凭据请求可从任意 Origin 发现 |
| `GET /.well-known/matrix/client` | 返回归属 Matrix `m.homeserver` 和 DSCord Core 地址 |
| `GET /api/bootstrap` | 保留已有字段，增加 `identity` 发现对象 |
| `POST /api/register`、`POST /api/login` | 使用既有 Synapse 路径；保留 Matrix `user_id/access_token/device_id/可选 expires_in_ms`，增加 `identity/home` |
| `GET /api/me` | 保留 `user/ownedBots`，增加稳定主体和归属；逐次核对 Matrix 有效性和本地 active 状态 |
| `POST /api/logout` | 撤销本设备的 Matrix 会话；重复退出成功。历史合成 demo 共用的服务凭据继续只在客户端退出 |
| `scripts/central-init.mjs` | 将已有初始化部署配置为中央默认归属，首次可建立没有示例用户的空账号目录 |

接口的可读完整形状、目标地址规则和版本差异见[契约](<artifacts/central-identity/contract.json>)。契约当前为 `1.0.1`，补充真实附件所需 `X-Upload-Id` 和旧单服回退。

## 身份和凭据

`accounts.sqlite` 新增 `account_subjects`，将完整 Matrix ID 唯一映射到持久随机 `subjectId`。`account_metadata` 保存永久 `authorityId`、Matrix `serverName` 和身份 schema 版本；未知新版本拒绝打开，避免降级。人类与 Bot 保持不同账号种类；Bot 返回其原 `ownerMatrixUserId` 和已登记所有者的主体。显示名称可以相同或修改，授权继续使用完整 Matrix ID，不能用昵称、localpart 或邮件匹配来绑定外服身份。

`authorityId` 是该部署账号映射的永久标识，不是 Matrix 联邦签名身份或 OIDC issuer。Matrix 服务器仍以原 `serverName`、签名密钥和协议参与联邦。`identity-config.json` 固定默认归属 serverName，并保存公开端点与独立客户端 Origin；它和账号数据库的 authorityId 必须一致。公开 Core/Matrix 地址可由明确配置更新，不能借改 URL 将账号改到另一 Matrix 域。

人类客户端的设备 token、Core 的服务设备 token、Bot Matrix token、Bot 节点凭据和每服独立部署管理会话用途分别保留。新注册人类/Bot 均是非 Synapse 管理账号。普通中央 token 无法作为节点凭据；它也不授予外服或每服部署管理权限。已有 Synapse 运维管理员固有的 Matrix 管理权限由 Synapse 自身控制，不把这种账号当普通用户测试样本。

外服协作通过归属 homeserver 联邦参与房间，保留原 Matrix ID。中央普通 token 只面向配置中的归属 Core `/api/` 与归属 Matrix 客户端/媒体 API。外部 URL 只能无凭据发现，不得更换已有会话归属。所有 Core → Matrix 请求（包括登录和媒体）拒绝重定向，避免密码、文件或认证信息随跳转发送。远端 Core 专用授权本切片未实现，也未下发任何远端 token。

## 受保护入口的统一门禁

Core 在进入具体普通 `/api/` 路由前执行 `accounts.authenticate`：使用唯一内部 homeserver 校验 `whoami`，再从 SQLite 读取该完整账号的当前 `status`，仅 `active` 通过。校验结果同时保留在 `request.dsIdentity`；后续路由可复用用户 ID，但不能绕过该入口或把远端声明当主体。空间、附件、任务、通知和后续新增普通 API 都落在此门禁后；本切片对尚未实现的 `/api/spaces` 只证明路由前拒绝禁用用户，并不宣称空间功能已经完成。

公开发现、健康/就绪、公开状态、通知能力配置与明确的注册/登录/demo 入口在门禁前；退出独立处理，以便失效或禁用用户仍能撤销本设备。登录、注册重试、补全和激活路径拒绝 disabled/deactivated，不能用一次正确密码登录重新启用本地禁用账号。新普通路由必须放在门禁后；并行治理切片若移动空间路由，应保留这一顺序。独立部署管理 API 由自己的管理认证授权，不能复用本门禁通过作为管理授权。

本地禁用只控制 Core API；它不冒充 Synapse 的全局撤销。直接 Matrix 访问需要归属 Synapse 运维停用或撤销设备。本切片分别实测了本地 disabled 和真实 Synapse deactivation。既有节点凭据不因人类退出被轮换；所有者停用是否冻结既有 Bot 运行属于治理/节点生命周期策略，不能从这次普通 API 门禁推出。

## 独立部署和旧数据升级

先使用现有 `scripts/server-init.mjs` 配置永久 `serverName`、内部 Matrix 地址和公开地址；部署生命周期仍沿用现有服务器工作。随后运行：

```sh
node scripts/central-init.mjs \
  --data-dir /srv/dscord/core \
  --core-url https://core.example \
  --matrix-url https://matrix.example \
  --client-origin https://client.example
```

客户端 Origin 可重复指定，必须是精确 HTTPS origin，本机验证允许 HTTP loopback；禁止 `*`、`null`、凭据、路径、查询和片段。公开 Core origin 自动允许。独立客户端源码和构建由客户端切片维护，本切片没有增加第二套产品 SDK；`tests/helpers/home-session.mjs` 只用于浏览器协议验证。

CORS 在处理 API 前检查 Origin。允许请求头是 `Authorization`、`Content-Type`、`Range`、`X-Upload-Id`；暴露 `Retry-After`、`Content-Disposition`、`Content-Length`、`Content-Range`。不使用 cookie 会话，也不允许带 cookie/Authorization 的公开发现。实际错误响应也保留已获准 Origin 的 CORS 头。CORS 是浏览器接入策略，账号和权限仍由服务器认证核验；命令行/节点没有 Origin 时仍须提交其对应凭据。

旧单服无需开启 central。已有公开 `publicUrl` 与 HTTP 私网地址保持可用。没有配置公开 Core URL 的旧单服发现返回 `home.coreUrl=null`，客户端只按其已经信任的发现来源补全；API 会话中也可能保留 null，恢复时须按同一来源规范化。原 HTTPS 反代在没有 publicUrl 时应保留 Host，允许与该 Host 对应的同 Origin HTTPS 浏览器访问；显式 publicUrl/identity.coreUrl 是独立部署的可靠配置。不可把浏览器任意外服发现作为旧会话的补全来源。

旧 `accounts.sqlite` 做追加迁移，保留原 ID、service token、Bot owner 和创建请求；`node-credentials.sqlite` 与 Matrix 房间历史均不被重建。旧 Matrix 账号尚未登记到 Core 时，必须在该实际归属服成功密码认证后才导入，不按名称创建新账号或跨服影子账号。已有可信本地部署 registry 作为运维种子保留，不能将来自网络的 registry 作为这种升级输入。

迁移入口针对已有 `server-init` 元数据的部署。历史 `scripts/matrix.mjs` 原始 demo 数据若没有 `server.json`，中央初始化会拒绝；运维应先核对原 homeserver 配置、serverName、签名密钥、注册密钥、setup 及账号库，形成匹配元数据后再升级，不能把 `server-init` 的全新密钥覆盖到既有 demo homeserver 上。

恢复应同时备份/还原 Matrix 数据库、签名密钥、Core 账号库、identity-config、server 元数据和节点凭据。运维通过 homeserver 的现有恢复机制重设同一账号密码后再登录，可恢复原主体和 Bot 所有权；真实 reset_password 及客户端/服务会话轮换已另验。本切片未实现邮件找回、自助跨 homeserver 搬迁、外部 issuer 绑定或多个 Core 同库运行。

## 成熟认证方案核查

本轮读取了官方 [Matrix 认证和设备会话规范](https://spec.matrix.org/v1.16/client-server-api/#client-authentication)。沿用现有认证能保持 Matrix ID、设备撤销和服务会话兼容，避免首个统一入口同时迁移全部账号。

[Synapse 原生 OIDC](https://element-hq.github.io/synapse/latest/openid.html) 使用成熟 authlib 接入外部提供者，支持 authorization code 和可配置 back-channel logout。[Matrix Authentication Service](https://element-hq.github.io/matrix-authentication-service/setup/homeserver.html) 则要求 homeserver 委托认证，并需路由登录/退出/刷新兼容端点。两者是后续独立认证组件的真实候选，本切片没有安装或运行。

如果后续采用 OIDC，需选成熟服务并验证 `(issuer, subject)` 到既有主体的唯一绑定；显式配置 client、HTTPS 回调、PKCE/state/CSRF、各 token audience/用途、退出/撤销和密钥轮换。不要把这里的 authorityId/subjectId 直接伪装为已验证 OIDC claims。MAS 迁移还需覆盖现有密码、Core 服务设备、Bot 设备与运维路径；这次 native Matrix 通过不代替那次迁移验收。上述判断是官方资料核查与实施取舍。
