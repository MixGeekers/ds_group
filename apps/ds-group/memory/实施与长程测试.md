## 历史显式记忆实验：发现及修复

- 原生 present 成功或附说明文字的附件 JSON 没有进入桥接附件列表。现在收集与当前调用匹配的成功回执，按实际工作目录解析路径，核对文件字节和摘要，合并并去重交付声明；显式错误声明仍报错。
- 原生委派的确认语在队友回信前结束请求。现在等待相关 exchange 的回信；直接给用户的原生工作保留自身交付目的地。真实补测已收到计算结果及保留原始人类来源的转述。
- 普通 JSON 对象、数组、数字等被旧交付解析器误拒绝。现在仅显式交付字段启用交付协议，普通结构化答案按正文保留。
- 第 150、174 号工具观察初写时曾默认取请求人为作者，随后才被自动整理纠正。现在观察作者在写入时由实际工具证据确定，保留请求与工具两条来源。真实补测直接检查 remember 当时的回执和后续语义召回。
- 两次新的撤回查询复用了近期正确答案，却没有执行用户明确要求的 recall。新增稳定规则要求明确刷新查询必须在本轮执行。补测撤回一条已保存的观察后，以三个不同事件连续提出同样的刷新请求，三次均实际调用 recall 并返回 withdrawn。

补测使用新的隔离宿主、同一指定生成模型、真实 Ombre/Harrier；18 项全部通过，53 次生成/记忆模型请求全部完成，0 次失败、0 次未完成，3 次索引嵌入和 6 次查询嵌入。交付请求的幂等重试没有新增模型调用。源码摘要见[真实补测](../artifacts/memory/native-delivery.json)。这是修复后的针对性复验，未声称把全部 240 轮在修复版上重跑。

## 历史显式记忆实验：调用、版本与边界

冻结长程记录 1,510 次模型请求：482 次生成、1,022 次记忆整理、6 次压缩；其中 815 次失败回执、0 次未完成，模型 ID 只有 opencode-go/deepseek-v4.1-flash。限流重试显著拉长墙钟时间。协议回执记录 49 次索引嵌入及 315 次查询嵌入；该 llama-server 构建未输出 HTTP 访问日志，独立服务端请求数记为未知，不把零条日志匹配当成零次请求。用量按 provider 回执保留，完整费用仍未知。

一轮早期预运行完成 60 轮后主动停止：两次生成超过 180 秒捕获窗口而记为 unknown；一次后续生成重新处理 46,443 个未命中缓存的输入 token，耗时 181.1 秒。原因是动态记忆指针进入系统提示，写入后令长前缀失效。修复后系统规则固定、动态来源移入逐步快照；兼容实测观测到 1,038 个新输入 token 和 17,024 个缓存输入 token。这不是对所有 provider 缓存行为的保证。该预运行、来源过滤/修订修复前失败、provider 429 和所有后续尝试均保留，unknown 不因后续成功被改写。

当前证据为真实本地 DSH、DS-Bot、Ombre、Harrier 配合合成 Matrix 信封。它不替代真实 Matrix 网络、物理跨机或浏览器视觉验收；未替换用户正在运行的 DSH。已有旧 DS-Bot 的升级方式见[复用与运行](复用与运行.md)。模块、构建、发行包和源码边界汇总见[最终验证](../artifacts/memory/validation.json)，各层结果见[证据目录](../artifacts/memory/目录.md)。
