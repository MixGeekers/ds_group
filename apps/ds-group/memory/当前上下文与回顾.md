## 唯一事实入口与并发

继续使用 `knowledge.sqlite` 的联系人、来源修订与记忆；新增 `observations` 只保存每 Bot 的来源引用和连续本地序号，不复制消息正文，不建立第二份可编辑人物档案。旧库只从本 Bot 的记忆引用和当前上下文恢复可归属的证据，不把整个旧来源表分配给全部 Bot。

`MemoryService.observe(botId, input | inputs, options)` 同步、事务接纳最多 256 条已观察输入；不改变 current/session，不调用模型或向量服务。输入沿用 `{event:{eventId,roomId,senderId,senderKind,body,timestamp},context:{source,room,members}}`。原始 Matrix 使用 `observedMemoryInput(event, participants, room)` 转换；编辑读取 `m.new_content`。

`options={streamId?,cursor?,afterCursor?}`。streamId 存在时须有 cursor；数值 cursor 单调，可选 afterCursor 提供 CAS。相同 cursor 和事件字节重试返回 duplicate；显示名更新不改变事件身份。正文冲突或较晚输入失败时，整批及游标不提交。收到来源不代表模型理解、已整理或已完成工作。

返回 `{sourceRefs,watermarks,duplicate,stream?}`。本地水位只属于本 Bot 的来源观察，不等于 Matrix 完整同步位置：

| 字段 | 含义 |
|---|---|
| receivedThrough | 已持久接纳的观察序号 |
| reviewedThrough | 从首条开始连续得到完整 review 确认的序号 |
| settledThrough | 连续已 review、已因修订/撤回失效，或仅为撤回通知的序号 |
| reviewedCount / invalidatedCount | 实际 review 确认数 / 已失效观察数，分别计数 |
| pendingReviewCount | 当前版本仍待自动整理的来源数 |
| contextThrough | 显式确认已组装有预算视图的位置；不表示全历史入模、语义理解或外部效果 |

来源接纳、同一 Bot 的记忆写入与 review 分别沿既有串行/事务路径。review 先整批预校验与暂存正文，再重新检查来源及目标修订，在一个 SQLite 事务发布整批变更；IO 期间发生修订、撤回或冲突则不发布当前事实。索引仍是可补建派生数据。原有一次反馈修正、8→4→2→1 缩批、单来源 8192→16384→32768 输出增长和 provider 选项保留。

## 只读视图

`attentionView(botId,{sessionId?,context?,roomId?,threadRootId?,eventIds?,query?,subjectIds?,projectIds?,self?,watermark?,workView?,pendingQuestions?,historyGaps?,budgetChars?})` 为同步纯读。`contextSnapshot(botId,sessionId)` 复用同一视图。传 eventIds 时临时关注相应来源作者，不移动原生 Session 的说话人或房间。

v2 返回 `self/speaker/people/currentClaims/preferences/projectFacts/changes/recentSources/pendingQuestions/historyGaps/watermarks/version/knowledgeBoundary/budget`。保留兼容 `speakerFacts/memoryPointers/sourceRefs/contextSources/toolSources`。相关性按稳定人物、明确项目、当前群、查询词及关键版本变更排序；不再只取最近 8 条。这里的词匹配用于候选排序，不用规则替代模型抽象事实。

每个 claim 带 `id/revision/text/subjectId/predicate/scope/kind/claimState/saidBy/sourceRefs/sources/basisRefs/conflicts/derivation`。`kind` 区分直接陈述、转述、工具观察、推断与 legacy；可选 `claimState=statement|proposal|confirmed|uncertain`、`facets`、`entityIds`、`projectIds` 支持人物/项目组织。程序检查来源及版本；内容是否真正构成确认仍需模型和业务验收，不能由字段名称代替证明。同一人物/项目、属性和范围的主张一起排序，避免旧稿因查询词更多而压过修正；已失效依赖先排除，当前陈述和工具观察同层按证据时间展示，推断、转述、提议及不确定项保留其类别。人类来源不全局压过实际工具结果，冲突不由排序自动裁决。

`sources` 为原作者、群、事件、时间和摘要指纹；时间未知为 null。近期尚未整理的人类原文保留在 recentSources，避免人类更正必须等待后台模型后才能成为判断材料。旧稿、过期、已撤回或依赖失效条目移入 changes；同范围同属性的并列主张显示冲突，系统不擅自选择两个不同人类的说法。Bot 文件/转述不自动升级为人类确认。

默认预算 12000 个 JSON 字符，最小 4096、最大 32000。文本摘录有 truncated，budget 为 `{maxChars,usedChars,omitted:{section:count}}`。缺口与已省略数明确保留；不把全部历史塞入提示。workView 只标为 caller-runtime 提供，超预算时明确省略；记忆不会据摘要宣布任务完成或附件交付。

每 Bot 只看到自己的来源观察、其记忆引用及既有显式 team 记录。群范围表示适用范围，不证明全员知晓、同意或有相同心理状态。人物不按显示名合并。

## 人物、项目与原文

原生 API 包装：

- `rt.memoryObserve(botId,inputs,options)`、`rt.memoryAttentionView(botId,options)`。
- `rt.memoryProfiles({botId,kind:'person'|'project',query?,roomId?,limit?})` 返回 `{kind,items:[{id,name,kind,entityKind,aliases?,currentCount,historyCount,scopes}],more}`；items.kind 与查询 kind 相同，entityKind 保留 human/bot/group/project 等原类别。
- `rt.memoryProfile({botId,kind,id,roomId?,budgetChars?})` 返回 `{kind,id,identity,view}`；未知 id 报 `MEMORY_PROFILE_NOT_KNOWN`。

面板 endpoints 为 `memory-profiles`、`memory-profile`。上游 Core 负责 owner 授权与节点 lease；这些方法不新增授权，也不因刷新而运行模型。person 使用完整规范账号；project 来自已观察群、明确 projectIds 或 project: 主体，不能凭显示名猜合并。roomId 可缩小范围。

`memory.readSource(botId,{id,revision?})` / 原生 `memory_source` 工具读取同库原文。默认选本 Bot 实际见过的最新修订；只知道旧版本时不泄露别的 Bot 新见版本的正文。历史版本明确标为 revised/withdrawn。

Matrix 撤回保留独立通知、删除者与目标入口，已知来源生成 withdrawn 修订。未知目标保留 `unavailable-redaction-target` 缺口并推进接纳；随后迟到原文立即应用已知撤回，不复活旧事实。原生请求的可见历史若已覆盖成 withdrawn 占位，它只作为传输元数据处理，不能冒充原作者的新正文；先见到占位时保留 contentUnavailable 缺口，迟到正文仍是历史撤回内容。

编辑关系仅在目标已知且作者一致时推进原来源修订。未知目标或作者不一致的编辑保留自身事件身份和 `unverified-edit-relation` 缺口，不占用原事件身份、不中断较晚原文接纳。原文后到且确认同作者后，可在历史回读/已核对的编辑重放中应用该编辑；未核对的关系不会被假定成立。

## 有界按需回顾与派生依赖

`reviewPacket` 按人物、项目或问题选最多 24 条来源与 24 条记忆，调用者可收窄，硬上限均为 40，默认输入预算 24000 字符。当前来源与不可引用为当前证据的 historicalEvidence 分开。`retrospect(botId,options,generate)` / 原生 `review_memory` 用现有提案校验与版本化发布纠错，不写独立 profile 摘要库。返回更改摘录与至多 10000 字符的 profile，不把全部原文重新灌入工具结果；总结果至多 24000 字符，省略更改计数单列，完整原文仍由 sourceRefs 读取。它是显式按需工具，不是每条闲聊后的模型整理。

`basisRefs:[{id,revision}]` 可记录认识、草稿或计划所依据的现有记忆。来源修订/撤回、依据记忆替换/撤回会递归让派生记录失效，并在 changes 中要求复核。`store.basisStatus({sourceRefs,basisRefs})` / `rt.memoryValidateBasis(botId,refs)` 可供工作层核对已记录依赖。未登记依据的旧文件不能被程序自动认定已经修好；真实任务和文件层仍须接线并独立核验。

持续观察默认合并：不足 8 条待整理来源时延后最多 60 秒触发后台检查，达到批量后合并调度；显式请求与原生 idle 沿原 review 入口。`config.memoryReviewForBot(stringBotId)` 可限定哪些 Bot 自动整理，默认沿 memoryReview 原行为。此回调只选择后台整理，不是新的执行权限；显式工具/面板不因此禁用。
