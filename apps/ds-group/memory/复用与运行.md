# 复用与运行

本切片以 DS-Bot 0.2.7 / `71d344bf193f3f18185f25de3d8e5c483046910a` 为基础，新增可替换记忆后端、来源透传、原生 checkpoint 入口与压缩提示中的身份/范围规则。其余原生任务与工具继续由 DS-Bot 执行。上游 Apache-2.0 LICENSE/NOTICE 保留；本轮更改不能再描述为完整未改动的上游副本。

`store.mjs` 适配识雨 `relationship-domain.ts`、`cognition-domain.ts` 与 ingress 的稳定账号绑定、来源修订、乐观版本核对、并列冲突及来源失效语义。移除旧单 `local-owner` 假设，来源作者、被描述对象、Bot 作者与群范围分开。显示名不触发身份合并。全局账号目录继续由 DSCord 现有核心维护，本地联系人保存 Bot 见过的账号与别名；同一完整 Matrix ID 在不同节点生成相同身份标识。

`service/ombre/` 的 Python 代码、SOURCE.json、MIT LICENSE 和依赖锁从本仓库 `plugins/shiyu/service/ombre/` 直接复用，保留 `shiyu_*` 协议名和原生存储格式。上游为 Ombre Brain 3.6.14 / `115d831d979bf67efc7150f976e2cb34c333c935`，启动时核对固定源码树。Harrier profile 保留 query/document 分离、正文先截 2000 Unicode 字符、1024 维、last pooling、L2 及缓存指纹。本地 GGUF SHA-256：`b017b8fceae7c77864652c63d07af51480088b078771a89cafe1a467b069ea75`。没有另写向量距离引擎。

## 配置

已安装的 Python 环境应包含 `service/ombre/requirements.lock.txt` 的依赖；Ombre 源码目录使用 SOURCE.json 中的固定提交。可复用原识雨的环境，不读取其记忆库。新库在当前 DSH_HOME 下的 `bot/knowledge/`。

```sh
node scripts/memory-setup.mjs --home /path/to/dsh-home \
  --python /path/to/python --ombre /path/to/Ombre-Brain-115d831d979bf67efc7150f976e2cb34c333c935 \
  --llama-server /path/to/llama-server --gguf /path/to/harrier-0.6b-q8_0.gguf
```

也可用 `--endpoint http://127.0.0.1:PORT/v1/embeddings` 复用已运行的 Harrier。跨平台需要对应平台的 llama-server；不把本机二进制复制成 Linux 发行依赖。测试环境可用 `DSCORD_MEMORY_PYTHON`、`DSCORD_MEMORY_OMBRE`、`DSCORD_MEMORY_LLAMA_SERVER`、`DSCORD_MEMORY_GGUF` 或 `DSCORD_MEMORY_ENDPOINT` 指定同样配置。

DSCord 自带的原生运行时默认接入此后端；断开 DSCord 连接不卸载记忆或更换 Bot/Session。若宿主原已安装另一份未升级的上游 DS-Bot，连接器仍使用该实例，`state.memoryBackend` 会显示 `native-markdown`。升级时保留其包和 `DSH_HOME/bot` 数据，在同一 DSH 配置中停用旧 DS-Bot 服务条目，再重载并让 DSCord 启动包内增强版；它沿用原团队、Bot ID 和 Session，自动导入旧 Markdown。增强版的状态标记为 `source-aware-v1`。不要让两个运行时同时占用同一个团队。开发者也可在自己的 `createRuntime` 中配置 `memoryBackend: installNativeMemory` 接入同一后端。

未配置 Ombre 时使用 SQLite 精确/文本检索并明确返回 `mode: exact`；配置后检索会派生索引、语义排序并核对原文。向量临时失败时返回 `lexical-fallback` 和错误说明，不能当作语义检索成功。索引可以补建，事实来源和修订不随索引重建改写。Ombre 当前继承 2048 行索引上限；大于 128 条候选按分区全部排名，并利用固定查询缓存合并，不丢弃早期记忆。

自管 Ombre 进程退出后，下一次操作重开原库；自管 Harrier 进程退出后，下一次语义操作先拉起替代进程，再让 Ombre 绑定新端口。替代模型暂时无法启动时，仍运行的 Ombre 正文服务可提供明确标注的文本回退。外部 `--endpoint` 由其部署者维护，本包不终止外部进程。中途丢失的嵌入调用回执标记用量不完整。

原生 Markdown 的个人、团队、原生群记忆首次启动时导入，保留旧元信息和文件，标为 legacy 来源；之后 remember/recall/forget 与自动整理写同一结构库和 Ombre 正文。不会把历史文件中欠缺的作者/群来源猜填为已核验事实。新来源记录保留原始事件、时间、账号、转述关系和工具观测。

修订和撤回是逻辑历史保留：当前召回排除旧版本、撤回、来源被更改及已过期记录；显式 history 可查看状态。群知识的范围是相关性与解释范围，不是额外的执行沙箱或工具白名单。

系统提示只保留稳定的记忆规则。当前说话人、房间、工具来源和记忆指针放入每一步的上下文快照，避免一次 remember/forget 使整个长前缀失去缓存。来源上下文跟随现有原生 Session；同一 Bot 的原生群会话互不覆盖，切换原生 part 时携带来源。Matrix 房间切换仍复用原有 Bot Session。

工具观察可以同时引用人的请求和工具结果；其观察作者在写入时由实际工具证据确定，来源列表不因作者推断而丢失。用户明确要求刷新记忆或历史状态时，原生提示要求每个新请求实际调用 recall；传输层对同一请求的幂等重试仍复用既有结果。
