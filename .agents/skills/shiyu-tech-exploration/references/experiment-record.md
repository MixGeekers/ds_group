# 实验计划与结果结构

目录、产物及工作台例外以识雨工作区 `测试/README.md` 为准。本文件只补充记录应包含的内容，不创建新的测试根目录。

## 实验计划.md

在执行前写清：

- **关联与范围**：对应候选或设计文档、要回答的一个问题、用户已经要求的实验范围。尚未要求执行时写“计划，未运行”。
- **假设与基线**：预期差异、对照方式、测试输入及预期结果；失败如何推翻假设。
- **判定条件**：能改变候选判断的可观察结果；阈值有来源，不能测试结束后迁就结果。
- **环境**：OS / 宿主、运行时、版本或提交、依赖、设备与数据来源。只写必要信息，不记录凭据。
- **动作与产物**：命令顺序、工作目录、文件和可配置缓存位置、需要的网络或设备访问、资源或费用范围。
- **结束方式**：停止条件、进程退出、临时文件清理、涉及状态变更时的恢复办法。没有相应实施范围时不得改变真实系统设置。

验证多个候选时保持输入、指标和预算可比；做不到则写明偏差，不强行排名。只阅读资料能解决的问题不必创建实验。

## 结果.md

执行后记录：

- 状态：未运行 / 失败 / 部分通过 / 通过，以及实际日期。
- 实际环境、命令、输入、退出码和关键输出；证据用相对链接指向 `artifacts/`。
- 按预先标准逐项判断，分开实际观测与解释；失败日志和反例同样保留。
- 结果适用的版本、宿主与数据范围；未覆盖的部分以及可能改变结论的条件。
- 已停止的进程、已清理与保留的内容、未完成的恢复事项。未核实的外部状态不可写成已恢复。
- 对候选判断的影响：继续比较、建议采用、暂缓或证据不足。是否采用及是否实施仍按用户决定处理。

不得只写“运行成功”而不给命令与证据，也不得把实验通过改写为识雨已集成该能力。
