本节及下方首切片验证记录保留该提交时点的范围与未完成项；后续进展见末尾“真实模型增量证据与阶段 2 进度”。原机器可读宿主/embedding 证据不回写。

- **受限 Session 适配：**replyer 默认 `opencode-go / deepseek-v4.1-flash / low`，使用专用原生 preset、受限请求与执行 guard；业务/scope 稳定绑定、原生创建/恢复、取消、卸载清理以及零模型探针。历史和压缩归 DSH，不自建会话日志。探针的创建、flush、释放和归档在真实宿主执行两次；尚未验证真实回复、业务会话恢复或压缩。
- **事件基础：**统一服务及具名 SQLite 命令，类型/schema/主体/scope 校验，幂等发布、订阅修订与暂停、有限回放/gap、一次性订阅、投递租约、旧回执隔离、有限重试、查询与统计。事件与匹配投递在同一数据库事务写入。
- **消费边界：**当前接入注册组件消费与 Agent background 持久引用；后者不是自动向原生 Session 追加消息。尚无 Agent 事件工具、自动续接、时间来源或外部渠道订阅。
- **运行状态：**独立数据库 WorkerThread；本地运行状态锁、序列化持久写、暂停/恢复竞态处理、同步失败时保留未知耐久状态并关闭后续写入、重启保留暂停与 Session 绑定；只读快照及 `shiyu_status` 工具。状态服务只有本地 owner 开发范围，没有完整多用户 Mandate 系统或原生 inbox/请求结果对账。
- **embedding：**Harrier 0.6B Q8_0 固定 artifact、1024 维与 query 模板、向量归一化、loopback HTTP 边界及有界烟雾验证；没有连接长期记忆或索引，没有自动启动服务。

仪表盘中的状态来自本体服务与组件记录：会话检查成功、生成草稿、实际送达是不同事实。当前 `reply.generate` 只返回草稿且 `sent=false`，没有渠道发送能力。暂停关闭新模型操作并发出取消，不假称所有在途效果已撤销。

### 真实宿主过程与证据边界

初次启用时仪表盘为 ready/idle，事件 1、pending 0、failed 0；第一次零推理探针后事件 2。暂停后事件 3；禁用再启用生成新的 instanceId，仍保持 paused，历史累计事件 4，只有一条 `runtime.activity` 订阅。上一次探针显示为历史，当前原生 Session 可用性重新标为 unknown。

暂停时再次尝试探针被 `Runtime is paused` 拒绝，事件仍为 4；恢复后事件 5，第二次探针完整回执成功并归档，最终事件 6、pending 0、failed 0。两次探针合计生成模型推理调用为 0。归档日志由 DSH 保留，所有者可显式取消归档；它不是删除或操作系统隔离保证。

上述只有 **1 次禁用/启用循环、2 次探针**，不声称满足 V24 的 20 次生命周期矩阵，也不证明业务 Session 恢复、模型请求、原生压缩或缓存命中。本地 shell 检查的 SQLite 为 3.53.3，真实 DSH 工作线程读值为 3.53.4；二者分别记录，不混用版本证据。

### 本地 embedding 实测范围

本轮使用用户既有评测产物，固定 upstream revision、GGUF SHA256 与本地 llama-server 二进制身份；Node `v24.19.0`、macOS arm64。测试输入仅有 3 条合成文档、2 条查询和 1 条重复文档，设 120 秒取消期限并执行退出清理；未接取消信号的文件哈希步骤不作严格端到端硬超时承诺。3 个请求共 6 向量，记录的请求耗时为 231 ms。这个数是该小样本实测，不是吞吐或生产延迟指标。

实际 paidModelCalls=0、externalNetworkCalls=0；调用的是本机 loopback embedding 服务。拥有的服务进程正常退出（code 0），未安装常驻服务。完整模型、文件与向量摘要由[机器可读证据](<artifacts/embedding-validation.json>)保存；通用 HTTP 客户端不能据响应证明任意 loopback 服务实际加载了该 GGUF。本轮没有重跑用户原有 102 查询基准，也没有证明 10,000 条记忆检索、删除传播或 V25 全量语义指标。

| 项目 | 本次结果与边界 |
|---|---|
| 真实生成主请求 | 2 个顺序主请求，同一原生 Session；每轮配置输出上限 1024 tokens、最多一个 Agent 模型步骤；不包含可能的原生旁路请求 |

| 第 2 轮宿主用量 | input 185、output 14、total 199 tokens |

| 缓存 | cacheReadTokens / cacheWriteTokens 均未提供；不能据此计算命中率 |
| 重试与旁路 | 识雨适配器自动重试 0；后续精确 Session 审计发现 **2 个自动标题请求，均无用量报告**；provider 底层传输重试未独立观察，逻辑 calls=2 不等于整个 Session 调用数或底层 HTTP 请求数 |

| 原生 UI 观察 | 确认两轮/同 Session/未发送回执；当时事件 8、pending 0、failed 0；Session 详情显示第 2 轮用量 |

缓存口径另有**静态核查**：当前 DSH 适配在 `cacheReadTokens > 0` 时才输出该字段，因此缺失可能表示值为 0，也可能是 provider 没有报告。运行证据只能写“未提供”；不能断言未命中、补零或者用总输入量当完整分母。cacheWrite 同样保持未报告。本次未测实际缓存收益、压缩调用或其用量。

后续只读审计本次精确合成 Session，确认两个主回复位于 seq 14/23，同时在 seq 13/22 有两个 `session/title-llm-request`。自动标题未报告 usage，故 **401 tokens 仅是两个主回复之和，整个 Session 的调用费用未知**；该补充事实保存在模型证据的 `supplementalAudit`，没有改写此前主回复数据。阶段 2 随后为识雨自有 Session 增加固定标题限制，不能据新修复回溯认定本次没有旁路。

入口每次显式运行最多两轮主请求，没有适配器自动重试；每轮使用已有 120 秒取消定时器，Client 等待上限 250 秒。它们不构成严格底层传输终止保证、整个 Session 旁路调用预算或跨多次验证的累计费用账本。失败或回执缺失保留未确认，不自动追加主请求。`lastModelVerification` 写入本地运行状态，旧实例结果仅作为历史；Session 行显示最近一轮用量，全局汇总仍保持未知。

这项结果只补充 V24/V25 的限定前置子场景：真实路由可生成、两轮原生 Session 复用及实际用量显示。未覆盖完整语义数据集、注入变体、重复轮次、业务会话恢复、长上下文、压缩或缓存验收，**不宣布完整 V25 或 V24 通过**。

### Goal 生命周期的权威与证据

Goal phase、objective 和轮次只属于 DSH 原生日志；本地绑定只存 Session/Goal 引用、native revision、criteria hash、metadata CAS 和命令事实。适配器先持久 pending，再执行原生写；create/resume 在同一同步片段内立即 disarm，原生成功后 flush 并 exact live get 回读，再确认本地回执。跨存储两次写入不声称原子，释放失败或无法确认均保留 unknown，旧 commandId 不盲重放。SDK 的 read/recover 会短暂恢复并释放受限 Agent，因此不作为仪表盘刷新操作。

`goal.verify-lifecycle` 只接受本地任务 ID。服务根据已保存的 Task/Assignment、完成条件、Effect、可信 Receipt 及重新读取的文件产生独立证明；在原生 complete 的两个授权检查中复查证据身份，绑定精确 native revision。模型摘要、请求 JSON 或 UI 选择不能提供 owner capability，也不能代替实际文件和回执。已知产物效果与模型费用的完整性仍是不同事实，未知费用不被伪造为已结算。

诊断固定同一 Task 对应一个 GoalBinding，完整序列为 create→pause→resume→complete；停止、取消、已有绑定或未知回执要求显式恢复核对，不能新建替代目标伪装成功。暂停/卸载在异步边界拒绝后续操作；若原生动作已经发生，取消不回滚原生日志，也不向 UI 释放未经完整确认的成功。

运行快照只显示 `lastGoalVerification` 的历史/本实例状态，读取不创建或恢复 Goal Session。显式诊断使用 `runtime.goal.verified` 记录检查结果；UI 必须同时确认任务、目标、Session、complete、inferenceRequested=false 和四步操作链，缺字段保留未确认。完整 UI 和真实宿主结果分别见本节末尾，不以 UI 替身代替原生日志。

### 实际路径和事务边界

`ConversationDomain` 与 Task、Event 共用 SQLite 连接和 `SqliteTransactions`。可信运行层固定 `local-owner` 身份/受众，命令只接受已有 Task ID 和可选本地对话标识，最多 64 个稳定本地 Conversation/Topic/回复绑定；重复关联复用身份，不创建原生 Session。仪表盘可选本地 Task 并读取关联、来源版本、待同步标记和后台扫描状态；受理回执不等于背景已加载。

每个 Task 只建立一个受限 `task.succeeded` 订阅，可向多个关联对话投影。消费者先领取持久投递，再在同一事务重新核查 claim、可信 `task-service` 来源、固定 scope、事件 schema 与真实 succeeded Task，写背景来源标记并 ack 原 Event。claim 尝试独立持久，投影或 ack 失败同时回滚，随后按既有投递规则重试；无法判断事务结果则停止使用该 store。来源版本 1 仅指一次不可变的成功事实，不拿事件序号或 Task 总版本替代。

`BackgroundPump` 在启动、任务结算及关联后唤醒，每 5 秒补扫；每批 20 条、每次最多 4 批，合并并发唤醒，失败尊重持久投递退避，卸载等待在途扫描。暂停仍接受纯背景标记，扫描不具备模型、Session 或发送能力。GET 不消费投递，Event ack 只确认背景标记已提交；本轮不调用 `ackContext`，不宣称原生上下文已同步。晚建绑定保持来源首次加载需要，即使旧成功事件投递已 ack，也不能标为已加载。

### 本地撤回与记账口径

撤回来源保存同意会撤销本地引用和读取资格，暂停或后端不可用时仍可执行；它不调用后端物理删除，原生 Markdown、索引和备份清除未实现。后端历史 applied 事实与本地当前不可读可以同时成立，界面不得把 withdrawn 写成 erased。保存/发布复查会话代次；精确读取复查当前保存同意、来源与受众、安装世代，并在后端 I/O 前后比对授权/删除等读取向量。日常对话代次或保存 grant 到期不自动撤销读取同意，旧 receipt 本身也不构成永久读取权。

### 本轮方案与实测边界（执行前冻结）

本切片将固定 Harrier 接入受控 Ombre 的独立索引操作，再把同一 Conversation 当前可读的记忆经 ReadView 送入 DSH 原生 Session。正文保存保持零推理；建索引单独使用 `memory.index` 授权、Effect 和最多两次 embedding 配额。查询候选必须来自控制域，索引基线及进度不能代替读取权限；返回前重核完整候选集。空可读集合不请求 embedding，缺索引明确返回未就绪，不回退关键词搜索。控制库、索引 journal 与仪表盘状态均不保存正文副本或查询正文。

读取视图携带独立的记忆删除屏障。原生加载前先耐久登记可能暴露的来源；撤回在同一控制事务中使受影响的旧 Session 绑定失效。正常消息继续复用原 Session，只有失去读取资格的已暴露来源触发安全代次切换，旧 Session 历史保留且不再续接。单纯从搜索结果移除记忆不构成该验证。

离线验证覆盖协议边界、独立索引回执、重复请求不重放、取消与未知结果、跨会话拒绝、读取中撤回、完整候选集复核、暴露后撤回和 Session 切换。启动器核对固定模型、主程序、实际加载的动态库及 profile；健康检查与工具握手不标记 embedding 已实测。
