本实验关联 [Ombre 候选](../../技术候选/Ombre-Brain.md)、[已有静态核查](../../research/2026-11-02-Ombre接入/核查结论.md) 和识雨 MemoryOperation 接入。用户已授权识雨完整实施与语义后端选型搭建；本轮明确授权隔离的真实 Ombre 服务验证，不重复索取许可。

## 固定条件与判定

- 上游固定 `115d831d979bf67efc7150f976e2cb34c333c935` / 3.6.14，MIT；隔离环境按官方 `requirements.lock.txt` 使用 `--require-hashes` 安装，不改上游源码。
- 使用既有 Python 3.12.16、固定 llama-server 与用户已评测 Harrier Q8_0，先校验已有模型及二进制 SHA-256。所有新依赖、配置、日志、vault、缓存和临时文件留在本目录。
- 子进程采用白名单环境；生成模型 API key 为空，生成地址为本实验回环拒绝端点；不继承外部凭据。embedding 仅转发本机 Harrier `/v1/embeddings`，记录请求计数及文本 hash，不记录凭据。
- You/Them 保持新库默认关闭；GitHub 同步间隔 0、无仓库/令牌，Tunnel 无配置，Hook skip。`embedding.background_indexing=false`；上游 decay 无总开关，本实验接受并记录其日志/派生副作用，不能声称完全无后台。
- 只建立一个全新 `test_data=true` 合成桶，完整提供 title/tags/domain/valence/arousal/importance；不传 source/media/quotes，不以 `hold` 降级保存冒充完整绕过生成路径。
- 通过条件：MCP list-tools 可用；grow 创建后通过公开工具独立取得唯一 ID 并精确匹配固定正文；正常停止/重启后公共回读仍匹配；trace archive 后确认归档，restore 后确认恢复；认证 export 如成功需检查原生 manifest/hash；harddelete 后公开 ID 查询确认不存在。生成端点请求计数必须为 0。
- 若任一阶段不支持或失败，如实记部分通过/失败；MCP 返回 isError=false、标题、batch ID 或原始数据库内容均不能单独证明写入成功。写后不明不重试创建，不增加第二测试桶。
- Harrier 本轮只验证上游连接和检索路径。Ombre 未区分 query/document 前缀、截断 2000 字符，不能声称复现既有 102-query 质量评测。

## 动作、边界与停止

先下载固定源码并核验 commit/version/锁文件；在 `.venv/` 安装依赖；脚本持有全部子进程 PID，回环监听由操作系统分配空闲端口。HTTP/MCP 客户端设有限 deadline，不自动重试变更。实验运行上限 300 秒（安装不含在内），最多一次正常服务重启。测试 Dashboard 凭据只在进程内随机生成，不写文档/证据或打印。

依次执行：启动 Harrier/回环计数代理/Ombre → list-tools → 单桶 grow → 检索取得 ID/精确读 → 正常停止并重启 Ombre → 精确读 → 原生认证 export（可用则验证）→ archive → restore → harddelete → 公共缺失核对。整个流程不改 DSH 配置、控制库、Session 或原模型资产。

`finally` 停止全部自有服务并确认退出。收尾先列出再删除可重建 `vendor/`、`.venv/`、`cache/`、`tmp/`、下载归档；保留最小脚本、合成样例、脱敏结果、锁文件 hash/依赖清单及必要公开 API 证据。运行 vault 与导出包仅含合成数据，按结果需要保留小证据或清理，明确记录清理范围。

## 补充：产品私有 stdio 连接探针（运行前冻结）

HTTP 主实验全部自有进程退出之后，再用另一全新空 vault 验证产品 `PrivateStdioMcpClient → OmbrePublicApiAdapter → 固定 Ombre stdio`。复用上述只读源码与隔离 Python 环境，不连接原 HTTP vault，不运行 DSH、不注册 Agent 工具、不建立或修改任何记忆桶。

本探针关闭 embedding，生成 key 为空，You/Them、同步、Tunnel、Hook 与主实验同样关闭。构造客户端应零 I/O；显式 connect（初始化及工具发现）后只调用一次 `readI`，必须得到固定版本的空库答复；随后 close 并独立检查自有 PID 已退出。原生启动/读取仍允许自身日志、SQLite 初始化与 decay 生命周期副作用，因此不是文件系统零写。连接 30 秒、单次调用 15 秒，预计总计不超过 60 秒；失败不重连、不重发。记录源码/产品构建 hash、版本、工具名、实际答复、次数、耗时、stderr 计数及关闭结果，运行状态放 `runtime-stdio/` 并忽略。

成功只证明当前本机 Node 与 Python 的实际协议接线，不替代 DSH peer 解析、正式记忆保存、Harrier 检索或权限业务验收。此补充不扩展主实验的单桶写入和一次 HTTP 重启次数。源码与依赖在两项试验均结束后统一清理。
