# DSCord 多后端存储协议实验

计划时间为 2026-11-04（America/Caracas）。主代理按用户本轮三路实施和本机资源授权安排本实验。关联 [多后端候选](<../../技术候选/DSCord多后端存储.md>)。

## 范围与假设

验证现有 DSCord / Matrix 附件路径通过固定 Synapse S3 provider 写入真实 S3 协议后端，并在本地媒体缓存被隔离后从后端读回。S3 后端为固定 rclone 的本地目录 remote，全部文件和凭据由实验生成。真实 R2、Google Drive 与 OneDrive 账号接入留待对应验收。

本轮同时实现最小产品配置，新增 local / s3 后端选择、可选 Synapse 扩展镜像和 Compose overlay。迁移、远端回收与云盘 OAuth 作为后续切片。

## 环境与写入

- 宿主为 macOS arm64，Docker Desktop Linux arm64。Synapse 固定 1.164.2 原项目镜像，S3 provider 固定 1.7.0，rclone 固定 1.75.2。
- 安装仅发生于隔离容器构建。产品配置、测试和复现脚本在 `apps/ds-group/`，本实验的计划和结果在当前目录。
- 私有运行数据统一为 `apps/ds-group/.local/storage-smoke/`，包括合成凭据、Synapse 数据、Core 数据与 rclone 对象目录。新建文件权限限制为当前用户，目录已由包的 `.gitignore` 排除。
- 容器和网络名称以 `dscord-storage-` 开头。绑定端口为 S3 22300、Core 22400、Matrix 22408，全部绑定 127.0.0.1。
- 实验只使用合成文件，模型调用和真实云服务调用均为零。候选镜像及包下载使用公开发行源。

## 判定条件

1. 默认 local 配置与已有 server-init 重试测试通过。S3 参数校验在配置写入前失败，输出不包含凭据。
2. 从正常附件上传入口得到稳定附件记录和 Matrix content URI，rclone 对象目录确有对应文件，SHA-256 与原输入一致。
3. 停止 Synapse，将本实验的 `media_store` 移到旁路保留目录，重启后可通过授权下载入口取得相同字节。
4. Range 请求返回正确片段与 Content-Range。重启 rclone 与 Synapse 后既有附件仍可读。
5. 重复 server-init 保留 S3 连接。显式更换已使用的 S3 目标提示迁移需求，并保持原配置。
6. 脚本最终停止并移除自己创建的容器与网络，记录退出码、组件版本、通过项及失败信息。

## 执行与退出

先运行相关模块测试，再执行 `node scripts/storage-smoke.mjs`。该脚本在发现同名容器、已占用端口或非空实验运行目录时拒绝覆盖。先构建扩展镜像，再启动 rclone、初始化 Synapse、注册合成账号并运行 Core，依次完成上述检查。

出现失败时先保留精简诊断与当前运行状态，针对可恢复错误修复后单独记录重跑。每轮均清理本轮创建的容器和网络，私有数据保留用于复核，之后按结果记录清理。公开证据只包含版本、哈希、HTTP 状态、检查结果和无凭据诊断。
