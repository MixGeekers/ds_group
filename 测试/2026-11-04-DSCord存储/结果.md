本轮新增 `DS_GROUP_MEDIA_BACKEND=local|s3`、服务器私有媒体配置、可选 Synapse S3 扩展镜像、S3/R2 endpoint 参数和 rclone 网关 overlay。现有附件入口增加流式单 Range 兼容、范围错误处理与上游大小核验。使用一个当前附件主存储，历史迁移、远端删除和全盘索引作业继续独立推进。

Google Drive / OneDrive 接法使用管理员已有 rclone remote，模板已静态渲染核查。真实云 OAuth、配额、授权刷新和云端故障行为尚待对应账号验收。本轮模型调用和真实云账号调用均为零。

## 按预定条件判断

| 条件 | 证据与结论 |
|---|---|
| local 基线与 S3 配置持久化 | 21 项模块覆盖默认、旧配置、重复初始化、凭据轮换、目标切换拒绝、非法持久配置与输出脱敏。协议复验确认省略 S3 参数后仍保留选择 |
| 正常附件入口与远端真实字节 | Core 上传与授权下载通过，59-byte Unicode 文件及 9 MiB multipart 文件的 SHA-256 与 rclone local remote 实际对象一致 |
| 本地缓存隔离后回读 | 停止 Synapse，重命名本实验 media_store，重启 rclone/Synapse，再经 Core 下载两份附件且哈希一致 |
| Range 与重开下载 | 真实请求返回 206、准确 Content-Range 和 1031-byte 片段，Core 重启后另一范围再次成功。模块另覆盖后缀、开放结尾、越界、错误长度与原生 206 |
| 远端写失败与恢复 | 停止 rclone 后上传返回服务端失败，附件行保持 failed。恢复后同 upload ID 返回原 attachment ID，并成功下载核验 |
| 退出与资源隔离 | 三个回环端口为 22300、22400、22408，自有容器与网络全部清理，其他开发服务保留 |

本地目录 remote 验证了实际 HTTP S3 协议、SigV4、multipart 和 Synapse provider 接线。R2 配置共享 endpoint / region 参数，R2 实际服务、Drive 和 OneDrive 分别需要真实后端验收。客户端主动中途取消的资源释放已作源码核查，本轮运行回归覆盖正常片段完成。
