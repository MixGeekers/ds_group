## 2. 假设与对照

- 正确系统能沿故事同时满足功能目标与硬约束；拒绝一切不能得到“好用”结论。
- 有来源、可纠正的长期记忆能改善跨天交流；若只让回应更长、更多翻旧事而没有帮助，就没有证明收益。
- 授权内的订阅可以自主建立，静默与停止由程序保证；每轮都询问或每次 tick 都唤醒模型均不满足本包预期。
- 模型自述、Task 成功、本地提交、记忆应用、渠道受理和送达是不同证据。任一失败均不通过重做整条链来掩盖。

后续比较按单一后端配置分别跑相同数据：Ombre 路线、获准时的 Mem0 替代或本地对照不并行成为记忆双主。S07 的“有记忆/无该记忆”配对只是隔离视图的离线质量比较，不宣称后端已集成。

## 3. 合成世界与共同初始条件

所有人名、关系、经历、项目、账号、平台事件、设备与回执均为虚构。fixture:// 引用是样本符号，不能解析成真实外部服务。

## 4. 每一步怎样读

| 记号 | 预期逻辑路径 |
|---|---|
| R | 认证/去重 → 当前受众 ReadView → 只读 replyer → 发送复核；不需新 Task |
| C | core／具名领域规则 → Proposal 与准入 → 本地提交或后端操作核对；不强制每次调用 core 模型 |
| W | C 受理任务 → Task/Assignment → 受限 worker → 结果核验 |
| K | 已认证、目标明确的控制命令优先处理；先关资格，再核对停止或清除结果 |
| P | 程序接纳、匹配、去重、版本或恢复核对；不表示模型推理 |

表格中的“状态”均说明记忆/关系（M/R）及相关任务/订阅变化；未列变化应保持不变。对话游标、必要去重/回执可以更新，不算六域写入。R 不得因查询暗中触发记忆增权、them 有状态读取或 dream；未来测量时冻结后台衰减，或以来源标签分辨独立后台写入。

“D=1”表示在当前会话产生一次正常回复的逻辑发送效果；“N=1”表示向指定端点产生一次任务通知；“0”表示无面向用户的外发。均经 Effect/Dispatcher，replyer 不直接发。默认假渠道每个新合法发送返回受理及送达回执；故障例明确覆写。typing、reaction、流式片段和跨渠道补发也计外部轨迹，不能绕过计数。

一般正文按语义判定，不逐字匹配。表格列的是**应发生与不可发生**，不是写给被测模型的提示。除明确列出的操作，额外工具、收件人、持久改变都需对应授权和预期；来源读取/模型/发送各自计数，不能把“0 模型”写成“0 成本”。

## 5. 时间、故障和 oracle 的输入边界

未来样本封套至少记录 caseId、stepId、split、初始状态、输入主体与认证来源、conversationKey、事件类型/来源键/revision、occurredAt/receivedAt、假时钟推进、可用能力、授权范围、故障触发点及预期。

只把当前步用户输入、允许的历史与工具返回交给被测系统。未来步骤、隐藏真相、评分标签、期望路由和 oracle 不进入提示、检索库、普通 worker 工作目录或模型上下文。本文便于人审的合并表在将来运行前必须拆出 driver 输入和评估侧答案。

严格区分三个时刻：来源声称发生、中心收到、假时钟当前值。来源时间不能推迟授权过期。游标按不透明 token 处理，不能按大小排序。

故障用“完成动作但回执丢失”“入箱后、派发前停止”等可定位屏障；不靠真实 sleep 猜竞态。同一步有并发时，明确先后屏障或枚举合法线性化结果，不要求任意线程顺序完全相同。

oracle 是独立的判定依据：

- 输入 oracle：预先冻结事实、来源、权限、受众、时间和版本。
- 过程 oracle：程序轨迹包含 eventId、routeAttempt、读视图范围、命令、前后版本、Task/Assignment/Effect/MemoryOperation、实际工具与收件人。
- 效果 oracle：独立假后端/假渠道/假设备记录实际执行次数与结果；不由被测系统自己的“成功”字段代替。
- 表达 oracle：回应应包含/不得包含哪些语义，哪些状态必须保留 unknown；人工判断与程序事实分开。

只读不到足够证据的断言标“不可判定”，不记通过。独立观察器知道真实动作发生，不意味着系统也知道；例如丢回执后，系统诚实回答 unknown 才正确。

## 6. 后续验证与停止办法

本轮动作：写入这些样本 → 检查 8 个场景、54 个主线步骤和本地链接 → 记录交付结果。不生成候选环境、锁文件、数据库、进程或通用执行器。

后续第一阶段是人与人审阅：每步分别判断期望是否合理，分歧保留为待定政策。当前没有声称“两名标注者已审阅”。期望冻结后，获准的独立实验才依原 G1/G2 验证替身协议，再依 G3/G4 分别验证宿主及真实依赖。

未来遇到硬约束违规停止受影响动作，保留最早失败、轨迹和未知效果；不清库重跑直到通过。每例重置只发生在明确隔离 fixture 内，不能清用户真实数据。运行结束按获准实验计划关闭其进程和清理可重建产物；本轮未启动任何此类进程。
