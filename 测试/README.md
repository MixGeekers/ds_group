# 探索测试目录

本目录是识雨存放技术探索、隔离实验与跨模块验证计划的指定位置。项目已于 2026-11-01 由用户批准进入“开始实现”阶段；产品源码与模块测试归属对应实现模块，Lab 保留在 `lab/`。目录的存在不自行扩大某项实验的范围，阶段与授权以 [工作区约定](<../AGENTS.md>) 及用户当前任务为准。

## 组织方式

每个实际需要的实验使用独立目录 `测试/YYYY-MM-DD-主题/`，日期按 America/Caracas 记录。同日同主题如有独立任务，加简短后缀，不覆盖旧实验。以下是按需创建的结构，不必预建空目录：

```text
测试/
├── README.md
├── YYYY-MM-DD-主题/
│   ├── 实验计划.md      问题、范围、通过条件、预期写入和退出方式
│   ├── src/             最小验证代码或资料处理脚本
│   ├── cases/           样例输入、合成数据、预期结果
│   ├── vendor/          固定版本的第三方实验源码（确有需要时）
│   ├── artifacts/       日志、截图、指标、临时数据库、运行结果
│   ├── 结果.md          执行事实、结论、限制与清理情况
│   └── .venv/ 等        仅该实验使用的依赖、缓存或构建目录
└── 归档/                迁入的历史材料；默认不执行
```

**保留例外：**`plugins/shiyu-workbench/tests/` 是工作台现有测试，不搬迁、不删除。新技术候选的实验不得借用该目录。

## 实验开始前

1. 关联一个已有候选或设计问题；只收集资料的辅助脚本可关联相应调研报告。先写可判定的通过/失败条件，不扩写完整产品。
2. 在 `实验计划.md` 记录用户已要求的验证范围；若尚未要求执行，标为“计划，未运行”。文档检查、skill 格式校验等本次交付自身的必要验证，可直接完成。
3. 写清将创建的文件、所用数据、依赖版本、外部服务或设备、预计资源、停止与清理办法。只有碰到任务尚未涵盖的依赖、费用、真实设备或数据使用时，才提出具体缺口。
4. 测试代码、包清单、锁文件、环境和可配置输出均留在本实验目录；不要在根目录运行会生成这些文件的命令。已有系统临时机制确实需要外部临时目录时，记录实际路径与清理方式，不把它变成持久运行目录。

## 执行与收尾

- 优先使用合成或专门提供的测试数据；测试凭据不进入文档、日志或工作区文件。真实数据、外部 API、设备设置或常驻服务的改动必须在用户任务范围内。
- 固定版本与必要配置；记录实际命令、运行日期、环境、退出码、核心结果及失败原因。未运行、运行失败和通过必须分开。
- 文件夹隔离不等于系统隔离。需要安装系统组件、改变权限、接入服务或部署时，单独明确任务范围，不能因为位于 `测试/` 就自动执行。
- 完成后关闭本实验启动的进程，移除可重建的大体积依赖与临时输出；保留最小复现材料、结果和必要证据。`结果.md` 记录保留和删除范围。
- 在候选条目中链接实验结果；实验成功仍不自动升级为“已采用”或复制到产品目录。
