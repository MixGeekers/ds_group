## 2. 差异 C-D1：什么新输入会使回复过期

旧[派工时序第5节](<../../架构与设计/A方案全景/Core派工与对话时序.md>)写“新输入增加 conversationGeneration，取消或作废未发送的旧草稿”；[公共契约](<../../架构与设计/A方案全景/跨模块契约.md>)规定代次和发送前复核。[V05](<../../架构与设计/A方案全景/验证与验收.md#v05>)要求先锁定合并/打断规则，再产生独立预期。

| 输入 | B0／旧文字按会话理解 | R1／企业拟验语义 |
|---|---|---|
| 同群无关闲聊 | 可使同会话旧草稿过期 | 只推进接纳序号，不建对应业务 DialogueTurn，不改其有效代次 |
| 同订单价格/交期纠正 | 使旧回复过期 | 使依赖该对象/来源的待发回复过期 |
| 源消息撤回 | 旧依赖不能继续发送 | 同样失效；缺可核对替代来源则暂停该回复 |
| 成员/受众/授权变化 | 发送入口复核 | 立即失效相关视图/待发效果；不能等待注意力模型完成 |
| 另一订单的新请求 | 整群统一代次可能一起取消 | 仅影响关联线程/任务；无依赖的回复可继续 |
| 判断迟到或相关性不明 | 旧文字没有完整定义 | 迟到 contextVersion 不覆盖新决定；不明时暂缓受影响回复，有界补查，不阻塞所有会话 |

R1 是待验证的企业配置，不能偷偷替换原 S04 的答案。S04.4 的“一句话就好”是相关修改，两种配置都应拦住旧长文。B0 若在 FL03 噪音流中饿死回复，是扩展需求不满足的证据，不证明它违反自己已冻结的旧规则。

拟记录 replyDependencyRefs、contextVersion、受众/授权版本和判定依据；这些只是实验侧或待验适配字段，不宣布新增公共 API。实际是否复用 conversationGeneration、按 thread 划分或引入局部版本，须正式映射后才运行。

## 3. 差异 C-D2：worker 上限不等于 core 获得容量

既有基线总模型槽 3、后台最多 2、对话预留 1、core 评估上限 1、worker 上限 2。两个长 worker 若占满后台，并不能由“core 上限 1”推出 core 还有一个可用槽。

FL04 同总预算比较：

- B0：上述原配置，记录 core 最长等待，不事先宣布失败。
- R1：同样总槽 3，持续保留 1 个对话槽和 1 个 core 槽，worker 同时推理最多 1；两个 Task 可以活动，但不能等同于两个同时模型调用。

首个 R1 不借出 core 预留槽给不可中断的长调用。以后若借用，需证明有界让出和预算回收，另列变体；不能依赖远端模型一定响应 abort。工具等待是否占模型槽须观察实际接缝。减少 worker 并发可能增加其完成时间，必须同时报告，不能只展示 core 更快。

这些是实验配置差异，未修订架构/产品并发默认值，也不额外增加第四个槽位。

## 4. L1/L2/L3 分开判定

| 层 | 本轮故事提供什么 | 可比较的结果 | 不可外推 |
|---|---|---|---|
| L1 | 四类标签、获准上下文、允许答案集合 | 规则、规则＋Jev、规则＋Decisions、规则＋普通分类器的语义错漏与费用 | 不能证明吞吐、取消或真实渠道 |
| L2 | 固定分类、队列屏障、独立假端点、负载轨迹要求 | 实际接入的待验队列/控制适配器是否满足状态和时间约束 | 假分类正确不证明模型懂业务 |
| L3 | 同样输入和 oracle，固定真实模型与待验组件组合 | 组合失误、等待、有限预算下的总成本 | 假端点成功不证明聊天平台已接通 |

## 5. 负载、时钟与截止条件

原 P0：20 会话、1,000 条、10 条/秒、假模型 100 ms、总槽 3；沿 V05 的每会话待答文本上限 20、总待处理输入 1,000。待答文本和已接纳背景事件是不同队列，不能混用同一指标证明都受控。明确接纳拒绝、待处理和上游 gap。

到达计划与回复完成独立；实际注入落后也要记录，不能用慢系统造成的降载得到通过。每条记录 scheduledArrival、injectedAt、receivedAt、attentionResolvedAt、businessMilestoneAt、effectDispatchAt。业务时钟用虚拟时间；性能持续时间用单调实际时钟，不混合相减。

| 条件 | 门槛与证据地位 |
|---|---|
| P0 接纳／认证停止 | 沿原 V05：P95≤500 ms／使新发送失效 P95≤1 s，各至少 200 个有效测量点；只适用于规定本地条件 |
| 样本纠正、撤回、撤权 | 以显式发送前屏障为截止：对应旧效果必须为 0；不是等待一个任意超时才失效 |
| FL01 关键关注／处置或有界复核安排 | L2 P0 建议 ≤2 s／≤10 s，自实际接纳起；另报自计划到达起的延迟。不强制一种通知，需有有效处理责任和复核期限。为待冻结探索门槛，不是生产 SLA |
| FL04 小会话查询／新 core 评估开始 | L2 P0 建议各≤2 s；每主体分别看最大值与 P95。R1 与 B0 逐项对照，不从总体平均推公平 |
| FL04 停止注入后的回落 | 建议 30 s 内清完可执行积压；pending/unknown 单列不能删掉充当排空。延长工作任务的变体须另定门槛 |
| L1／L3 | L1 不作队列吞吐结论；L3 真实模型的延迟/费用阈值须另冻结，不能直接套假模型 100 ms |

新门槛是可审阅的建议；用户政策与执行环境未定前不报通过。按时间记录关键事件及时捕获、迟报、漏报、业务里程碑及时达成、未完成五类，不能“最后发现了”就抹掉迟报，也不能只送到 core 就算业务完成。

这里的服务处理耗时不规定“等几秒就必须 @”。用户已明确由识雨判断，且负责人已回复可静默、无人回应可直接 @；提醒时机按当时业务与对话评价。FL01 的处置里程碑允许形成有依据的等待/后续复核，不能把自主选择等同于机械超时提醒。

## 6. 噪音与公平的两个不同对照

FL01 的主故事有 4 条业务聊天输入：

- 增量对照：保留这 4 条的内容与到达时刻，分别加 0/16/76 条噪音，合计 4/20/80 条，噪音占 0%/80%/95%。总负载变化须显示，不能只归因为筛选精度。
- 固定总量对照：另建 100 条的轨迹族，100/20/5 条业务、0/80/95 条噪音；这改变业务密度。使用不同但配平的冻结业务子例，不能复制同一事件 ID 凑数或用单个故事装成独立样本。

首批只给主线与噪音片段模板，尚未物化这些完整变体或 1,000 条轨迹。后续生成时绑定 familyId 和种子，审定每条确实与业务无关；未经审核的自由生成闲聊不能自动标为噪音。

FL04 单源 80% 偏斜与 10→25 条/秒、60 秒突发分开运行；P0 的 1,000 条只支撑 100 秒到达，不足以同时装下 60 秒×25 条/秒加前后区间。突发例须另算总量并冻结，不能仍标“1,000 条 P0”。

报告每员工/项目/供应商的等待、饥饿、拒收/重试、队列峰值与回落；core 排队、worker 完成、对话回复分别列。至少 200 条停止测量通过独立重复轨迹收集，不把一次停止的 200 个轮询点当 200 个样本。

## 7. 成本与失败计数

每千条原始入站费用 = 该运行中规则/筛选/core/worker/replyer/附件/重试等实付费用合计 ÷ 原始入站事件数 × 1,000。原始入站、去重后唯一事件、业务事件另列分母；自触发内部消息不拿来稀释费用。注入失败/拒收要报告，不能靠少处理消息压低成本。

价格/用量缺失标不可核算，不能填零；规则/本地计算另报 CPU 时间等资源，不杜撰币种成本。取消但已计费、冷/热缓存与降级都计入；另报每个成功业务事件的费用，且必须连同漏报/迟报率查看。

硬边界为零违规；功能必须完成正例；误公开回复和误唤醒独立计数。全静默会漏业务，全升级会触及预算/公平，两者都不能用总体准确率获得合格结论。先报逐例分子/分母，扩展集才按独立故事族给区间。
