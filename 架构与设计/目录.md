# 架构与设计 · 目录

这里存放 DS-Group 的整体架构、专题设计与设计决策，并保留识雨项目的历史资料。当前产品目标是多个人类与多个独立 Bot 共同对话和协作，Bot 可跨机器加入共享核心。

**当前实施方向。** 2026-11-04 用户确认项目更名为 DS-Group，并授权 Codex 开启 Goal 无人值守完成首个框架。实施根为 `apps/ds-group/`，Matrix/Synapse 与两个 DS-Bot 节点已完成首轮同机多进程闭环，前端扩展为 PWA，并接入个人 Bot 归属与群邀请。职责、来源和验收见[DS-Group 首个框架与实施路线](<DS-Group首个框架与实施路线.md>)，实际运行结果见[应用说明](<../apps/ds-group/README.md>)。

后续服务器发行切片已完成多系统 CI，首轮 16/16 任务成功。Linux amd64/arm64 容器、独立 npm DSH、数据恢复及节点导出见[部署说明](<../apps/ds-group/deploy/README.md>)和[发行验证](<../apps/ds-group/发行验证.md>)。正式发布、物理跨机器模型协作与手机实机验收分别登记。

0.2.0 文件工作与 UI 切片接通附件、工具执行、任务与成果，以及 Discord 式提及。React + TS7 的选型、组件职责、全局 token、主题和多语言约定见[前端架构与设计规范](<../apps/ds-group/前端架构与设计规范.md>)，实际范围按应用实施记录核对。

私聊交付与界面修补补齐在途交付更新、原始发起者目标、Bot 间私聊委派和稳定重试。对话区采用轻量活动点，图标统一为[Lucide](<../技术候选/Lucide.md>)，实际 9 项真实验收与历史失败见[应用实施记录](<../apps/ds-group/实施记录.md>)。

2026-11-04 后续用户确认中央账号、统一客户端与默认归属聊天服务，各协作服务器采用独立后台和分层白名单。主聊天已分派中央身份、客户端、服务端治理、跨服 Bot 工作四条实施线，并负责整合验收，见[统一平台目标与实施分工](<DSCord连接、账号与存储.md#统一平台目标与实施分工>)。当前新范围处于实施阶段，跨服整体结果按后续固定提交留证。

**并行协作范围。** 识雨旧模块的接手工作继续交给 DSH，从[交接入口](<DSH交接/00-交接入口与实施路线.md>)读取对应目标和边界。2026-11-03 用户授权的[识雨健身房升级](<识雨健身房长程互动升级方案.md>)及五人七日剧本继续按既有分工推进。上述三条工作线分别记录实施与验证结果。

## 组织约定

1. **一个 Markdown 对应一个架构或设计主题。** 总体设计保持简洁；记忆、回顾、工具接入等专题有实质内容后再独立建文档，不预先堆空文件。
2. **本文件维护目录与状态。** 新增主题、确认方案或替代旧方案时，同步更新清单。
3. **设计状态与实现状态分开。** “方案已确认”不等于“代码已完成”，更不等于“已经验证可用”。
4. **草案不冒充共识。** 助手整理的建议须明确标为草案；只有形成明确决定后，才标为已确认，并记录日期与范围。
5. **来源使用链接，避免重复抄写。** 项目评估引用技术候选条目；设计文档集中解释我们自己的组合、接口与取舍。
6. **修改保留理由。** 重要决策记录背景、备选方案、选择理由及影响；被替代的方案注明替代关系，避免新旧规则混用。
