# 识雨本体文件树规划

更新：2026-11-02（America/Caracas）。设计状态：完整目标目录规划。项目阶段：已批准开始实现；**本体 0.1.0 首切片已在 `plugins/shiyu/` 建立，完成本地检查及限定真实 DSH 接入验证，阶段 2 正在实施**。实际入口及结果见[本体 README](<../plugins/shiyu/README.md>)与[实施记录](<../plugins/shiyu/实施记录.md>)；下方完整树仍包含尚未落地的职责。

识雨本体已放在 **`plugins/shiyu/`**，作为一个独立的 DSH 插件包。首版采用单包内的模块划分，权威核心仍按 A 方案位于 DSH 宿主进程内；按实际实施切片创建文件，不把下面的完整规划一次性建成空目录。

用户随后确认：**尽量复用 DSH 原生 Session，本体界面改为运行仪表盘**，展示当前状态和正在做什么。基础界面提前到首个切片，详细边界见[运行仪表盘与 Session 复用](<运行仪表盘与Session复用.md>)；完整代码目录仍为规划。

多频道、多人私聊的[话题与后台协作建议](<A方案全景/多频道话题与后台协作.md>)归入既有 conversation、ingress、订阅与 views 职责：补必要绑定和通知路由，不另建 Session 历史或通用消息平台。具体拆合与并发策略仍待验证。

2026-11-02 的[统一事件接口](<A方案全景/统一事件接口与发布订阅.md>)在控制域组合既有接纳、订阅和投递职责，供 Agent tools 与普通组件 API 共用；不另开消息平台。下方补相应规划落点，仍按实际切片建立文件。

本规划承接 [A 方案](<A方案全景/完整架构方案.md>)、[跨模块契约](<A方案全景/跨模块契约.md>)与[连接、订阅及派工方案](<A方案全景/连接、订阅与派工总方案.md>)。现有全景文件夹树继续承载设计资料；源码按调用边界与数据所有者组织，不机械复制 40 个资料模块。

## 目录对应的调用与写入边界

| 边界 | 目录如何落实 |
|---|---|
| 三角色 | `core/` 判断，`execution/worker/` 执行，`outer/replyer/` 表达；六部分不固定绑定六个模型 |
| 内外双工与外层只读 | 外层通过事件入口提交观察，接收视图、状态与回执；可以维护受限对话状态，不能 import 内层写服务或取得数据库句柄 |
| 权威提交 | `core/commit.ts` 组织提案采纳；`control/` 的具名服务负责确定性规则；`control-store/` 在短事务内复核并写入，不在事务中推理或联网 |
| 目标权威 | `control/goals/` 只维护绑定、授权与操作核对；生命周期仍归 DSH Goal/Session 日志，不在 SQLite 新建另一套 Goal 状态机 |
| 记忆权威 | `inner/` 表达领域规则；Ombre 持有记忆/感受正文与索引，控制库保留操作、引用及核对材料，不复制成第二份可独立修改的记忆 |
| 通讯录与关系 | `control/contacts/` 管可核验账号与寻址；`inner/relationships/` 管有来源的关系判断；关系亲疏不授予控制权限 |
| 三种队列 | 对话生成归 `outer/queues/`，任务调度归 `control/tasks/` 与 `execution/`，实际发送/动作归 `control/effects/`；不为此部署三套队列产品 |
| 发送与取消 | replyer 只产草稿，ConversationService 通过受限效果接口登记发送，统一派发前复核；可信控制命令不等待生成队列，新聊天不默认取消后台任务 |
| 宿主外部分 | 后端、渠道侧车、OS 监督和备份按配置运行；权威判断不离开 DSH 插件，监督器不代替 core |

`bootstrap.ts` 是依赖组装点。领域模块依赖 `contracts/` 与所需 `ports/`，具体 `adapters/` 实现接口；Client 只走受限的视图与控制 API。外层和 Client 不直接导入控制库、内层写实现或后端管理客户端，后续以依赖检查和权限反例验证。

这里的 `control/tasks/`、`control-store/`、`outer/replyer/` 是复用机制的落点：任务与事务沿既有 Superagent 复用方案，模型和所有角色的会话优先使用 DSH 公共能力。DS-Bot 旁路仅为原生路线确有缺口后的条件备选，不默认复制第二套会话与压缩逻辑。复制部分需记录来源、提交、许可、依赖闭包、补丁和保留测试；未正式引入前不建 `third_party/`。Ombre、渠道连接器和其他候选保持各自采用状态，规划路径不表示已经安装或接入。

## 运行数据与构建产物

正式数据位置通过 `dataDir` 明确配置，建议独立于源码仓库；合成开发可以使用包内被忽略的 `.local/`。下列是识雨自有数据的逻辑布局，实际路径必须记入实施记录与运行空间清单。

```text
<SHIYU_DATA_DIR>/
├── control/                          控制 SQLite、迁移信息与本地运行门禁
├── objects/                          输入附件、来源材料与证据对象
├── workspaces/                       按任务隔离的工作文件和交付物
├── profiles/                         已发布的稳定人格/偏好配置
├── cache/                            可从权威来源重建的数据
├── logs/                             结构化运行诊断
└── checkpoints/                      一致性说明、组件清单与本地导出
```

Ombre 数据和 DSH Goal/Session 日志沿用各自明确配置的位置，通过引用与检查点清单关联，不假装已迁入此树。独立备份位于配置的独立故障域；最新撤权/删除记录的恢复来源另行登记，不能只依赖旧备份里的控制库。凭据只保存引用，不进入源码、示例、日志或分发包。

## 分批建立的顺序

| 切片 | 实际创建的重点 | 可审阅的完成依据 |
|---|---|---|
| 1 插件基础、原生会话、事件基础与基础仪表盘 | 包配置、Host/Client、runtime 服务组装、事件契约/SQLite Worker、暂停与绑定、受限 replyer 适配及本地 embedding 适配 | 已有基础代码、本地检查及限定宿主安装/零推理探针/重载证据；持久 component/background 事件与正常重启单独测试；真实生成、压缩和完整生命周期待验，不宣称任务闭环或真实外发已实现 |
| 2 控制账本与执行闭环 | control-store、commit、Mandate、Task/Assignment、worker、effects、结果核验与 unknown 核对 | 复用代码来源可查；合成任务经授权、执行、核验形成回执；去重、撤权、重启与未知效果测试通过 |
| 3 持续目标与内层接入 | DSH Goal 绑定、订阅、MemoryOperation、所需六部分规则、联系人及视图失效 | 一个合成持续目标和可核对的后端操作；跨存储中断如实保持 unknown；只实现本轮真正使用的模块 |
| 4 仪表盘完善与健身房 | 完善任务控制、活动/Session/缓存详情、locale、Lab 协议适配与 e2e | 本体作为被测对象走 Lab 公共协议；界面能追到真实任务、原生会话与证据；Lab 执行与评分独立，不导入 Lab 引擎作为本体能力 |
| 5 逐项接入外部能力 | 实际选定的渠道/设备/后端、health、checkpoint、恢复与部署模板 | 每项分别记录真实环境、范围、费用和证据；外部能力启用前具备所需停止、核对及恢复路径 |

切片编号表示主要推进顺序，不表示到第 5 批才考虑恢复：控制库迁移、生命周期清理、暂停/取消、未知状态与重启测试从相关功能首次落地时一起实现。检查点、多后端恢复与正式部署随实际依赖扩展。

**当前在首切片限定宿主接入证据上推进第 2 个切片，并补齐真实生成与完整会话验证。** 基础插件、受限 Session 适配、事件持久链和仪表盘已有代码及限定证据；阶段 2 新增事务/任务源码尚未集成，不计入首切片已验快照。具体范围见[实施记录](<../plugins/shiyu/实施记录.md>)；真实模型、账号、设备和备份继续使用各自已有的具体授权范围。
