## 目标与主方案

宿主外只处理可确定的进程、配置和恢复操作；core 的语义判断仍在 DSH 插件中。首轮使用 **macOS launchd 用户级 LaunchAgent + 极薄 RunGate 启动门控**，启动[宿主方案](<../03-DSH宿主进程/README.md>)确定的专用 DSH Web profile。关闭浏览器不结束宿主；用户注销、主机睡眠、断电不承诺持续执行。若要求无人登录时持续运行，迁移整个 A 宿主到 Linux systemd，Mac 作为设备执行器；不另建独立智能核心。

launchd 负责进程托管与异常退出重启；RunGate 只把识雨的期望运行状态、故障预算、固定版本清单和启动代际接到 OS 机制。它没有模型、任务规划器、通用插件体系或任意修复脚本入口。这一小段领域适配是为弥补 OS 服务管理器不知道“用户暂停、旧备份、任务未知结果”的语义，不替代成熟服务管理器。

复用核查进一步收缩自建内容：单实例锁由宿主 Runtime 唯一持有，调用 proper-lockfile 4.1.2 并局部复用 Superagent 生命周期顺序；恢复入口直接调用 restic、Ombre 组件验证器和任务域同一恢复实现，不再开发通用进程管理、ZIP 解包或第二套任务恢复引擎。保留的识雨逻辑为停用/代际/删除/未知副作用屏障。固定来源、许可证及补丁范围见[复用核查](<../../../research/2026-11-01-复用核查/恢复备份.md>)；目前均为设计接入决策。

## 分工和运行流

| 责任方 | 输入 | 输出与边界 |
|---|---|---|
| [进程监督](<01-进程监督/README.md>) | 受信用户运行意图、退出结果、心跳与本地就绪检查 | 启动、退避、停止或隔离；不写业务记忆 |
| [恢复入口](<02-恢复入口/README.md>) | 故障分类、已知版本、检查点、最新删除与授权记录 | 恢复报告、新启动代际、任务核对屏障；不盲目重放外部动作 |
| DSH 与识雨插件 | 固定启动清单、运行意图版本、启动代际 | ready / degraded、排空结果、去敏诊断 |
| 数据与任务域 | 状态版本、commitSeq、任务与 effect 账本 | 一致快照、恢复核对；判断未知结果而非推测成功 |
| 独立备份 | ready 的 BackupBundle | 可校验副本；只在恢复入口验证后用于切换 |

故障路径为：发现 → 分类 → 停止新派工 → 保留证据 → 执行预定义恢复动作 → 校验 → 核对任务与删除状态 → 在当前运行意图允许时恢复。配置损坏、数据库损坏、备份来源不可信均进入隔离，不能靠反复重启修复。

## 共同控制约束

- `desiredState` 与 `intentSeq` 放在宿主外控制记录中，不能随业务数据库回滚；由可信用户控制入口改动。模型和普通事件不能将 paused / stopped 改回 running。
- 进程实例用 `installationGeneration + hostEpoch` 标识。普通重启生成新 hostEpoch；还原旧备份或控制源丢失时生成新的 installationGeneration 并重新建立设备受控会话。不能只对旧数据库计数加一。
- 还原副本默认 `maintenance`、`reconcileRequired=true`。旧任务暂停、取消、撤权和未知结果要重新核对；最新删除账本不明时不开放 ReadView。
- DSH Goal 的目标专用 Session log 及必要 projection 定义/配置是必需恢复组件；缺失不得 complete/read-ready。恢复先关闭目标调度出口并保持 disarmed，核对 GoalRef/phase、本地 stop 和当前授权后才决定是否重新启用，旧 armed 不构成恢复授权。
- 单任务错误、单个模型超时或离线设备先走其模块恢复；只有本地服务确实失去就绪能力才升级为进程重启。
