## 1. 下一步怎样启动验证

本体首个切片建立可装载插件、受限原生 replyer Session 与基础运行仪表盘，产品代码及测试归属[本体实现模块](<../识雨本体文件树规划.md>)。独立候选探针按明确范围放在测试目录：验证原生会话接缝和核查过的事务/任务闭包，配一条事件入口、假 worker 与假设备；不先提取旁路回复作为默认实现。先验证现成组件与所需补丁，不从零重写同职责引擎。

控制域采用TypeScript与复用的SQLite事务/Engine，模型/设备用确定性替身。同一控制操作的状态、审计、回执与outbox原子提交；DSH Goal的Session log与Ombre各为独立权威。跨组件命令经operation记录及核对发布，不能以control commitSeq报远端成功。公共包/API、许可证、来源与改动清单先验证；模型外发、真实设备与远端备份默认关闭。

## 2. 统一实验参数、证据与失败规则

将实际执行日期记为 `D`，单次实验根记为 `R = 测试/D-识雨A方案验证/`。这是未来路径约定，本轮不创建运行目录。每项写入 `R/artifacts/Vxx/<runId>/`，其中 `runId` 包含代码版本、场景和随机种子；fixture 放 `R/cases/`，验证代码及依赖放 `R/src/` 与该实验根下。各 V 下列出的证据文件均相对该产物目录。

- 执行前冻结 `实验计划.md`、fixture 摘要、代码/DSH 提交、Node 与实际 SQLite 版本、OS、库编译选项、适配器/策略摘要、并发、随机种子、时钟规则与阈值。默认随机种子 1–20；不在失败后修改阈值来获得通过。
- 复制样本另保存来源commit/路径/函数范围、LICENSE/适用NOTICE、依赖锁、逐项补丁与上游测试映射。记录哪些断言只在对照配置成立；不得将上游已有测试文件记成实际通过。
- 时间逻辑默认用可推进假时钟；实际性能用单调墙钟，注明硬件和负载。单步协议等待默认最多 5 秒、单用例默认最多 120 秒；备份、集成与语义评测按各项额外上限。超时记失败或结果未知，不能删掉该样本。
- 每项至少保存 `manifest.json`、`result.json`、脱敏 `trace.jsonl`、预期与实际差异、失败种子；涉及持久化保存前后 `state-digest.json`，涉及外部效果保存独立执行器的 `effect-ledger.jsonl`。观察器与账本不放在被注入崩溃的进程中，防止由被测组件自己宣告成功。
- 故障断点覆盖：受理前、受理持久化后、领域事务提交前/后、outbox 可见后、发送前、外部已执行但回执丢失、回执落盘前/后、释放租约前。每个适用断点做一次故障和持续故障两类，各重复 20 次；关键边界竞态另按 V06/V11 的并发规模执行。
- **硬门槛均为零违规**：未授权写入/动作、跨主体泄露、旧执行实例覆盖、已删除内容复活、被暂停系统自动恢复运行、无法解释的半提交、把未知效果宣布成功。合格的有限样本不证明所有输入都安全；记录覆盖范围。
- 性能和语义阈值为本轮提出的探索门槛，不是现有测量或生产 SLA。候选达不到时提交证据、保留失败，选择文中备选或重新评估设计；不得以“模型波动”免除边界失败。
- 任一硬门槛失败即阻断依赖它的后续阶段，冻结失败快照与执行器账本；停止新效果，不自动清空数据库或删除权威状态。修复后先复现失败种子再跑该项及直接依赖项。结束时关闭本实验进程，记录已清理和保留路径。

## 3. 验证用例

<a id="v01"></a>
### V01　契约覆盖、版本和事务能力门槛

- **前提/依赖：**G0，无运行依赖；准备 G1 时补实际版本检查。输入为 40 模块清单、跨模块契约、DSH 固定源码和候选运行环境。
- **步骤：**核对40模块所有者、复用源码/API、依赖闭包、许可与补丁；各后端写路径具名且跨服务有操作记录。对实际进程记录Node、SQLite版本/compile_options、各库日志模式及备份/检索能力；控制域准备四表事务，Ombre/DSH Goal单独验证操作核对，不用四次storage-domain写入冒充事务。
- **预期/门槛：**40/40 覆盖、零无所有者写入口、零关键契约冲突；SQLite WAL 基线为 >=3.51.3 或有官方回补与实际构建证据，Node >=24.9 或选定 Node 24.22.2 本身不能替代 SQLite 核查；跨表原子性由 V06/V12 实测才算通过。
- **失败处置/证据：**阻断仓储实验，选已核查修复的 SQLite 构建或回退方案重新核查，不默认沿用嵌入旧版。保存 `coverage.csv`、`contract-conflicts.md`、`runtime-versions.json`、`transaction-capabilities.md`。纯文档覆盖通过与运行环境通过分别记录。

<a id="v02"></a>
### V02　输入、主体、目标与可信控制来源

- **前提/依赖：**V01；F1/F3；渠道和可信用户控制入口替身。
- **步骤：**投递同名异人、伪造actor与控制命令外观正文；DSH Goal按单目标Session创建/修改/暂停/完成，测试GoalRef revision冲突、cancel/expire先关闭本地派发后处理原生状态。切断Session日志写入与GoalBinding确认之间的连接；恢复核对unknown，不以本地回执代替原生phase。
- **预期/门槛：**40 个身份/控制组合全部符合预先表格；同名异人误合并 0；普通正文或 worker 输出产生新授权/恢复暂停目标 0；目标至少保留范围、完成条件、预算、暂停及截止条件，拒绝有可追踪原因。
- **失败处置/证据：**冻结受影响目标，停止自动派工；保留 `identity-cases.json`、`goal-transitions.jsonl`、`control-origin.jsonl`。不能用“用户说过类似的话”补造来源。

<a id="v03"></a>
### V03　事件重放、乱序和接收回执

- **前提/依赖：**V02；F1；持久 inbox 与假时钟。
- **步骤：**100 个唯一事件各投递 10 次，打乱顺序并跨受理断点重启；同源同 ID 换载荷，跨来源复用相同外部 ID，回放撤回后迟到事件。
- **预期/门槛：**每个合法去重键只产生一次应有的领域变化；同键异内容冲突拒绝；跨来源不误吞；零跨会话串线；已接收、已处理和内部已提交回执分开。20 个乱序种子全部满足；未知 schema 进入有界隔离队列。
- **失败处置/证据：**停止消费冲突事件，保留原始合成事件及冲突解释；`event-ledger.jsonl`、`dedup-report.json`、`receipt-stages.json`。

<a id="v04"></a>
### V04　外层只读、注册准入与执行授权

- **前提/依赖：**V01/V03；F2/F7；独立工具注册表与执行授权入口。
- **步骤：**从 replyer/渠道/检索尝试越权写、取得 DB 句柄和跨用户视图；覆盖 own-scope 与 customExecutor。检查受限原生 Session 创建、恢复与实际请求的 tools=[]，没有继承通用工具权限或未获准的主会话历史；旁路适配检查只在该备选启用时适用。重复读取 1,000 次，包含仪表盘刷新，确认不新增模型调用、任务派发或记忆写入，区分查询因果写与独立后台衰减；先关闭 You/them，再验证启用时其有状态读取仅由内部任务执行。推进视图 TTL 30 秒并改变撤权/删除水位，最多重取 2 次。
- **预期/门槛：**至少 30 条越权路径零成功；只读获取不修改权威状态；禁止工具未注册成功或执行前被拒绝；视图只含当前主体获准字段，不含写能力和密钥。不能以 DSH ToolRestriction 单独判定通过；同进程受信插件不被宣称具备 OS 强隔离。
- **失败处置/证据：**阻断开放不受信扩展；需运行不受信代码时转进程/系统执行边界另验，核心仍留在 A 宿主中。`tool-admission.jsonl`、`execution-auth.jsonl`、`readonly-state-diff.json`、`scope-leak-report.json`。

<a id="v05"></a>
### V05　对话队列、过时回复与发送状态

- **前提/依赖：**V03/V04；F1/F4；假生成器和渠道发送账本。
- **步骤：**将 F1 扩展为 20 会话共 1,000 条短消息，输入突发 10 条/秒；全局模型槽 3、后台最多 2、对话预留 1，另让至少 4 条非模型控制任务并发；在生成中插入新消息、取消、目标暂停和内部版本变更，假生成器故意忽略 abort；发送成功后丢回执，再重启。覆盖合法 dialogue origin 的普通回复、task origin 的任务通知，以及 origin 缺字段、混合字段和旧 conversationGeneration；锁定模块选择的合并/打断规则后生成独立预期序列。
- **预期/门槛：**20 个种子无依赖倒序、无跨会话串线、无取消后新发出的旧回复；已有外部发送结果未知时不伪报未发送。普通回复不伪造 Task/Assignment，两个 origin 分支均复查有效 Mandate、目的地和外发范围；缺失/混合来源拒绝，旧会话代次不能发送。假模型每次 100 ms 的基准下，本地接纳回执 P95 <=500 ms，认证停止使新发送失效 P95 <=1 秒（至少 200 样本，不计真实模型/外网）；每会话待答文本 <=20、总待处理输入 <=1,000，饱和时控制入口仍有界可用。
- **失败处置/证据：**暂停自动发送并核对渠道账本；`queue-timeline.jsonl`、`channel-send-ledger.jsonl`、`latency.csv`、`stale-reply-report.json`。

<a id="v06"></a>
### V06　core 提案、readSet/CAS 与领域原子提交

- **前提/依赖：**V01/V04；F2/F3；真实临时 SQLite 专用库与独立观察器。
- **步骤：**控制域100提案竞争同聚合expectedVersion，另100个独立聚合；测试集合谓词、同ID异内容与事务写断点。复制的atomic注入SAVEPOINT建立失败、嵌套回滚、RELEASE/ROLLBACK失败、afterCommit抛错和误传Promise；Promise不得被当作同步完成。仅FTS对照配置额外测试search_docs/FTS同事务及预分词来源CAS；跨后端写断点归V12/V23。
- **预期/门槛：**同实体恰有1成功，独立聚合均可成功；集合约束保护write-skew；同ID重放返回原回执，异内容拒绝。控制事务各断点20次均全有或全无，integrity_check通过；回滚未知隔离连接，不虚报成功。FTS对照才要求索引同事务；其来源CAS失败不得提交旧分词。跨服务不要求虚假的共同回滚。
- **失败处置/证据：**停止写入，冻结数据库/WAL和失败种子；不得自动覆盖冲突。`cas-history.jsonl`、`write-skew.json`、`atomicity-matrix.csv`、`commit-receipts.jsonl`。

<a id="v07"></a>

## 4. 三条合成端到端场景

**E1：有目标的主动工作与只读表达。** 用户 U1 给出持续目标“文件变化后生成摘要”，范围只含假设备 A 的测试路径。以专用 DSH Session 创建目标，保存 GoalRef 与 GoalBinding；插入 Session log 已写但绑定未确认的中断，核对后继续，不能重复建目标。相同外部事件重复 10 次并乱序到达，core 生成受限任务，按设备 executionMode 派发；worker 返回摘要及证据。新认知/记忆提案先经本地批准，再以 MemoryOperation 调用默认后端；分别跑后端 applied、确定拒绝和写后断连 unknown 分支。replyer 读取已核验视图，components[] 带各后端 revision 或核验摘要、capturedAt、索引及删除水位，连同控制 commitSeq/stateVersion 形成可追踪的版本向量；不伪造跨组件原子版本。

预期：一个有效任务效果；摘要完成有 VerificationReport，控制采纳有 CommitReceipt，记忆 applied 有 backendReceiptRef/verificationRef，对外发送有 DeliveryReceipt。Task 成功可以与记忆 unknown/rejected、通知 unknown 并存；未获后端完成证据时不能宣称“已经记住”，依赖该记忆的后续任务保持等待。U2 同名对象与设备 B 同名路径不被读取；六部分状态可查询，无变化部分明确未更新，人格/情绪不扩大授权。另做纯状态问答：采用 dialogue origin，不捏造 Assignment、不赋予内层写权限；视图部分 stale/unavailable 时明确展示，不用旧值补成 current。

**E2：外部完成但回执丢失，随后暂停。** direct 现成工具和 gated 执行器分别运行：假设备 A 已执行一个非幂等动作，回执丢失，Host 在记回执前退出；用户从可信入口暂停系统/目标，旧 Assignment 迟到上报，设备 B 被建议接替。目标暂停再插入本地停止已生效、DSH Goal 日志确认未知的中断；阻止新派发不得等待远端或 Session log 回执才生效；已发动作仍按真实停止证据核对。恢复目标专用 Session 后保持 disarmed，核对原生 GoalRef/phase、本地 stopReason 与当前 Mandate；记忆后端若也存在未确认操作，独立保留其 operationId 与状态，不把目标暂停推导成记忆回滚。

预期：监督器不将 paused 改 running，不创建第二个动作；任务保持 unknown 或按原 effectId 的真实证据收敛。direct 无查询/停止证据时继续冻结资源，不凭连接恢复重发；gated 只在持久回执和代际检查通过后承认已完成结果，旧实例不能凭迟到回执提交新提案。未确认资源释放前不改派，Goal 命令 unknown 不被本地 commitSeq 掩盖；replyer 分别报告 Task、Goal、MemoryOperation 与通知的实际状态。可信控制入口明确恢复后还须复核原 Mandate/预算、Goal 原生状态和未核清效果，不能以重启续授权或自动重 arm。

**E3：删除期间备份、故障恢复与数据重建。** 在 checkpoint 生成时删除一条事实及其派生认知，令默认记忆后端的清除或索引消费者离线，并制造磁盘满。bundle 必须包含控制 SQLite、Ombre 原生导出、目标专用 DSH Session log、必要 projection 定义/配置及 components 清单；记录各自实际 revision/seq、capturedAt、删除水位、校验摘要与静默证据，不能把逐库一致称为同一事务截面。分别恢复较旧完整 bundle、缺失/截断 Goal 日志的 bundle，以及取得/未取得最新删除账本的分支；SQLite/FTS 对照另验其本库删除与索引重建，不能替代默认后端清除验证。

预期：可信删除水位核验后先施加控制屏障并核对各组件清除，再开放获准读取；未完成物理清除明确标记，索引或 feel/I/关系派生不能复活正文。缺删除账本、目标日志或无法解释的组件版本时保持恢复锁及 reconcileRequired，不伪报完整恢复。目标从日志恢复仍先 disarmed，旧 active/armed 不能自动派工；核对 GoalRef/phase、GoalBinding、stopReason、授权及 MemoryOperation/Effect 未知结果后才能由合法控制恢复。ReadView 版本向量须反映实际恢复组件，部分不可用不得填造版本；未删人格/关系及对象按各自权威证据一致。unknown 不重放，低空间只回收可重建缓存，不删除权威状态。

## 7. 本轮审查收敛与尚需验证的关键点

已作为计划基线收敛：实体 readSet/CAS 与集合谓词在实际支持的后端执行；控制 SQLite 单 writer 及本域记录/outbox 同事务；DSH Goal 日志与默认记忆后端各有权威回执和核对流程，不能伪造跨服务原子提交。暂停不等于已发效果已取消；direct/gated 能力承诺分别验收；设备失联不提供瞬时撤权；恢复必须有最新删除账本和必要目标日志，目标先 disarmed；RPO 按已完成 bundle 的采集时间计算。不同字段或状态名须在跨模块契约给等价映射，不能改变含义。以上均为待执行计划，本轮未运行 V01–V27。
