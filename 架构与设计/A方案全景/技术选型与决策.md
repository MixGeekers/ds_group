**v1.1复用修订：**依据用户要求，已逐项核查全部40模块，选择直接依赖、局部复制与必要补丁。DS-Bot/Superagent不再只作机制参考，Ombre优先承接联合内层能力，短时ToneView撤出默认；公共契约同步为分域事务与可核对操作。具体[40模块复用方案](<复用方案.md>)与[固定源码证据](<../../research/2026-11-01-复用核查/目录.md>)优先于旧结论。以下选择是进入验证的设计，不代表已复制、安装或运行。

**Session 后续决定优先：**core、worker、replyer 默认使用原生 DSH Session 的生命周期、历史、恢复及压缩；早期 DS-Bot 旁路表达改为条件备选，不先实现两套会话系统。该调整来自用户明确方向，具体隔离、缓存命中和压缩效果仍待本体验证。

## 2. 架构决策记录

| ID | 选择与理由 | 不选方案及重新评估触发 |
|---|---|---|
| ADR-01 | 保持 A 单一核心；宿主退出暂停，外部监督负责恢复 | B 只有在必须跨 DSH 存续或需要强进程边界时重评 |
| ADR-02 | 2026-11-01 用户确认尽量复用 DSH Session；三角色默认原生会话、历史、恢复、压缩，不为内层组成各造代理宿主 | replyer 的 DS-Bot/低层流改为条件备选；只有原生隔离等必要边界经验证不足时才评估，不并建两套历史/压缩 |
| ADR-03 | 控制库局部复制Superagent事务/仓储；Ombre等后端单独持有自己的权威记录 | 单库保留为对照。DSH单聚合+嵌入pendingEvents可直接原子；跨记录才需事务库，不声称宿主完全不能做业务持久化 |
| ADR-04 | 程序授权与合法迁移先行，模型只提出判断和提案 | 不以提示词或角色类型当写权限。可信插件破坏边界时阻断装载，必要时进程隔离 |
| ADR-05 | 内层六部分作为领域状态，core / views 作为组织职责 | 不默认一部分一模型、一模型一进程；测量证明专门模型收益后局部路由 |
| ADR-06 | 对话与任务运行状态可以持久化，但与长期记忆和内部提交权限分开 | 不把“外层只读”误解为不能维护发送回执，也不让回执记录顺带修改内层 |
| ADR-07 | 复制Superagent纯域Engine闭包与Effects/Outbox并补确切边界；TaskService仅产品门面 | 不再从零写任务引擎；多中心持久流程确有需求时再比较Temporal等现成系统 |
| ADR-08 | 优先复用Ombre联合能力；Mem0可作完整替代，FTS5为对照/回退 | 不同时维护多份权威记忆；LanceDB阈值只适用本地索引增强，不能用来排除整个记忆组件 |
| ADR-09 | 设备网关是插件内适配职责，中心保持权威状态 | 不先部署完整远控中枢；设备数量、异构运维与审核成本显著上升后再比较成熟中枢 |
| ADR-10 | 物理预留由OS卷/配额完成；应用另做预算与降级 | 普通目录不保证磁盘预留，容器也不自动覆盖全部外置数据 |
| ADR-11 | 复用各后端原生导出/验证和restic，顶层只做组件清单与恢复核对 | 不重写Ombre导出器；逐库一致不等于跨库同截面，同盘副本不算独立域 |
| ADR-12 | 情绪/I与记忆共用Ombre；稳定Profile用宿主提示装配；能力用DSH原生registry/skills | 撤回默认三维ToneView和重复技能平台；情绪/I不扩权，来源与正文变更须复验 |
| ADR-13 | 原始输入、正式记忆、索引、回执和备份分别保留并可追踪删除 | 不将无限日志积累当记忆；不承诺删除记录立即抹除所有历史介质 |
| ADR-14 | 以确定性假模型先验证边界，真实模型另测质量与费用 | 不用一次流畅演示替代事务、权限、恢复和多平台验证 |
| ADR-15 | 稳定会话绑定与前缀，动态上下文追加；generation 只控制草稿有效性，压缩保留 Goal 专用 Session | 缓存不是权威或权限；撤权/删除/受众变化重建有效投影，实际命中以 usage 与延迟验证，不预设百分比 |

ADR-01 的 A 形态与 ADR-02 的原生 Session 优先来自用户决定；其余为规划细化，实施状态与验证结论单独记录。未来替代需注明触发证据、迁移成本和回退方式，不能默默改变旧目录的含义。

## 3. 统一参数登记

| 参数族 | 规划值 | 生效范围 |
|---|---|---|
| 并发 / 主动节流 | 模型3、后台≤2、对话预留1；core1、worker2；同目标自动最多4次/h且至少15min间隔 | 合成负载起点；控制入口不占模型槽 |

| replyer | 输入预算8000 tokens、最大输出1024；视图30s、最多重取2次 | 模型真实调用仍须激活预算，数字不是消费授权 |
| Session / 压缩 | 同 Goal、Assignment 或 conversation/受众绑定复用；按角色输入预算与输出预留使用原生 compaction | 摘要调用计入统一预算；模型与 effort 在实际宿主接缝核对；缓存字段缺失标未知，generation 不新建会话 |

| 单轮推理 / 视图 | 一次自动评估含格式修复最多2次模型调用；ReadView≤20项/64KiB | 六域共用预算；provider重试与本上限取交集，所有实际尝试计费/计次，不另得免费重试；视图注入仍受角色token上限 |

| 备份 | 每5min尝试，单批目标≤5min；最近完整capture年龄目标≤15min；7d保留全部+30d日快照 | 时间与保留为验证策略；权限/删除优先，实际RPO取最近完成备份，不以调度周期冒充 |

## 4. 必须编写的有限领域层

| 自有内容 | 必要收益 | 限制自研范围的方法 |
|---|---|---|
| 六部分逻辑映射与保存规则 | 表达识雨自身语义、来源和边界 | 复用Ombre/DSH等完整能力，不把逻辑分区当作六套自研系统 |
| 领域权限、后端操作与只读视图 | 外层只读、授权可查、组件版本和结果可核对 | 任务域与事务采用已列源码；只补产品差异，不重写底层状态机/队列 |
| Effect核对与设备薄适配 | 知道超时后究竟发生什么，避免危险重复 | 协议传输、远程管理和GUI能力复用成熟产品；能力不支持核对就限制自动化 |
| RunGate与恢复清单 | 尊重停用、限制失败循环、处理旧状态恢复 | 生命周期交OS、备份交restic，不重写守护或快照系统 |

若某项薄层不断扩成通用平台，先停下来重做成本比较；“完整方案”不意味着每项能力都必须自写。
