# 全架构复用方案 v1.1

[完整方案](<完整架构方案.md>) · [模块目录](<目录.md>) · [公共契约](<跨模块契约.md>) · [选型决策](<技术选型与决策.md>) · [核查证据](<../../research/2026-11-01-复用核查/目录.md>)

日期：2026-11-01。用户要求逐项重新核查：能直接用就直接用，整包不合适则复制可用部分。本版把“借鉴思路”推进为**有具体接口、源码边界、必要修改与验收的复用设计**。这是设计路线的选择；依赖、源码复制与运行接入尚未实施，不能把下表读成已安装清单。

## 1. 先修正取舍方法

渠道、订阅和core派工进一步细化见[专题总方案](<连接、订阅与派工总方案.md>)与[新核查证据](<../../research/2026-11-01-连接订阅与技术栈/目录.md>)。OpenClaw统一渠道侧车优先进入条件验证，保留官方SDK对照；现有DSH入口、DS-Bot表达和Superagent任务分工继续有效。

保留用户确定的 A 插件内核心、内外双层、六部分逻辑职责、core / worker / replyer 和外层只读。六部分可以共享组件；外部记忆服务、数据库线程或设备执行器不自动构成第二个智能核心。

撤回“必须所有六部分在同一 SQLite”“记忆服务只能返回纯提案才可复用”“情绪必须先自写三维状态”“发现默认权限不同就只能参考思路”等前置假设。它们不是用户硬约束。先核查能否配置、限制入口或修改小范围代码，再比较完整功能下的维护成本。

有成熟公共接口时直接依赖；项目没有稳定可用包，但局部实现有价值时按固定提交复制源码；必要补丁必须明确。数据库、MCP 客户端、模型重试、备份工具等已有通用能力不重新实现。产品语义和授权核验仍需要识雨定义，复用不等于把上游默认政策全部继承。

## 4. 源码复制必须具体到什么程度

每个拟复制单元记录仓库、固定 commit、路径与函数范围、许可证及版权/NOTICE、运行时 import 闭包、拟删改项、对应上游测试、识雨新增断言和升级比对方法。不可把网上可见但许可不清的代码按可复制登记。

公共包优先保持依赖，避免 vendoring；需要复制的项目内部代码保留独立来源清单和小补丁。直接引入项目根入口可能带入全权限执行器、数据外发或后台任务，因此优先复制经核查的局部闭包。MIT/Apache 项目的具体许可与通知以固定版本文件为准；不自动将仓库主许可扩张到全部第三方资源。

验证阶段所需源码副本与依赖放 `测试/D-主题/vendor/` 或该实验依赖环境；本轮没有在产品目录复制源码。验证通过后进入产品的范围仍按当时明确实施任务执行。上游策略/提示可以作为素材复用，但要删除不属于识雨权限的动作指令，输出改为受控提案。

## 5. 多后端一致性与回退

控制 SQLite 记录任务、授权、操作命令与回执；Ombre 只在该路线中独占记忆与感受主副本。`commitSeq` 只代表控制账本提交，不能证明远端记忆已保存。跨后端操作记录先持久化，再调用服务，最后核对结果；写后丢回执时保持 `unknown` 并查询，不盲重放。

持续目标使用 DSH Goal 的专用 Session 日志与原生 revision / phase，控制库保存 GoalBinding、授权和停止原因，不另建目标生命周期。备份必须包含这些专用日志、实际序列和投影定义；只保存 GoalBinding 不足以恢复目标。恢复默认为 disarmed，未核对暂停、撤销和授权前不续做。

ReadView 必须标注各组件版本或可验证来源摘要、采集时间和新鲜度。不能把两个服务先后读取的结果叫作一个 SQLite 原子快照，也不能把内容哈希当作服务端 CAS。Ombre 缺少所需幂等、版本或清除接口时，先完成限定补丁与合成验证，真实自动写入保持关闭。

后端原生导出保留各自的一致性边界，逐库成功不证明全局静默。Ombre 当前导入累计未压缩上限为 512 MiB，首个 1 GiB 组合恢复用例把其子包限制为不超过 256 MiB，其余为独立对象；扩大限制必须另验资源消耗。现成设备工具使用 direct 模式和中央授权，未知动作锁住资源；需要离线排队或断连后续做时才增加 gated 端侧协议，不能假设现成 SSH / MCP 客户端支持 fencing。

单库 SQLite/FTS5 保留为对照/回退配置，与 Ombre、Mem0 后端互斥选择；不默认并行维护三份长期记忆。若服务适配最终需要大面积长期 fork，则以记录的维护成本和功能效果比较回退，不用想象中的优势决定。

## 6. 验证顺序

1. **版本与可复用闭包：**先证明公共导出、运行时、许可与复制依赖完整；这是 V01/V24 的前置，不先从零实现替代品。
2. **单组件探针：**DS-Bot 只读快照、Superagent 同步事务与效果队列、Ombre 保存/检索/回顾/清除分别以合成数据验证；默认无模型外发和真实设备。
3. **跨组件闭环：**复用 V04–V12、V16、V21–V24 的边界与恢复场景，补记忆服务写后断连、跨组件版本不一致与旧数据恢复。
4. **真实依赖：**再按 V25–V27 分别启用有预算的模型、获准设备与独立备份。静态核查或上游有测试不能替代本轮实际结果。

每次复用失败先定位是配置、接口、缺少小补丁还是结构性不适配；只有后者才评估替代项目或必要自研。验证记录同时统计自行编写/修改的代码与运维依赖，避免只比召回率而忽略整个产品机制的复用收益。
