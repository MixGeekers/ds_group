## 主方案

**数据模块构造一致 BackupBundle，restic 负责加密、去重、传输、快照与保留。** 不自写压缩备份引擎、加密协议或块去重系统。首选固定 restic 0.19.1；官方 release 为非预发布，目标平台二进制和校验须在验证时固定。[官方发布](<https://github.com/restic/restic/releases/tag/v0.19.1>)。

复用核查将 BackupBundle 明确为组合格式：唯一 CheckpointService 直接调用各组件既有快照能力；Ombre `115d831` 已有流式导出、SQLite backup、manifest和引用闭包，不再重写它的导出器。包记录 components、各组件版本/水位/manifest摘要/静默证明；Ombre 导出锁不是全写者锁，缺少共同截面证明时只可称组件快照向量，恢复须核对后才能开放。备份模块不重复扫描 live 数据。固定来源、许可、限额与补丁见[复用核查](<../../../research/2026-11-01-复用核查/恢复备份.md>)。

生产建议目的地为已授权、与主机分开的 SFTP / NAS 存储；若暂时只有第二块独立物理盘，明确其只能覆盖相应磁盘故障，不能把同机副本宣称为异机灾难恢复。首轮合成逻辑验证可在测试目录使用独立仓库，真实故障域验证另列 V27，不能混为通过。

## 模块与契约

- [独立域备份](<01-独立域备份/README.md>)：接收 ready 的 Bundle，备份、校验、记录新鲜度、执行受控保留与删除传播。
- [恢复演练](<02-恢复演练/README.md>)：从副本和独立恢复凭据重建隔离环境，验证业务状态、删除和未知外部效果，测量 RPO / RTO。
- [本地检查点](<../06-预留空间/08-本地检查点/README.md>)：拥有在线 SQLite 备份、对象 GC 屏障、快照水位及 bundle manifest；不由 restic 从活跃数据库目录自行猜测一致性。
- [恢复入口](<../05-宿主外恢复/02-恢复入口/README.md>)：拥有恢复锁、版本迁移、激活切换和任务恢复屏障。

BackupBundle 的最低信息为 snapshotId、captureTime、schemaVersion、软件 / 配置 manifest、从快照数据库读取的 commitSeq / stateVersion / tombstoneWatermark、数据库 hash、不可变对象列表及 hash / size、凭据引用清单。恢复密码不在 bundle 内，宿主外最新运行意图也不能被旧 bundle 覆盖。

组件清单还必须含 `dsh-goal-sessions`：GoalBinding 绑定的目标专用 Session 耐久日志、必要 projection 定义/配置、实际日志序号与 GoalRef revision、原生 phase/armed、对应版本及 flush/静默证据。缺少它不能用本地任务副本代替权威 Goal 状态，包不得 ready，恢复不得 complete/read-ready；只覆盖目标专用 Session，不扩展到无关聊天。恢复先 disarmed，重新启用取决于当前意图、授权及任务核对。

## 新鲜度与恢复目标

合成验证基线为 1 GiB 数据、1000 个任务记录、100 个结果未知的外部 effect。每 5 分钟尝试 checkpoint + 备份，单批目标 ≤5 分钟；以最近完整且可恢复的独立副本 captureTime 计算实际恢复点年龄，目标 ≤15 分钟。备份开始时间、进度或返回了 snapshot ID 都不足以证明完成。

RTO 验证目标为 ≤30 分钟恢复至“只读校验通过、删除与任务核对完成”；不含购买 / 准备硬件时间，也不保证无法查询的真实设备副作用已解决。网络离线、凭据不可用、检查失败或副本年龄超标时明确 degraded，不自动删主数据抵消备份容量不足。
