## 1. 主方案与此次修订

情绪职责优先由**同一 Ombre 记忆服务中的情绪坐标、感受记忆和回顾机制**承担。六部分职责不要求六套独立组件；本模块不再默认建立第二套情绪数据库或独立情绪Agent。

撤回此前“三维valence/activation/strain＋分钟级半衰期＋事件固定增量”作为首验优先路径的安排。那是未经效果验证的产品假设，不足以排除已有实现。短时ToneView仅在用户明确需要“当前互动状态随时间恢复”、且现有感受记忆不足时另作对照；当前验证先使用固定表达基线与Ombre联合方案。

这里的情绪是可记录、可解释的模型输出和记忆元数据，不声称模型具有主观体验。情绪可以影响记忆相关性和回顾材料，但不能赋予工具权限、扩大预算、改变用户指示或成为拒绝删除的依据。

## 2. 直接复用组件与接口

固定 Ombre 3.6.14，提交 `115d831d979bf67efc7150f976e2cb34c333c935`，MIT。Python服务经DSH现有MCP client接入；同一服务由记忆模块管理，不另起情绪服务。协议和进程组合仍须验证。

| 入口 | 输入与输出 | 状态及副作用 |
|---|---|---|
| `hold(content, valence, arousal, ...)` | 经core批准的经历正文与V/A；返回桶标识/提示 | V/A均为[0,1]；显式值优先，模型打标失败保留正文及中性默认值 |
| `hold(content, feel=True, source_bucket, valence, arousal)` | 经回顾形成的感受文本与来源桶；返回feel桶 | 建立独立feel类型，关联来源；标来源digested，可写model_valence；不是只读调用 |
| `feel(query)` | 具体回顾问题；返回相关感受正文 | 语义阈值0.65；语义失效退回字面匹配。缺失与低相关不编造感受 |
| `dream(window_hours)` | 回顾窗口；返回经历、相关feel及I候选材料 | 记录I见证pass/offer，可能触发webhook；只能作为受控整理任务 |
| 记忆评分/衰减 | 原有importance、activation_count、arousal、时间、resolved/digested | 影响记忆活跃分与归档；feel类型不衰减，不能误称为“当前情绪向中性恢复” |

精确API源码、依赖、许可与局部复制闭包见上方证据。优先公共MCP调用，不直接嵌入依赖共享runtime的store_feel或I内部函数。服务SDK兼容和真实吞吐未验证。

## 3. 数据所有权与更新流程

**权威感受正文在Ombre桶中。** 识雨只保存命令回执、bucket引用、sourceRefs/dependencyRefs及访问范围；EmotionView是可重建投影，不再双写一套权威EmotionState。稳定人格配置另由人格模块维护，不把感受自动晋升为人格规则。

1. 外层递送观察，core依据来源和范围决定是否构成记忆/回顾任务；普通外层文本没有直接调用hold/dream的路径。
2. worker可以返回感受候选与来源，core校验来源仍有效、用途和数据出站范围；模型评分不代表真实性或授权。
3. 经记忆适配器提交命令，记录 `approved→dispatching→applied/unknown/rejected`；仅收到确认后推进本地状态版本。unknown先核对，不能盲重试hold。
4. replyer取得裁剪的EmotionView：`bucketRefs, sourceRefs, content/summary, valence, arousal, scopeHash, stateVersion, commitSeq, authEpoch, tombstoneWatermark, observedAt, validUntil, freshness`。摘要如有，必须标明派生性质与引用。
5. 取回感受仅作为当前任务的表达与回顾材料。它不自动成为新证据；重复检索不得产生新的feel，也不得累计人格“支持次数”。Ombre当前搜索已经取消自动touch。

内层只读是外层访问边界；Ombre后台衰减与归档属于后端自身维护，需要观察和同步状态，不能假称整个系统只由一个SQLite事务修改。统一多库命令和恢复规则由记忆/数据模块负责。

## 4. 失败、隐私与变更治理

- 服务不可用：返回缺失或明确过期的视图；replyer使用稳定人格和当前用户要求，不制造感受。语义服务不可用可用原项目字面降级，并保留降级标识。
- 来源被删/撤权：立即以删除水位抑制相关feel/I及旧ReadView，随后按记忆模块删除协议清理；“感受需要保留”不覆盖删除要求，归档不等于清除。
- 模型把用户感受写成自己的感受：在回顾数据集核查主语与来源；无法判断时只保存原经历，不自动创建feel。
- 重复/迟到命令：按命令ID和结果核对处理；尚未证明原工具端幂等，不能把MCP成功连接视为恰好一次。
- 模型服务可能接收正文：沿统一出站策略；视图按主体范围裁剪，不向其他会话泄漏来源。
- 不保留旧版24小时情绪事件TTL作为feel默认删除策略；长期feel与记忆生命周期一致，具体保留由用户范围和删除规则决定。
- 变更情绪检索/衰减参数必须固定版本、比较质量与记录回退，不对线上感受数据静默批量重算。回退只改变后续检索/投影，不重放写操作。
