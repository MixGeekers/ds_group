# 内层 · 六部分状态与一致性方案

[上级](<../README.md>) · [全景目录](<../../../目录.md>) · [全景图](<../../../../图示/识雨全景架构-A.html>)

- 更新：2026-11-01（America/Caracas）。区域 ID：`inner`。
- 设计状态：六部分方向已明确；本轮形成进入验证的共同状态与提交基线。
- 实现状态：仅设计，未建立内层运行数据或模型。

## 1. 主方案

首版采用一个逻辑准入中心与一组受控领域服务；权威数据可由既有领域组件持有。优先验证 Ombre 记忆后端 + SQLite 控制账本，同库六域是对照方案，不是用户硬约束。记忆、关系、情绪、认知、人格、能力是六种领域职责，可以由同一模型服务按任务处理，不预设六个 agent、六个模型或六个常驻循环。core 组织判断和提交，ViewService 组织读取；两者不是第七、第八种内部状态。

把“候选观察 / 推断”“权威记录”“只读表达依据”分开：外部文本与模型输出先是来源材料或 Proposal；领域规则校验通过才成为正式状态；replyer 只拿与当前用途相关的投影。受控提交是结构性边界，不依赖一句提示词“不要改记忆”。

## 2. 状态所有者与跨域影响

| 领域 | 拥有的正式对象 | 能提交什么 | 跨域关系 |
|---|---|---|---|
| 记忆 | Ombre 持有经历正文、情感痕迹与原生整理状态；控制账本持来源和操作引用 | 受控保存、修订、遗忘、删除 | 为关系与认知提供来源引用，不复制第二套正文权威，检索次数不等于可靠性 |
| 关系 | 本地已验证身份绑定与关系断言；Ombre them 条件承接人物认识 | 有依据的关联、矛盾和撤回；them 子项验证后开启 | 人物名称不等于账号绑定；them recall 有写副作用，不能直交外层 |
| 情绪 | 同一 Ombre 服务中的情绪坐标、feel 感受与来源；EmotionView 为投影 | 经批准的 hold / feel 与回顾，后端维护单独登记 | 可影响记忆相关性与回顾材料，不能改变权限、预算或用户指示；不另建短时情绪状态库，feel 不衰减 |
| 认知 | 本地有来源的 Claim、假设与冲突；Ombre dream / I 提供回顾及自我候选 | 提出 / 修正 / 撤回认识，服务写结果确认后才引用 | 重复见证不等于独立事实支持；保留多种冲突证据 |
| 人格 | Ombre I 自我认知候选与本地小型 PersonaProfile 分别持有权威 | 经核对的 I 晋升与另行审核的 Profile 发布 | I 晋升不自动改 Profile；不重复存 I 正文，一次感受不能覆盖稳定配置 |
| 能力 | 能力声明、验证记录和当前可用状态 | 注册与验证后的能力状态 | 有效执行还需当前 Mandate、设备健康与新鲜验证；能力存在不等于获准使用 |

各域处理函数产生受限命令和校验结果；既有组件通过其公开写接口执行，不为统一结构而复制其数据库实现。模型与外层不持写入口。外层只负责传消息；TaskService 只拥有任务域，不能替内层决定某条信息应成为记忆。对于一个动作产生多个内层影响，core 在一个 Proposal 中列出依赖与命令。同库部分可同成同败；跨 Ombre 等组件使用控制账本记录分步结果、可见性屏障和核对状态，不能把异步完成伪装成原子提交，也不为维持单库而拒绝成熟组件。

## 3. 共同实体与版本

本地实体使用稳定 aggregateId、aggregateType、revision、schemaVersion、sourceRefs、状态及必要的隐私 / 删除标记。外部组件对象通过 backendId / nativeId 映射其真实字段，不要求 Ombre 具有同名实体表或 revision。具体载荷由各域适配 Schema 定义，不能用一个无约束 JSON 字段承载任意改变。

- `commitSeq`：每次控制账本事务递增，关联任务、回执、策略等运行域；不能代表外部记忆组件版本。
- `stateVersion`：已发布的内层组合投影版本；仅任务回执不必增加它。外部组件另带其真实版本与 freshness，不把它作为全组件 CAS。
- `revision`（本地 aggregateVersion 的持久列映射）：支持原子版本的聚合才具备 CAS；Proposal 的 readSet 在所属后端核验 expectedVersion。无关实体变化不应令所有提案失效。
- `authEpoch`、`tombstoneWatermark`：权限收窄 / 撤销和删除变化的失效依据，不能用 stateVersion 替代。
- `indexWatermark`：派生检索索引追到哪个已提交位置；索引滞后可降低完整性，不可绕过权威删除或权限检查。

外部组件没有提供可靠 revision / CAS 时，明确记为能力缺口；不能自行把时间戳或控制库序号包装成组件 CAS。记忆项仍使用稳定来源引用、已确认结果与删除屏障；正式字段与状态以根跨模块契约更新为准。

对“某集合为空”“尚无同类活动任务”这样的判断，readSet 还须包含集合版本或由唯一约束 / 同事务谓词检查保障；仅校验已读取的实体不足以阻止写偏差。实体字段和两个序号的最终语义见预留空间设计，公共契约不可各自改名。

## 4. 共享提交与读取流程

1. 控制库在短读事务内生成快照；领域组件通过自己的只读查询取得版本与 freshness，明确视图是否跨组件一致，不假装所有读共享 SQLite 快照。
2. DSH 模型或领域规则在事务外产出 Proposal；原始来源引用必须可解析、在当前访问范围内、未删除。
3. CoreCommitService 检查 Schema、调用身份、命令白名单、授权、预算、暂停、readSet 及领域不变量。
4. 在控制库短写事务中复核授权与本地版本，原子记录本地变化、审计与 outbox；组件写入在事务外受控执行，先记录待核对状态，取得可信结果后更新可见性和回执。仅同库命令可直接给出整体 committed。
5. 提交后触发派生索引、裁剪视图失效和必要通知；副作用失败不能把已成功提交的事实改写成“从未提交”。

读取通过 ViewService 和经核查的只读检索接口，不直接返回仓储对象、凭据或 SQL 能力。排序与摘要拼装不触发领域写入；hold / feel / dream、I 晋升和 them recall 等写副作用由内层另行受控调用。Ombre 后台衰减与归档属于已登记的后端维护，不冒充查询纯计算；其变化需同步组件证据和投影。若需要按访问学习，另发受控 Proposal，不借只读接口暗中发生。

## 5. 失败、删除与恢复

冲突提案返回冲突对象和允许透露的最新版本，不自动 last-write-wins 或悄悄重算。模型提案可重新读状态后重提，验证基线最多自动重评 2 次；超过上限转为等待或人工决策。同库跨域校验失败回滚；跨组件已经发生的写入不能假装回滚，保留独立结果并阻断依赖它的后续动作，核对后再继续或明确补偿。

删除先建立权威 tombstone 和失效水位，再清除受影响缓存 / 索引 / 引用；已生成但未发送的表达必须重验。证据已被删除时，依赖该证据的推断标为来源缺失或待复核，不能从旧摘要重建出被删除正文。保留期限、备份删除传播及取证例外统一使用数据生命周期政策，不由六域各自私存副本。

启动恢复基于事务数据库与兼容迁移。索引、缓存和视图可以重建；不能用模型猜测补齐权威状态。来自旧 hostEpoch 或已过期 Assignment 的回调不能提交。备份恢复后在 quarantine 中核对授权、删除和未知效果，完成校验才恢复写入。

## 6. 验收与技术取舍

V06 覆盖本地 CAS、同一 Proposal 重放、同库原子失败、跨组件 unknown / 核对、写偏差和撤权竞争；V04 覆盖只读副作用；V09 覆盖声明能力但未验证 / 已失效时不能执行；V23 验证“经历 → 内部判断 → 任务 → 结果 → 表达”可追溯且不把所有对话自动持久记忆化。

六域是职责划分，不要求六套自研实现或独立进程。Ombre 等成熟组件优先通过公开接口验证，允许分域存储；它的查询、梦境整理和写入副作用逐项分类，不能将默认写回能力直接交给 replyer。DSH 提供模型 / 会话 / scoped context，Superagent 提供任务核心，识雨补充角色、目标、来源及删除可见性规则。详见[复用核查](<../../../../../research/2026-11-01-复用核查/核心与视图.md>)。
