# 只读状态视图 · 裁剪、失效与自身状态方案

[所属区域](<../README.md>) · [跨模块契约](<../../../../跨模块契约.md>) · [core](<../00-core-主动判断/README.md>) · [全景目录](<../../../../目录.md>)

- 更新：2026-11-01（America/Caracas）。模块 ID：`views`。
- 设计状态：外层对内只读已明确；本文为视图协议和验证基线。
- 实现状态：仅方案，未建立查询服务或缓存。

## 1. 主方案与边界

由程序化 ViewService 从权威数据、受检索引和健康探测生成裁剪快照，再注入 replyer 的独立对话上下文；采用专用 Agent 路线时由 DSH Session 承载。默认 replyer 不拥有工具；需要追加读取时仅开放具名只读查询，不能选择任意表、SQL、文件路径或调用内部提交接口。core 与获准 worker 使用不同 purpose 的视图，不共享 replyer 的完整会话上下文。

ViewService 是对话和内部执行共享的受限读取入口，不要求每次先让 core 模型审阅。普通问答直接取 reply_context；任务进度读 task_status，不等待 worker 完工或另写一段解释；健康查询读 health_summary。后台结果事件只提示刷新视图，不能把 worker 原始输出直接当可发送正文。core_decision 用于判断与委派，不能因名字含 core 就扩大数据范围。路径和职责见[Core派工与对话时序](<../../../../Core派工与对话时序.md>)。

用户已确认本体界面为[运行仪表盘](<../../../../../运行仪表盘与Session复用.md>)。它组合现有受限状态/健康视图及获准的原生 Session 事件，展示当前工作阶段、来源与更新时间；页面刷新不触发模型、记忆写入或任务派发。无证据的状态与缺失缓存统计标未知，不能将模型生成说明或最后一次旧状态当作当前运行事实。需要新增视图 purpose 时先同步公共契约与权限验证。

直接复用 DSH Session.snapshotEvents / deriveMessages 与 agentCtx.systemPrompt.context，scope 生命周期由宿主负责；不新造会话快照、context 注册表或通用投影框架。业务数据通过控制 SQLite 与 Ombre 等领域组件的只读接口投影，不要求所有后端同库。视图不是数据库副本、操作权限令牌或长期记忆。读取不触发记忆强化、feel / dream、I 晋升或 them recall 的写副作用；Ombre 后台衰减与归档另记维护来源及组件变化，不是视图读取行为。

DS-Bot 的 trimToolBoundary + callIds 作为局部源码复用候选，闭包仅数组 / Set / 字符串检查，用于丢弃尚缺工具结果的历史尾部。其 snapshotOf 的 header、toolHistory 和完整主会话不能直接作为 ReadView；仅取已授权会话的冻结快照和必要锚点，不继承工具权限。无需携带历史时只注入裁剪后的业务视图，省去该助手函数。

DSH snapshotEvents 是不可变序号区间；Session.surface 是实时投影，不当作冻结快照。systemPrompt.context 在 agent scope 注册并随生命周期释放，设置 interpolate:false 保留外部文字字面值；动态上下文会成为持久 user-role 快照，因此受同一删除 / 保留策略约束。refreshContext 仅刷新运行上下文，不能代替发送或执行授权复验；scope 是注册可见性，不是数据 ACL。

## 2. 查询与返回契约

请求为 `ViewRequest{requestId, purpose, conversationId?, taskId?, query?, sourceFilter?, maxItems, maxBytes}`。actor、channel、允许资源及角色从认证调用上下文注入，调用方不能自报扩大。purpose 首版限定 `reply_context / task_status / core_decision / health_summary`；不接受自由文本 purpose 扩展权限。合成验证默认最多 20 项、64 KiB；调用者可请求更小值，不能自行增大上限。注入模型前还须服从角色 token 预算，截断范围需明确。

认证上下文中的会话按稳定 `ConversationKey` 解析：connectionId + platformConversationId + threadId? + 会话类型 / 受众范围。connectionId 为识雨登录连接配置的稳定身份，重连不变；connectorAccountRef 指本方账号，对方账号为 accountId。内部 conversationId 与 scopeHash 依赖这一身份和当前授权，不能因重连换了运行句柄就串入另一受众、复活失效视图或建立独立发送队列。

返回 ReadView 遵守跨模块契约，除裁剪后的 data 外至少可解释以下字段：

| 字段 | 含义 |
|---|---|
| viewId、schemaVersion、issuedTo、purpose | 稳定视图身份、契约版本和接收主体；viewId 不能作为 bearer 授权 |
| scopeHash | 由主体、渠道、会话 / 任务、用途及允许字段范围计算；缓存命中也必须先认证 |
| generatedAt、expiresAt | 生成与过期时间；验证 TTL 为 30 秒，最长不能超过授权期限 |
| commitSeq、stateVersion | 控制账本快照及已发布的内层组合投影版本；不表示 Ombre 等组件已追上 |
| components[] | 每项为 backendId、componentRevision?、verifiedSourceHash?、capturedAt、indexVersion?、freshness；revision 缺失不能伪造，hash 不是 CAS |
| aggregateVersions | 本视图实际依赖的聚合版本；不暴露无关私有实体清单 |
| policyVersion、authEpoch、tombstoneWatermark | 策略说明、授权收窄与已提交删除的强失效依据 |
| indexWatermark | 检索派生数据追到的已提交位置，不能表示权威数据已全部被检索 |
| freshness | current / stale / unavailable 及原因，未知用 unavailable + reason 表示 |
| sourceRefs | 允许接收者访问的来源和版本，不自动附上敏感正文 |
| data | 当前用途所需片段、冲突 / 来源缺失标记及必要状态，不包含凭据明文 |

`current` 表示各来源满足当前读取政策，不表示跨源同一原子截面，也不宣称外部世界从未改变；`stale` 可用于带时间的历史解释，不能授权新动作；`unavailable` 说明未取得可验证数据。权限不足返回统一 FORBIDDEN，不能以“没有匹配内容”泄露某私有实体存在。

## 3. 内容裁剪

| 用途 | 可包含 | 排除 |
|---|---|---|
| reply_context | 当前会话可见事实、相关记忆摘要、表达配置、任务进展与允许公开的证据 | 其他身份的私有材料、内部秘密、原始全库、写入能力 |
| task_status | 当前用户可见的 Task 状态、完成证据、unknown 原因及最后更新时间 | worker 私有提示、未授权设备路径、凭据、无关任务 |
| core_decision | 当前目标范围内必要六域状态、Mandate 概要、任务与健康依赖 | 密钥明文及范围外原始内容；模型不因是 core 就可读取所有秘密 |
| health_summary | 实例与版本、路径映射摘要、空间余量、连接 / 能力 / 任务 / 备份状态与探测时间 | 凭据内容、完整个人文件列表、不能验证的“正常”断言 |

先按权限和删除状态缩小候选，再检索 / 排序，再回查候选引用的权威 ACL、tombstone 与来源版本。模型摘要不能把较低权限来源合并进较高权限视图。每次结果有 maxItems / maxBytes 限制，溢出可分页或明确截断，不静默把缺失内容编成事实。

## 4. 一致读取、缓存与强失效

1. 检查请求角色、用途和当前授权；计算 scopeHash。
2. 控制库用短读事务读取 metadata / 本地实体；领域后端通过其只读 API 读取，附各组件真实水位或不可证明标记。后端不同步时不宣称全局快照；需要一致依赖的任务暂缓，历史表达可按权限与时间明确展示。结束事务后再做耗时推理。
3. 使用索引检索时按 indexWatermark 标记完整性，逐项对权威数据再检查删除和可见性。来源缺失、冲突或检索失败分别标注。
4. 按 purpose 投影、去敏和大小约束构造视图；默认内存短期缓存，键包含 scopeHash、查询摘要、相关版本及安全水位，不能只按用户名或问题文本缓存。
5. 正常数据变化可保留尚未过期的快照并标时间；撤权、权限收窄、删除、会话取消 / 打断属于强失效。下次取用及发送前以权威水位再检查，通知丢失不能导致旧视图继续有效。

失效事件只帮助尽快清缓存，不能作为唯一正确性机制。`authEpoch` 或权威 tombstoneWatermark 改变时，首版宁可使全部在途视图重新验证；后续可优化到依赖集合，但必须通过同样的泄露测试。索引清理完成进度与“已提交删除水位”分开记录，不等待慢清理才使视图失效。

viewId 只存最小元数据与依赖引用；视图正文默认不落盘，过期或会话结束即释放缓存。为对话恢复确需保留的已发内容由渠道保留政策管理，不能私自变成长期记忆。若宿主 Session 日志会保存注入内容，应按同一来源权限 / 保留与删除策略纳入盘点，不能只清内存缓存就宣称已删除。

## 5. 表达前的最后校验

replyer 生成 ReplyDraft 时携带 viewId、conversationGeneration、相关 Task / Goal、来源引用和生成时间。发送入口复验当前 actor / channel 授权、authEpoch、删除水位、会话 generation、任务取消和过期状态。

对话队列拥有生成和发送顺序，ViewService 不拥有队列或任务生命周期。新 conversationGeneration 使旧草稿过时，普通聊天打断不取消后台 Task；用户当前查询取消结果时可读取新视图回复。replyer 的 needs_core 只移交原输入，由程序保持 eventId / routeAttempt 去重，不能从视图内容合成授权、直接派 worker 或使用 core_decision 扩权。

- 仅普通状态变化：允许在有效期内表达有明确时间的进展；对“当前已完成 / 已连接”的断言须取足够新鲜的任务或健康事实。
- TTL 过期：重取视图，最多重新生成 2 次；持续变化时发可证实的简短进度或暂缓，不无限追赶。
- 撤权 / 删除 / 取消 / 新轮打断：阻断旧草稿，重取必要范围或丢弃；不能通过“只是聊天”绕过。
- 发送超时：交由发送 Effect 的 unknown / reconcile 机制，视图服务不补发。

## 6. 自知状态的生成

HealthService 的探测事实是自身状态依据；模型解释它们，不直接维护“我能做什么”的文字真相。必要字段为 probeId、subject、observedAt、expiresAt、probeVersion、result 和 evidenceRef；默认健康样本 TTL 为 60 秒，具体设备可更短。

| 自知对象 | 数据来源 | 无证据时表达 |
|---|---|---|
| 身份、宿主与数据版本 | 启动记录、schema 元数据、hostEpoch / installationGeneration | 显示已知版本；迁移失败标 unavailable |
| 预留空间与容量 | 已登记路径映射、实际磁盘 / 配额探测 | 路径配置存在不等于容量已预留；检测失败不回填“充足” |
| 设备与能力 | 最近探测、能力版本、验证记录、授权有效期 | 声明支持、可连接、验证有效分别展示 |
| 任务与资源 | 任务账本、预算预留、租约、unknown 年龄 | 不从会话措辞推断成功；重启待核对明确显示 |
| 备份与恢复 | 成功备份记录、校验记录、恢复演练结果 | 有备份文件不代表已验证可恢复 |
| 模型 / 服务 | 受限可用性探测、真实调用结果、费用配置状态 | 模型路由已配置不等于当前服务可用 |

健康探测本身按程序节奏和许可执行，不为获取心跳反复调用模型。状态声明不能反过来放宽动作能力；真正派发时仍用当前 Mandate、能力与执行策略复核。

## 7. 故障、替代与验证

| 情况 | 首选处置 | 替代或停止条件 |
|---|---|---|
| 索引落后 / 不可用 | 标明水位，回查权威过滤；可退回有限 SQL / FTS 检索 | 不能满足范围或完整性时返回 unavailable，不伪造完整答案 |
| 权威数据库不可读 | 返回最近已知健康元信息且明确时间；拒绝新授权判断 | 不以缓存当权威恢复源 |
| 超大查询 / 缓存压力 | 限量、分页、逐出可重建缓存 | 不把原始数据库对象直接给模型 |
| 订阅失效事件丢失 | 读取 / 发送时重新查权威安全水位 | 不依赖仅内存通知维持权限 |
| Schema / 投影版本不兼容 | 拒绝该视图，选择已验证旧版本适配 | 不猜测字段、权限或枚举 |

V04：冻结独立后台维护后，重复查询、缓存命中和排序不造成权威数据写入；并发维护测试按变更来源区分，不误把后端衰减视为查询写回。遍历跨会话 / 跨主体 / 过期 viewId 均不能扩大访问。V06：控制库并发写入得到完整本地快照；分域后端明确各自版本及未确认状态，不把部分完成视为同一原子跨域快照。V09：健康 TTL 过期或验证失效后不再宣称能力可用。V23：生成草稿后删除来源或撤权，所有未发送旧草稿被阻断，索引与缓存未清理也不能泄露。

合成验证覆盖 100 次交叉角色查询、缓存命中、索引滞后和失效通知丢失；期望越权与已删除正文泄露为 0。验证只读取元数据时的 p95 目标为 100ms（固定测试机与合成 1 万实体），若超标先检查查询、索引与视图大小，不默认新增缓存集群。该数值是验收目标，未测得。

## 8. 复用验收与证据

V04 / V06 补充验证：snapshotEvents 后继续 append 不改变旧快照；同名 context 在不同 agent scope 不串线，dispose 后注册释放；裁剪后 messages 不含未完成 tool-call，且不继承主会话 tools；ReadView 查询不会触发 Ombre dream 或其他持久学习。故障回退为只注入必要业务视图、禁用历史复制；领域后端不可读则对应部分 unavailable，不能用旧缓存补出权威正文。

V05 / V23 补充：两个后台任务运行时直接状态查询仍可排入对话槽；普通新消息不取消任务；旧任务成果草稿被取消后，新的“已取消”状态查询仍能表达。来源删除 / 撤权发生在查询与发送之间时，直答路径与 core 路径都必须阻断旧内容。
