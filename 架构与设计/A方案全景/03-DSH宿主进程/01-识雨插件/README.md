# 识雨插件 · 组合与运行边界

- 更新：2026-11-01（America/Caracas）。区域 ID：`plugin`。
- 设计状态：A 为用户已选择的宿主形态；本文给出进入验证的建议基线。
- 实现状态：仅设计与证据核查；未实现或启动运行插件。

## 1. 主方案与复用范围

一个识雨插件域运行在受信的 DSH 宿主中，复用 DSH 的模型、Session、工具注册与 guard、事件和插件生命周期。识雨只补充持续目标、六部分状态、受控提交、任务账本及设备协议适配，不新造 Agent 宿主、通用调度平台或分布式工作流服务。

复用核查后的优先验证路线为 Ombre 记忆后端与本机 SQLite 控制账本，文件承载较大的证据和产物；六域同库保留为对照与回退。A 插件、内外双层、六域职责与外层只读是用户约束，单库不是。DSH 的公开 domain 存储接口不能直接承诺跨记录事务；控制账本事务拟局部复用 Superagent Store，记忆后端按真实接口接入，不虚构跨库事务。DSH 的 Session 日志仍由宿主管理，不能替代业务账本。存储选择与验证门槛见[预留空间](<../../06-预留空间/README.md>)和[宿主底座](<../02-DSH运行底座/README.md>)。

复用技术分别承担清晰职责：DSH 提供推理与工具运行；SQLite 提供事务与查询；JSON Schema 2020-12 + Ajv 8 提供跨模块输入校验。DSH 工具参数使用宿主支持的 Schema 子集适配，不能把完整领域 Schema 原样塞进工具定义。协议校验、授权校验和业务校验三者分开。依赖版本在验证工作区锁定，不依赖浮动最新版。

## 2. 逻辑服务与所有者

以下均为插件内职责，不表示新增进程或独立模型。

| 服务 | 拥有的决策 | 不能代替的部分 |
|---|---|---|
| IngressService | 验证来源、持久受理、去重、关联会话 | 不决定长期记忆，不从消息正文生成权限 |
| GoalService 适配 | 复用 DSH ctx.goals 的 CRUD / revision CAS；控制账本持目标会话映射与 Mandate 元数据 | 不另建第二生命周期，不从模型文本扩大范围或解除暂停 |
| CoreCoordinator | 在 DSH Agent 公共生命周期与 Superagent Engine 端口上组织目标评估、预算准入及重评 | 不直接执行任意外部副作用，不直接写任务聚合 |
| ModelAssessor | 通过 ctx.agents 与 DSH Session 解释上下文并产生结构化 Proposal | 没有数据库、策略、凭据或内部状态写入口 |
| PolicyGate | 核对调用身份、Mandate、策略版本、预算、暂停与资源范围 | 不把模型的相关性判断当授权 |
| DomainHandlers | 六域服务或既有组件适配维护规则；TaskService 适配 Superagent Engine | 不能越域改写其他聚合或绕过受控准入 |
| CoreCommitService / UnitOfWork | 统一逻辑准入；控制库内原子提交账本、审计和 outbox，跨后端记录独立结果 | 不宣称控制库提交已经完成 Ombre 写入；事务内不调用模型或网络 |
| ViewService | 生成裁剪的只读视图及失效标记 | 不让读取暗中改变权威记忆、人格或关系 |
| EffectDispatcher | 读取已提交待执行记录，按当前权限派发与核对回执 | 不以 outbox 存在代替派发时授权，也不承诺外部动作恰好一次 |

TaskService 复用 Superagent Engine 状态迁移并适配公开 Task 投影，不再另造任务状态机；CoreCommitService 是共同逻辑准入与控制账本提交入口，不是各后端共用的数据库连接。调度回执、审计和健康探测可以更新自己的运行域，不能因此写六部分内层。逻辑作用域不构成操作系统级隔离；同宿主插件属于共同信任边界。外层和 worker 的可见工具、文件与进程权限必须在验证中逐项检查。

## 3. 一个闭环的接口链

```text
来源适配 → 持久 inbox → IntakeReceipt(accepted / duplicate / rejected)
                          ↓
目标 / 事件 / 健康变化 → CoreCoordinator → ReadView → DSH ModelAssessor
                          ↓                    ↓
                  PolicyGate ← Proposal(typed commands + readSet)
                          ↓
      领域规则 → CoreCommitService → 控制SQLite事务：准入 + 账本 + outbox
                          ↓
            领域组件适配（如 Ombre）→ 核对组件结果与可见性
                          ↓
                  CommitReceipt / 新版本
                          ↓
          EffectDispatcher → worker / 设备 / 对话发送 → 效果回执
```

输入受理、执行成功、内部提交与发送完成分别建模，不用同一个“成功”状态混代。读视图和事件均有稳定身份、版本、来源和作用域。公共字段由[协作基线](<../../协作基线.md>)及全景根目录的跨模块契约统一，模块不得各自创造同义版本号。

## 4. 装载、暂停与卸载

| 阶段 | 主方案 |
|---|---|
| 装载 | 先校验配置和 Schema，取得单实例资格，检查数据库与迁移版本，生成新 hostEpoch，再注册角色工具及读接口；完成恢复核对前不允许新效果派发 |
| 恢复 | 对未完成 Assignment、未知 Effect、未发 outbox 重新核对当前 Mandate 与策略；旧实例回调以 hostEpoch / fencingToken 拒绝；备份恢复额外进入 quarantine |
| 正常运行 | 事件驱动评估，宿主定时器只负责唤醒必要检查；没有触发原因和有效目标时不调用模型 |
| 暂停 | 先持久记录暂停及策略版本，再阻断新评估与新派发；发取消给执行器，区分“请求停止”和“实际停止”。用户恢复事件才解除暂停 |
| 卸载 / 退出 | 停止接收新评估，释放注册和定时器，取消模型请求，结束或记录在途状态；短事务完成后关闭仓储。无法确认的外部效果标为 unknown，不伪造回滚 |

数据迁移失败时宿主仍可提供故障说明，但识雨拒绝开始新任务。A 下宿主退出便暂停核心判断；由宿主外恢复处理，不能暗中另起一个语义 core。

## 5. 权限、数据与可观测性

每次命令执行的角色由宿主认证的调用上下文注入，不接受模型在载荷中自报 `role=core`。replyer 仅获得裁剪视图与任务状态查询；worker 仅持当前任务能力。模型和 worker 返回的 Proposal 都需程序检查，不能把 TypeScript 类型当作运行时权限隔离。

观测记录包含 correlationId、eventId、goalId、taskId、assignmentId、proposalId、commitSeq、effectId 及错误类别；不把完整提示、密钥或个人正文当默认日志。领域记录、原始证据、派生索引和审计分别依保留策略删除。性能基线记录事务耗时、积压、模型调用、有效任务、未知效果和打扰次数；模型调用次数不是主动能力指标。

## 6. 验证与替代条件

- V01：全套边界输入均按 Schema 与角色能力校验；版本不支持、额外字段和伪造角色在进入业务迁移前拒绝。
- V04：replyer 正常完成对话，但通过工具、存储、共享对象或 worker 旁路的六部分写入尝试全部失败。
- V06：控制库并发、撤权、重启不产生部分本地提交，重复 Proposal 返回原回执；跨后端处理中 / unknown 不伪装成全部提交，恢复先核对组件结果。
- V23：一个合成目标从输入、主动评估、受控执行到核验与表达可关联完整证据链；关闭宿主后无虚假继续运行。

接入细节见[本轮复用核查](<../../../../research/2026-11-01-复用核查/核心与视图.md>)：直接使用 DSH ctx.agents.create/resume、AgentHandle.dispose、Session.snapshotEvents 与 scoped systemPrompt.context；局部复用 Superagent Engine/Store 由任务与数据专题共同持有，DS-Bot 仅取纯历史边界函数。原“自行组织通用循环、快照与任务状态机”计划由这些现成实现替换，产品授权、目标与六域规则仍需识雨定义。

复用不满足验收时按已核查边界回退：DSH 工具 Schema 无法表示的约束在领域校验补齐；SQLite 事务适配不满足原子性则在验证中替换驱动，不降级成多次独立写；若必须跨宿主持续语义判断才重新评估 B。只有验证证明长期复杂工作流显著超出当前 TaskService、且引入收益足够时再比较成熟工作流引擎，当前不预建该依赖。
