## 1. 目标与方案

为每个任务提供可核查的行动依据，并在执行前持续确认“现在还允许做什么”。主方案复制 DSH-Superagent core 的 Mandate / Ticket、策略变化通知及 Policy / SourceScope 端口；由识雨适配机器可校验范围，借助 DSH 工具 guard 和最终 Broker 执行。上游现有状态处理保留；认证授权、预算、撤权与到期是明确的产品补充，不能只靠上游自然语言 Mandate。

授权来自认证用户的明确请求或已生效的持续规则；环境事件、第三方文档、模型推断、情绪和人格不能授予新权限。模型只提出候选范围，程序从既有权限中求交集。规则允许的内部整理可自动接纳；超出持续规则的外部效果形成待授权提案，不擅自扩权。

## 2. 数据契约与所有者

| 字段 | 语义 |
|---|---|
| mandateId / version | 稳定授权身份与版本化快照；每一版本内容不覆盖，范围增加必须有新的可验证依据 |
| issuer / basisRef | 认证授权主体及原始指示或持续规则的引用；不信任模型自行填写的 actor |
| policyVersion / authEpoch | 签发时策略版本与当前权限代际；执行时必须检查最新有效值 |
| allowedActions / resourceScopes / dataEgressScopes | 明确能力与操作、deviceId 与资源范围、目的地与数据类别；子任务 scope 为这些字段的规范化组合 |
| budget | token / 费用上限、工具次数、墙钟时间、并发、产物字节预算；未配置项目不能被解释成无限制 |
| validFrom / expiresAt | 明确生效和到期时间；恢复不会续期 |
| state / stateReason | active、suspended、revoked、expired；授权内容保留版本，生命周期变更另留审计 |
| inheritedFrom / scopeHash | 子任务授权引用及规范化范围摘要，便于验证不比父级更宽 |
| createdAt / version | 记录时点与聚合版本；授权状态变更也递增 version，旧版本仅供追溯 |

GoalService / PolicyGate 拥有 Mandate 与授权生命周期规则；TaskService 只消费、复核授权并维护预算预留。各自的类型化命令由 CoreCommitService / UnitOfWork 统一提交。核心只读视图提供范围摘要与拒绝原因，不暴露密钥或后台访问令牌。scope 使用稳定对象 ID 或规范化资源引用，不以任意自然语言字符串直接充当文件权限。

## 3. 输入、输出与关键流程

输入 `AuthorizeTaskRequest` 包括 sourceEventIds、goalId、requestedScope、completionSpec、预算请求及幂等键；调用者身份由运行通道绑定。程序按以下顺序判定：

1. 验证来源身份、事件去重、授权主体与规则适用范围。
2. 计算“用户 / 规则范围 ∩ 系统策略 ∩ 目标限制 ∩ 当前能力范围”；命中禁用项立即拒绝。
3. 检查任务目的和参数是否匹配可执行范围；语义不明确时生成解释 / 补充需求，不让模型自动扩大接口权限。
4. 在事务中写 Mandate 版本、Task 与初始动作；返回任务受理结果（taskId、mandateId、admitted / duplicate / rejected、reasonCode、commitSeq）。Ingress 的 IntakeReceipt 仅证明原事件已进箱，两者不能混用。
5. 每次分配 Assignment、派发 Effect、恢复 Task 时重新加载当前 authEpoch、状态、到期与资源预算。旧快照不能替代当前校验。

范围变更、到期和撤权由确定性命令触发并生成事件；主动目标暂停与撤权分别记录。scope 扩大需要新的授权依据；scope 缩小递增 authEpoch，未派发动作失效，已经发出的动作进入停止 / 核对路径。

## 4. 预算与授权竞争

预算采用同库“预留 → 结算 / 释放”，分配前先预留估计最大资源；实际消耗以宿主或执行端回执结算。结果未知时保留预留，不能当作零费用释放后继续无限派发。模型费用估算误差超过预留时立即暂停新增调用并记录差额，不能追溯取消已经发生的费用。

所有派发事务检查 authEpoch 和 Mandate.version。派发到远端后仍存在撤权竞争窗口；远端应验证短期命令的有效期、当前承认的宿主代际与资源 token。离线端无法即时得知中心撤权，默认仅允许已开始单步在原约束内收尾，到期不得开始下一动作；机器人停止策略由设备本地优先执行。

## 5. 失败、恢复与数据生命周期

- 来源身份不可验证、策略缺失、预算不明确或参数超范围：拒绝或等待处理（Task.waiting，waitReason=blocked），提供原因码；不自动改用更高权限工具。
- 暂停可经合法 resume 恢复；revoked 或 expired 不可因新对话、重启、恢复备份自动变回 active。
- 权限校验异常时停止新增副作用；状态查询、故障证据记录、停止请求仍可在独立受限通道执行。
- 授权引用避免复制私密原文；授权版本、撤销记录与相关任务须按数据专题统一保留。需删除原始文本时保留最小不可逆摘要和必要审计身份，不声称因此可无限保留个人资料。
- 旧备份恢复的授权先处于隔离状态，核对当前用户停用、已撤销设备和 authEpoch 后再恢复。

## 6. 验证与通过条件

全局验收见 [V10](<../../../../验证与验收.md#v10>)、[V23](<../../../../验证与验收.md#v23>)。下述数值是合成验证场景的初始配置，不是已测性能。

V10 至少覆盖：到期前后临界派发、授权缩小与并发执行、伪造 actor、子任务扩大 scope、同一预算并发预留、暂停后重启、旧备份携带旧授权。通过条件为所有越界请求零成功派发；可证明 dispatch 前已撤权的请求零外部效果；已发出的动作如实标明取消竞争及回执，不要求不可能的瞬时远端撤回。

验证预算输入固定为 20 次工具动作、2 个 worker、1 MiB 单产物、10 分钟任务期限，参数在实验计划中记录；这些是验证夹具，实际部署由资源配置确定。并发 20 次预留不得突破总额，未知消费不得提前释放预算。

## 7. 替代与证据

已有任务只要求固定只读资源时，可从极小能力白名单开始，无须先构建通用 ABAC 产品。若形成大量跨租户策略、策略委派与统一组织审计需求，再评估成熟策略引擎；仅升级策略求值层，仍保留 Mandate 记录和派发前复核。当前不自建完整 IAM 服务。

DSH-Superagent 固定 `6337fc823ce20251c8de8085948165c81aaa701e`、MIT；core 纯域闭包与任务模块共享一份副本，不为授权模块再复制一套状态引擎。GoalService / PolicyGate 将当前机器范围提供给既有 Policy 端口；政策变更沿用 Engine.policyChanged，派发前再次查权威授权。上游 GitHub Settings / allowlist 不作为识雨授权数据库。

复制接口、运行依赖、许可、同步事务和失败隔离补丁见[本轮复用核查](<../../../../../../research/2026-11-01-复用核查/任务执行.md>)。Goal 生命周期沿核心专题采用 DSH ctx.goals，每个持续目标使用专用 Session；GoalService 为适配器，Mandate/预算为补充元数据，不再建立第二 GoalStore。任务库里的授权版本是当前派发验证所需的记录，与独立后端之间必须核对版本；跨库异常时停止新副作用，不回退到旧授权。本轮无源码接入或运行实测。
