## 运行基线

本轮[宿主复用核查](<../../../research/2026-11-01-复用核查/宿主与依赖.md>)优先保留原生服务与配置：无需另写模型网关、Agent loop、工具执行器、日历解析、插件兼容装载或配置修复框架。领域事务小内核按精确来源局部复用；只有识雨自己的身份/授权/预算与状态规则保留产品代码。

采用 **一个专用 DSH Web 宿主 + 识雨插件 + 一个权威领域数据库**。Web 界面是可关闭的客户端；关闭浏览器不停止核心，退出 DSH 主进程则暂停判断与调度。复用 DSH 的 Agent、Session、模型适配、工具执行、Web 认证与生命周期，不另造 Agent 宿主。

首验证在当前 macOS 用户会话下运行 Web profile，监听 `127.0.0.1`，使用 `--no-open`。专用 `DSH_HOME` 和 profile 与个人默认宿主分开；数据位置由预留空间清单决定。上述是验证部署规格，本轮未创建这些路径或服务。

## 组件与接口

[识雨插件](<01-识雨插件/README.md>)拥有领域服务；[DSH 运行底座](<02-DSH运行底座/README.md>)提供宿主适配。模型、工具与 Session 句柄不穿透领域边界：业务只传稳定对象 ID、授权范围与契约版本。

领域数据库的同步 SQLite 调用由宿主内一个专用 DB WorkerThread 承载，通过受控命令队列提供异步接口；权威记录、基础 FTS5 更新、事件与 outbox 在同库事务中提交。该执行线程不运行另一核心，也不增加独立部署进程。

主 Web 宿主的文件系统与 subprocess provider 保持本机语义。远程设备通过 DeviceGateway 的独立执行适配接入，不把全局 `ctx.fs` 切换为某台远程机；上游 SSH provider 的独立作用域适配须先验证，失败则使用设备方案的受限 OpenSSH wrapper。全部领域身份、世代和回执遵守[跨模块契约](<../跨模块契约.md>)。

启动依赖顺序为：配置与受信清单 → 领域库版本/完整性/单实例检查 → 权限与工具注册准入 → HostAdapter 服务 → 恢复任务与待发送记录 → 恢复队列 → 发布 ready。模型不可用时仍可显示状态和接受暂停，不能宣告完整可执行。

停止顺序为：停止接单与新派工 → 取消等待和模型请求 → 将正在执行但未核对的动作保留为未知 → 刷新领域事务与 DSH Session → 释放句柄。DSH 此版本优雅停止预算为 5 秒，识雨内部 drain 预算取 4 秒；超时后下次启动以账本恢复，不假定所有外部动作都终止。

## 部署边界与替代

首阶段不公开 Web 监听，不引入反向代理、容器集群或第二核心。需要远程访问时沿 DSH 已有认证入口另做部署验证，不能把 `--public-url` 当鉴权。

macOS LaunchAgent 的生命周期受用户登录、睡眠和系统权限影响；注销后继续运行不是本方案默认保证。如果验证目标升级为无人登录持续运行，迁移同一 DSH Web 宿主到 Linux systemd，Mac 保留设备执行器，仍属于 A。桌面 App 可用于交互体验对照，只有固定版本的 profile、插件装载与退出语义验收通过后才作为主机替代；不选一次性 headless 或缺少审批设施的 sdk-minimal 作守护宿主。
