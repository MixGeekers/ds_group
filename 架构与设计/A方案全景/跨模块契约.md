## 1. 所有者与调用边界

| 逻辑服务 | 所有者与写入范围 | 允许的调用者 | 不允许的行为 |
|---|---|---|---|
| IngressService | 输入 inbox、来源去重、接收回执 | 经身份与大小校验的渠道、设备和定时入口 | 将输入正文转换为授权事实或直接写长期记忆 |
| ConversationService | DialogueTurn、ReplyDraft、conversationGeneration 等局部对话运行状态 | 经校验的输入与表达流程，通过受限 UnitOfWork | 把维护对话状态权限扩大为内层写权 |
| GoalService / PolicyGate | DSH Goal为生命周期权威；控制库维护映射、Mandate与确定性授权 | 用户控制入口、core 的受限提案 | 第二份独立Goal状态机，或模型自行扩大范围/撤销暂停 |
| CoreCoordinator | 决定何时推理、生成提案与委派意图 | 已接受的事件与到期目标 | 在数据库写事务中等待模型或网络 |
| CoreCommitService / UnitOfWork | 控制域受控事务入口；跨服务命令只原子登记操作与出箱意图 | 各域具名服务，使用各自受限命令 | 任意 SQL、无类型 patch、模型获得数据库句柄，或把远端调用冒充本地事务 |
| TaskService | Task、Assignment、执行预算与合法状态迁移 | core、控制入口、经核验的执行回执 | 以任务完成为由任意修改记忆 / 人格 |
| ViewService | 裁剪快照、状态查询、失效通知 | replyer、诊断界面、获准任务 | 用查询接口隐式变更权威记忆权重或绕过权限 |
| EffectDispatcher | outbox、发送尝试、外部动作核对 | 仅已提交的 Effect | 在提交前调用外部动作、对未知的非幂等动作盲重放 |
| DeviceGateway | 能力与设备绑定、执行路由、回执标准化 | dispatcher、能力探测任务 | 形成第二个权威核心或直接改内层状态 |
| MemoryAdapter / 所选记忆服务 | 服务独占记忆/感受主副本；适配器管理命令、引用与核对 | 获准的内部命令；ViewService只取受限结果 | 双写第二份权威记忆、把dream当纯查询、未核对就重放unknown写入 |
| Health / CheckpointService | 探测事实、状态快照、一致检查点 | 调度、恢复控制入口 | 用模型生成的自述替代探测，在线直接复制单个 WAL 数据库文件 |
| RunGate / OS supervisor | 期望运行状态与进程恢复 | 本机控制入口、OS 进程管理 | 用户停用后继续拉起，代 core 进行语义决策 |

服务名首先表示职责。协调与授权在插件内，Ombre等后端可以独立进程；它们不是第二个决策核心。各权威后端只有明确所有者和受控写入路径；服务后台衰减、索引和用户管理入口须另列受委派的变更来源。不能只限制模型工具就忽略Dashboard或文件编辑。“由 core 控制提交”不表示每次写账本都调用 core 模型。

控制SQLite的同步绑定运行在宿主内专用DB WorkerThread，以消息传递具名领域命令和结果；不传任意SQL或可执行回调。它不属于智能worker角色。本地策略复核、CAS和不变量在同一事务内完成。远端后端必须有自己的版本/去重保证或经验证的限定写入口，不能将本地校验外推成跨服务CAS。

## 2. 公共类型、版本和身份

- `schemaVersion`：契约版本，初始 `1`；新增可选字段可兼容，修改语义或必填字段需要新主版本和适配器。未知命令、未知枚举、未知必填语义拒绝执行。
- 实体 ID：无业务含义的随机唯一标识；来源已有 ID 另存，不将文件名或聊天顺序当稳定身份。时间使用带时区的 UTC 字符串；租约时限由中心判定，不信任设备自报时间。
- `Actor`：`principalId, kind(user|service|device), authenticatedBy`。它由连接适配器和认证结果构造，模型文本不能设定身份。单用户起步仍保留主体标识，不建设多租户平台。
- `SourceRef`：`sourceId, revision, contentHash?, observedAt, trustClass`。来源、原始证据、推断与模型生成内容分开；引用已删除内容时返回墓碑状态。
- `PayloadRef`：受控对象 ID、哈希、大小、媒体类型与隐私级别。允许小型合成载荷内嵌；真实大对象走存储服务，不接受任意路径作为对象引用。
- `ResourceRef`：规范化的对象 / 设备 / 会话身份加允许范围；设备路径必须绑定 `deviceId`。写文件前验证规范路径、授权根、符号链接和目标类型；仅字符串前缀检查不构成访问控制。

| 版本 / 世代 | 何时变化 | 用途 |
|---|---|---|
| `commitSeq` | 每次控制账本成功事务递增 | 本地记录、日志与outbox对齐；不表示记忆服务已经提交 |
| `stateVersion` | 已发布的内层组合投影更新时递增 | 投影版本；不替代各后端revision，也不表示跨服务原子时刻 |
| `componentVersions` | 后端版本、来源摘要或经验证的导出版本变化 | 逐后端/对象追踪来源；不支持原子版本的后端明确标记，不伪造CAS |
| `aggregateVersion` | 某个聚合合法更新时递增 | CAS 的实际比较对象，避免无关任务更新导致全局冲突 |
| `collectionVersion` | 涉及跨实体集合谓词的成员 / 规则变化 | 防止仅比较单行而遗漏新增成员、身份合并等竞态 |
| `policyVersion / authEpoch` | 策略修改 / 授权收窄或撤销 | 执行前再授权及已有视图强失效 |
| `hostEpoch` | 每次宿主启动产生新值 | 拒绝旧进程、旧回调和旧 Assignment 的提交 |
| `installationGeneration` | 新安装或备份恢复时生成新值 | 防止从旧备份恢复后复用旧身份世代和 fencing 值 |
| `conversationGeneration` | 新输入合并、打断、取消使旧回复过时 | 发出前拦截旧回复 |
| `indexWatermark / tombstoneWatermark` | 派生索引消费进度 / 权威已提交删除水位 | 新删除一提交就使旧视图失效；物理清除进度另记 purge / consumer watermark |

`readSet` 在拥有该聚合的后端校验，`baseStateVersion` 解释使用的组合投影，不要求无关更新都造成冲突。本地跨实体唯一性由数据库约束或 collectionVersion 保护；跨后端不变量通过串行操作、核对和明确的未完成状态处理，不声称分布式事务。缓存不能仅凭 stateVersion 宣称授权和删除状态有效。

## 3. 输入与接收回执

### EventEnvelope

| 字段 | 约束 |
|---|---|
| `eventId, type, schemaVersion` | 稳定身份与注册事件类型；相同来源重送不创建新事件 |
| `occurredAt, receivedAt` | 分开来源声称时间与中心接收时间；按中心时间判断过期与租约 |
| `source, actor` | 来源 URI / 适配器标识及经验证身份 |
| `correlationId, causationId?` | 同一业务链与直接原因；不能代替权限依据 |
| `conversationId?, goalId?, taskId?` | 明确关联，缺省不通过模型猜成既有任务授权 |
| `payloadRef, privacyClass, expiresAt?` | 限制大小、保留、可外发范围和处理有效期 |

入箱事务内写来源去重键、事件和接收状态。唯一键优先使用规范来源 + 平台独立 sourceEventId；仅有 sourceMessageId 的渠道必须把 revision 和 event kind 纳入事件键，以区分创建、编辑与删除。来源无法给稳定 ID 时由适配器记录接收键及重传映射，正文哈希只能作为辅助，不能把两条合法相同消息合并掉。

`IntakeReceipt = {eventId, status: accepted|duplicate|rejected, receivedAt, reasonCode?, commitSeq?}`。accepted 只证明受理；不证明记住、执行或完成。队列压力达到上限时明确返回可重试拒绝或已受理待处理，不丢弃后仍报成功。

渠道边界优先采用 [CloudEvents 1.0.2](<https://github.com/cloudevents/spec/blob/v1.0.2/cloudevents/spec.md>) 的 JSON 事件格式；`id/source/type/time` 映射到内部字段，`specversion=1.0` 与本领域 `schemaVersion` 不同。内部 camelCase 对象不是 CloudEvents 原格式；身份与权限仍需额外验证。

## 4. 目标与授权

`Goal`生命周期直接使用DSH `ctx.goals`，每个持续目标绑定一个专用Session，权威引用为`GoalRef{id,revision}`，原生phase为`active|paused|blocked|complete`。控制库的`GoalBinding`只保存`goalId,sessionId,goalRef,owner,scope,completionCriteria,priority,budget,reviewAt,expiresAt?,metadataVersion,stopReason?`及观察投影，不再维护第二套独立Goal.state。

取消/到期为识雨控制命令及停止原因，先关闭本地派发资格，再按已核验的DSH disarm/pause/clear语义处理并保留引用墓碑。恢复需原生状态、当前授权和本地停止记录一致；普通定时输入不能重开已停用目标。DSH Goal存储在Session log，与控制SQLite不共享事务：命令登记、按revision调用、读取核对、确认回执依次执行；中断标unknown，不伪报同步完成。Goal原生armed也不能绕过识雨的每轮准入，不默认加载自动continuation driver。

`Mandate` 必备：`mandateId, goalId?, issuer, basisRef, allowedActions, resourceScopes, dataEgressScopes, budget, validFrom, expiresAt, policyVersion, authEpoch, state, version`。状态为 `active|suspended|revoked|expired`。预算保留、扣减、释放通过任务账本记录；不把聊天描述中的“随便做”当作无限权限。

动作注册项声明 `read_only|idempotent|reconcilable|non_replayable` 类别、支持的平台、所需授权、参数 schema、结果 schema 与核对方法。不是所有工具都有可重试性。作用域必须收窄到能力、资源、接收方和数据外发位置，不能只比较一个工具名称。

授权在受理、派发、外部动作开始和内部提交四处按需复核；等待期间到期或撤销的任务不因已经入队而继续执行。已产生的外部副作用不能由撤权自动回滚；进入核对与必要补偿流程，补偿也需要自己的授权。

## 5. 提案与受控提交

`Proposal` 必备：`proposalId, schemaVersion, actor, role, sourceRefs, baseStateVersion, readSet[], policyVersion, idempotencyKey, commands[], expiresAt`；工作执行提案另带 `taskId, assignmentId, hostEpoch, installationGeneration, fencingToken`。`readSet[] = {aggregateType, aggregateId, expectedVersion}`。每个 `command` 必须是领域注册命令，不接受任意 SQL 或无类型对象合并。

本地提交顺序：schema 与大小校验 → 验身份 / 命令范围 → 验有效期、暂停与策略 → 验执行世代及 fence → 验本后端readSet / 集合约束 → 校验领域不变量 → 短事务写本地状态、版本、来源记录、回执与outbox → 提交后唤醒派发。网络、模型、文件下载和慢扫描在事务外。局部复制的atomic回调必须同步；SAVEPOINT/回滚失败及afterCommit错误须通过故障验证，不能原样复制后宣称可靠。

`CommitReceipt = {proposalId, status: committed|rejected|conflict, commitSeq?, stateVersion?, changedAggregates?, effectIds?, reasonCode, retryClass}`。重复相同提案返回既有回执；同一 idempotencyKey 携带不同命令摘要拒绝。conflict 重新读取后生成新提案，不以覆盖模式强行写入。

内部提交成功和外部动作成功分别记录；不能以事务 rollback 声称已发出的消息或设备动作被撤销。

### 记忆服务操作

跨服务命令登记 `MemoryOperation = {operationId, backendId, proposalId, commandDigest, sourceRefs, expectedComponentVersion?, mandateRef, status, backendReceiptRef?, verificationRef?}`，状态为 `approved → dispatching → applied|unknown|rejected`。`approved`只表示本地批准入账，`applied`必须有后端效果与来源核对；跨域操作回执不能与已完成记忆提交的CommitReceipt混用。

跨多个后端的commands不得承诺全成或全败，拆成具名子操作并保留各自结果。重复operationId同内容返回原记录，异内容拒绝；这只解决本地去重。后端必须提供可验证去重/结果查询或限定补丁，才可自动恢复写入；否则写后断连进入unknown，停在核对而不再次hold。已有Ombre接口尚未被证明满足此契约，不虚构现成CAS。内容哈希可用于核对版本，不能替代后端原子比较更新。

## 6. Task、Assignment 与 Effect

| 对象 | 最小内容 | 责任 |
|---|---|---|
| Task | taskId、goalId、mandateId/version、completionSpec（类型化 check 列表）、输入引用、预算、状态、version | 稳定工作事项；完成由结果核验决定，区别于 Goal 的 completionCriteria |
| Assignment | assignmentId、taskId、attempt、workerRole、sessionBinding、leaseExpiresAt、fencingToken、hostEpoch、installationGeneration、状态 | 一次执行资格；同一任务可以有新的执行实例 |
| Effect | effectId、origin、动作类型、resourceScopes、参数引用、参数摘要、幂等键、重放类别、授权版本、期限、状态 | 一次计划产生的外部效果，和对应领域变更同事务入账 |
| Receipt | receiptId、effectId、设备/服务身份、观察时间、结果状态、外部操作 ID、证据引用 | 区分投递、开始、实际效果与核验结果 |

`Effect.origin` 为判别联合：`task{taskId, assignmentId}` 或 `dialogue{conversationId, turnId, conversationGeneration}`。普通 replyer 回复不虚构 worker Assignment；其 Effect 仍绑定有效 Mandate、目的地与允许外发范围，并由受控 ConversationService 创建。数据库可展开为可空列，但必须校验恰有一种完整来源。

任务受理返回 `taskId, mandateId, status: admitted|duplicate|rejected, reasonCode?, commitSeq?`，不复用只说明事件进箱的 IntakeReceipt。终态任务需显式重做时创建新Task并关联前序；非终态恢复保留原Task，创建新的Assignment。

Task 对外规范状态：`queued|running|waiting|succeeded|failed|cancelled|unknown`。内部可细化等待原因，但须映射到这些状态。`succeeded` 需要完成条件与证据；`unknown` 表示可能已产生效果，不能自动改成 queued。Assignment 租约过期只取消提交资格，不证明旧进程或设备动作停止。

Effect 规范状态：`pending|dispatching|succeeded|failed|unknown|cancelled`；派发尝试单独记录。pending 可以取消；dispatching 后若无法证明尚未执行，进入 unknown / reconcile。幂等与可核对类别按注册契约重试；non_replayable 在不确定后等待证据或控制入口裁决。

可靠性目标是“持久化、至少一次投递、幂等处置和可解释的不确定性”。数据库唯一键和 outbox 不保证任意远程动作恰好一次。支持端侧去重的设备必须持久保存请求键及参数摘要，返回旧回执；不支持的工具不享有自动重放承诺。

租约校验值包含 installationGeneration、hostEpoch 和单调 fencingToken。恢复备份产生新世代，旧回执进入隔离核对；不能把旧数据库里的计数简单加一就当全球更新的 fence。默认不在中心失联后继续新动作；允许离线继续的能力须单独规定任务期限、停止规则和端侧回执。

## 7. ReadView、表达和设备能力

`ReadView = {viewId, schemaVersion, scopeHash, issuedTo, purpose, generatedAt, expiresAt, commitSeq, stateVersion, aggregateVersions, components[], policyVersion, authEpoch, tombstoneWatermark, indexWatermark, freshness, sourceRefs, data}`。`components[]`记录`backendId, componentRevision?, verifiedSourceHash?, capturedAt, indexVersion?, freshness`；revision缺失不能伪装成全局版本，hash也不是CAS。`freshness`标示current/stale/unavailable及原因；current指各来源满足当前读取政策，不代表跨源同一原子截面。

ViewService 从权威状态和已校验派生索引组装视图。模型只收到所需片段；replyer 默认无工具，由程序注入视图。确需追问查询时只开放只读窄接口，调用仍校验主体与范围。视图不是整个数据库副本。

产生回复后，发送入口再次核对 `conversationGeneration`、授权与删除世代、关联 Task / Goal 取消状态。过期回复丢弃或重生成；发送完成回执与内部提交回执分开。对于来源和目的地不支持发送去重 / 查询的渠道，超时发出状态为 unknown，不能立即补发一条可能重复的消息。

`DeviceCapability = {deviceId, capabilityId, capabilityVersion, protocolVersion, executionMode, supportedActions, parameterSchemaRef, requiredScopes, replayClass, health, observedAt, verifiedAt, credentialRef, resourcePolicy}`。executionMode为`direct|gated`，表示直接调用现成工具或具有端侧资格校验；健康与能力声明分别记录。远程对象引用必须绑定设备身份，配对不自动授予全机控制。

内部DeviceCommand封套携带Effect/Assignment与installationGeneration、hostEpoch、整数fencingToken，受信适配器校验后映射现成工具参数；不要求所有SSH/MCP/GUI工具原生理解这些字段。gated执行器在端侧校验资格；direct工具只保证中心授权、受限单次派发与结果核对，不能宣称端侧fencing。无停止/去重证明的unknown动作锁住相关资源，不离线新增、不自动重放、不将其改派给另一个worker。持续排队或跨重启续接的有副作用执行需端侧gate后才启用。

回执仅更新匹配的执行记录。GUI等独占资源另带resourceEpoch，不与fencingToken混成复合字段。机器人高频控制与急停仍由本地系统负责。平台和能力未知时禁用对应能力，不以连接成功推断全控制。

## 8. 错误、升级和可观测性

统一错误结构：`code, message, correlationId, retryClass, detailsRef?`。默认不返回凭据或敏感正文。核心错误码至少覆盖：`INVALID_SCHEMA, UNAUTHENTICATED, FORBIDDEN, EXPIRED, PAUSED, BUDGET_EXCEEDED, VERSION_CONFLICT, STALE_FENCE, RESULT_UNKNOWN, OVERLOADED, STORAGE_FULL, DEPENDENCY_UNAVAILABLE, INCOMPATIBLE_VERSION`。

`retryClass` 为 `never|after_delay|after_refresh|after_reconcile`；只有 after_delay 可按有上限退避直接重试。after_refresh 重新读取并提出新请求；after_reconcile 先核对外部事实。不能把所有 5xx 或进程退出统一视为可重放。

日志以 correlationId / taskId / effectId 串联。跨进程追踪可携带 [W3C Trace Context](<https://www.w3.org/TR/2021/REC-trace-context-1-20211123/>)；trace ID 不承担业务幂等或授权。默认本地结构化日志与运行状态视图，未来观测平台仅在测量需求出现后接入，不新增常驻观测集群。

记录入箱延迟、队列长度、有效任务完成率、unknown 年龄、冲突率、重试次数、预算占用、模型耗时、空间余量、索引水位、最近备份与恢复结果；禁止仅用调用次数评价主动性。真实正文与密钥不进入普通诊断日志。

契约使用 [JSON Schema 2020-12](<https://json-schema.org/draft/2020-12>) 和 Ajv 严格校验作为验证基线；DSH 工具的受限 schema 用单独适配。schema 校验不替代语义权限；版本升级在隔离副本检查兼容，未知主版本拒绝运行而不是猜字段。

## 9. 三条必须通过的事务与恢复路径

1. **输入 → 内层 → 表达：**重复输入命中相同 IntakeReceipt；core基于有版本视图提出命令；本地提交或后端操作核对完成后再发布新投影；replyer读取含来源版本的视图，发送前核对generation；可分别查询受理、本地批准、后端应用与发送结果。
2. **任务 → 设备 → 迟到结果：**事务创建 Task / Assignment / Effect；设备按能力执行；中心中断、重启并产生新 hostEpoch；迟到回执先核对身份与世代，作为证据处理，不能覆盖新的执行权或直接变更内层。
3. **删除 → 备份恢复：**提交 tombstone、撤销相关视图并取消含敏感引用的待发动作；索引与备份按生命周期清除；恢复旧检查点进入 quarantine，应用最新独立删除 / 撤权记录并核对外部任务后才开放派发。缺少较新控制记录时仅开放无业务正文的诊断与人工恢复；ReadView、模型上下文和对外读取全部阻断，不自动恢复旧授权。

## 10. 权限保证的实际限度

同进程 DSH 插件属于可信代码。工具可见性、role allow-list 和提示词都不是操作系统级隔离。DSH 的自注册工具与自定义 executor 必须经过插件装载准入，所有动作走统一执行时策略核查；禁止通过另注册同名工具或通用 shell 绕过。

不信任的扩展代码需以独立受限进程及最小文件 / 网络权限执行，验证失败前不装入权威宿主。外层无 DB 引用、无写工具、无原始数据根访问；但本方案不声称能抵御同进程恶意插件任意读内存。若该威胁成为必须支持的要求，应升级进程隔离，重新评估 A 的部署边界。

验收对应 V01、V03–V06、V10–V19、V21–V24，具体场景、合成数据、门槛和证据见[验证与验收](<验证与验收.md>)。

## 11. 渠道、订阅、路由与通讯录补充

2026-11-01 细化。完整流程见[连接、订阅与派工总方案](<连接、订阅与派工总方案.md>)。以下为识雨设计契约，不是上游已经公开的同名 API。

| 职责 | 权威记录 / 允许动作 | 边界 |
|---|---|---|
| ChannelBridge | 渠道账户、入站去重、原生消息映射、发送回执；映射现成连接层到 EventEnvelope / Effect | 无 Goal/记忆/订阅写权；桥故障不能回落到另一个自主 Agent 回复 |
| IngressRouter | 原 eventId 对应的路由决定与升级记录；控制命令、只读问答、core 判断分流 | 规则只处理明确结构/已知条件；无法判定的自然语言转 core，不能猜出授权 |
| SubscriptionService | 订阅定义/修订、来源绑定、游标、触发记录；时间规则用现成解析器与宿主触发机制 | core 可在有效 Mandate 内自主登记/修改/停用；来源事件不能创建新权限，replyer 不能写订阅 |
| ContactService / IdentityResolver | 人物、平台账号、发送端点、已验证身份绑定、合并/拆分与联系偏好 | 名字/手机号候选/模型认识不自动构成已验证绑定；人物合并不合并聊天可见范围 |

**渠道身份：**`connectionId`是识雨一项渠道连接配置的稳定ID，绑定provider、登录服务账号及租户/工作区；重连不改变它。`connectorAccountRef`映射OpenClaw accountId或平台SDK凭据配置；通讯录`ParticipantAccount.accountId`表示对方账号，三者不能互换。入站去重使用connectionId、平台原生会话/消息标识及事件类型（按平台实际ID作用域确定）。`ConversationKey`为connectionId＋platformConversationId＋threadId（如有）＋会话类型/受众范围，不能使用临时socket/登录实例作为串行键。平台senderId另含namespace和identityType，不能当全球personId。旧字段channelAccountId/channelInstanceId仅在明确映射为稳定connectionId时使用。

**只读快路：**已有受众限定视图足够的普通问答/状态查询可直接调用 replyer。允许 replyer 返回 `needs_core{eventId,reason}` 作为程序接管提示；它没有 TaskSpec、Mandate 或订阅写权限，不产生新授权。程序以原 eventId 去重并记录一次升级，同一路由原因不再回送成新输入；仍不足时澄清。需要执行、持久变更或目标判断时进入 core。控制命令优先绕过模型等待，不绕过可信来源认证。

**订阅：**定义和运行句柄分开，持久定义含来源/时间条件、目标或任务引用、Mandate、范围、预算、期限、版本、静默与补触发策略。匹配条件使用允许的声明式操作，不接受任意 eval/动态代码。登记、更新、触发、派发分别复查授权；trigger 记录来源事件/时隙和订阅修订，事务内去重后才发入 inbox。具体 schema、状态和时间语义由[订阅专题](<时间与事件订阅.md>)给出。DSH Schedule 的 Agent inbox 投递不能直接当 callback；专用无模型接纳路径必须先验证。

**通讯录和发送：**联系人存在、同人绑定或“朋友”认识都不授予主动联系权限。发送时解析明确 endpointRef，并复查渠道账户、受众、成员状态、同意/屏蔽、任务/对话授权和速率；收件人不确定先澄清。Ombre them 为可选认识后端，不能替代通讯录、平台身份凭据或发送策略。

**恢复与备份：**控制库备份覆盖订阅修订/游标/trigger、桥接回执/去重、通讯录与端点偏好；渠道连接器自己的登录状态、原生消息映射和版本列入独立恢复组件，凭据仍由专门设施管理。恢复时先核对原账号、订阅授权、目标暂停与未知发送；不能只恢复目标就自动重新登录或补发历史消息。

## 12. 多频道话题扩展建议

本节是[多频道话题与后台协作](<多频道话题与后台协作.md>)提出的待实现契约扩展，不代表既有 schema 或 DSH API 已有同名字段。

- ConversationKey 继续定位平台会话、原生 thread 和受众；拟议 topicId 只组织讨论、事件引用与业务对象/Task 关联，不能作为授权。一个会话可有多个话题，一个话题可关联多个获准会话；话题关联不合并原生历史、Task ownership 或预算。
- ConversationService 拟保存话题关联修订、受众限定的 Session 绑定与输入/草稿映射；不复制 DSH inbox 或模型历史。replyer Session 按 conversation、必要的 topic 与可见范围稳定复用，core/worker 仍分别按 Goal/事项与 Assignment 绑定。
- 独立话题并行前，必须配套细化 conversationGeneration 的作用域、草稿和 Effect 的绑定引用；共同授权/成员变化仍使全部受影响绑定失效。当前字段扩展未完成前，同一会话保守串行，不能只新增 topicId 就跳过现有发送门禁。
- worker 结果经核验后发布 Task 变化；外部事件经来源、订阅和授权校验。背景变化使相关视图过期，下一次生成按需读取；主动通知按既定目的地和用途裁剪，不广播到全部关联 Session。通知去重、路由修订、已送达记录和 unknown 恢复共同验证。
- 合并/拆分只修订关联与后续路由，保留来源及既有 Task/Effect 身份；当前调用和发送复查绑定修订。恢复需核对原生 Session/inbox、话题关系、订阅游标和未确认效果，不能重播所有历史通知。

## 13. 统一发布订阅接口补充

2026-11-02 设计补充，详细规则见[统一事件接口与发布订阅](<统一事件接口与发布订阅.md>)。以下扩展尚未实现，不是 DSH 原生 API 的同名声明。

- Agent tools 和可信组件 API 共用事件类型目录、发布接纳、订阅及回执服务；EventEnvelope、IntakeReceipt、SubscriptionSpec/Delivery 和既有 outbox 继续承担原职责，不建立第二权威消息库。
- 事件类型目录定义 schema、可过滤字段、发布资格与事实含义；source/actor 由运行时核验。Agent 报告观察和结果，Task 权威组件在核验后发布完成事实；事件不能替代业务命令或提升授权。
- SubscriptionSpec.target 拟扩展为注册组件 handlerRef 或受控 Agent 业务绑定；deliveryMode 区分组件处理、背景待更新与原生 Session 续接。背景模式不直接追加会自动执行的 inbox，Agent 目标继续核对现有 Goal/Assignment/话题范围与当前预算。
- 事件按独立订阅扇出，每条投递单独记录；同一 deliveryId 的并发实例竞争消费资格，故障恢复允许至少一次尝试。重复调用通过稳定 deliveryId、提交资格和既有 Effect 幂等规则控制，unknown 先核对。发布受理、目标受理、业务处理完成与外部效果回执分开；取消、崩溃和有限回放窗口沿用既有恢复核对。
- 订阅起始水位/回放政策、当前状态与后续变化的竞态、防循环、背压和失败消费者隔离须验证；同一发布幂等键换载荷拒绝，暂停恢复不清空已命中的去重身份。
