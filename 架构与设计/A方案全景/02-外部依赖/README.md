## 依赖基线

[复用核查](<../../../research/2026-11-01-复用核查/宿主与依赖.md>)将接入方式具体化为DSH现有provider配置；不增加模型SDK或独立服务网关。必要适配只维护批准的角色路由、用途/预算和外发边界；现成模型目录、凭据解析、重试和流转换直接复用。

外部依赖通过 DSH 已有 adapter 接入。模型 API、检索/抓取服务、MCP server 和设备服务分别登记用途、凭据引用、版本、目的地、发送数据类别、预算与失败策略，不把“模型能调用”视作已获业务授权。

唯一叶模块 [模型与服务](<01-模型与服务/README.md>)负责以上接入契约。DSH 与原生数据库等本地依赖由[宿主方案](<../03-DSH宿主进程/README.md>)固定；本区域不复制第三方源码作为产品，也不引入自己的模型平台。

首阶段只启用完成准入的主模型路由与验证必需服务。无密钥时用替身推进本地验证；允许外发与费用范围由部署配置约束，不假定当前用户授权了新的供应商。无额外需求不新增通用向量服务、远程缓存、消息集群或自动 fallback 服务商。

## 外发与可用性

每个请求在发送前检查当前用途和数据范围；模型输入、额外Session日志贡献、反馈遥测和备份是不同外发路径。规划基线关闭额外 Session 日志贡献与 OTel 内容上传，后续显式启用时另列数据目的地；这不影响按授权调用模型本身。

依赖健康状态分 configured、reachable、authorized、capability-verified、degraded，不用心跳替代业务功能验证。V13/V14 先用替身证明缺凭据、过期授权、不可达和慢依赖都能回到等待或降级；V24 才验证实际宿主配置和请求路径。
