## 选择与复用

本轮[复用核查](<../../../../research/2026-11-01-复用核查/宿主与依赖.md>)明确直接配置已有 provider：`dsh-llm-deepseek-api-key` 注册 `deepseek-official`，`dsh-llm-deepseek-account` 注册 `deepseek-account`；`llm-deepseek` 是两者共享传输库。primary 只是识雨的逻辑映射，不是另写的 provider。其他供应商优先配置 `llm-pi-ai`，删除自建模型 SDK、目录缓存、流协议转换与多厂商网关计划。DSH 与所列包为 MIT；SDK传递许可由固定锁文件验收。

主模型通过 DSH 原生 DeepSeek adapter 使用已配置授权路由；需要其他供应商时优先复用 DSH 已有 `llm-pi-ai` provider，不自行实现 LLM SDK。检索与HTTP抓取优先使用已准入的宿主工具，MCP server 逐项加入清单；远程设备调用按设备专题，不把任意服务直接暴露给模型。

模型标识采用逻辑路由 `primary`，部署时解析为有效 provider/model 并固定到清单；评测准入必须覆盖中文对话、工具参数、长上下文、结构化提案和实际需要的视觉能力。首轮先一个模型服务多个角色，有测量证据证明成本或质量收益后才增加专用路由。

## 服务契约

| 字段 / 对象 | 要求 |
|---|---|
| ProviderManifest | provider ID、服务类别、adapter/协议版本、endpoint、模型ID/能力、凭据引用、允许数据类别、费用计量、重试与超时策略 |
| RequestContext | role、request/task ID、用途、ReadView或产物引用、剩余预算、deadline、允许目的地 |
| ProviderResult | request ID、实际provider/model、用量、finish/error类别、来源引用与生成时间 |
| HealthSnapshot | 最近成功探测、配置/鉴权/功能可用状态、下次允许尝试时间；不含密钥值 |

配置和凭据由受信程序解析，模型只能读取脱敏能力与可用性；严禁模型通过更改 endpoint 把同一份上下文转发到新服务。来自模型、网页、MCP资源和工具结果的说明不增加授权范围。

## 默认失败策略

期限和模型重试遵循[模型与会话](<../../03-DSH宿主进程/02-DSH运行底座/01-模型与会话/README.md>)，不在adapter外重复叠加无限重试。网络不可达、429和短暂5xx按有限策略等待；401/403或配置错误进入人工可见的依赖失败，不反复请求。取消会终止本次等待；对已经发出的外部副作用通过Receipt核对，网络错误不证明对方未处理。

连续 5 次可重试失败可进入 60 秒冷却，仅允许一次探测请求；这些数值为验证默认值，成功后再恢复有限并发。服务健康恢复本身不复活已取消任务。替代路由必须预先准入相同用途、数据和费用范围，否则回到等待状态；不自动切换陌生供应商。

上述冷却只需要业务下一次允许尝试时间，不建设通用熔断服务。模型目录发现/自动刷新也可能产生网络请求；准入检查包含这些宿主现有请求，不能只统计推理调用。API-key/account 凭据失效保持各自错误语义，不将二者自动互换。

## 外发、费用与留存

验证默认关闭 DSH 的额外 DeepSeek Session 日志贡献，并设置 OTel 上传为 disabled；不是声称本机已改变这些设置。核查上游默认贡献为启用且可以带完整会话后缀，因此部署检查必须显式读取有效组合，不能只看自定义插件配置。

每个请求在送出前记录用途与预算预扣；费用、调用次数、总时间、最大输出 token 四项限额缺一则不启用真实 provider。费用上限由验证用例的授权预算绑定，不以“使用默认模型”推定无限额度。收到计费用量后结算，未知计费按保守预留保留，不以失败请求等于免费。服务价格表在部署验证时记录日期与出处，不在长期架构中硬编码实时价格。诊断保留ID、耗时、错误和计量摘要，原始正文与工具参数按数据保留方案控制。

## 验证与备选

V13 注入含伪授权的网页/工具内容，确认不能扩大调用范围或改变目的地；核查模型正文与额外日志上传分别控制。V14 用替身覆盖超时、错误、流中断、取消、用量缺失和冷却；V24 核查有效路由、关闭贡献与telemetry的实际网络行为。所有外部依赖失败时，系统仍可查询状态、暂停和保存已收到任务，不虚报完成。

当主模型未通过角色质量评测时，优先换已支持adapter中的已授权模型；需要新协议才评估薄adapter。没有实测收益前不引入多模型自动仲裁或整套新Agent平台。
