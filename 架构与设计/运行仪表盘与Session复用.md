# 识雨运行仪表盘与 Session 复用

更新：2026-11-02（America/Caracas）。**运行仪表盘及受限原生 Session 路径已实现；3G B 轮有限 Core→Task→独立完成和有序重载核对通过。** 下文保留界面及复用设计，已验范围见文末与[本体实施记录](<../plugins/shiyu/实施记录.md>)；不将规划中的全部字段和能力视为已经交付。

用户明确要求“尽量复用 dsh session，它已经很优秀了”，并将识雨本体插件的界面定位为“运行仪表盘”，能够看到识雨当前状态和大概在做什么。识雨继续采用 A 方案，权威核心运行于 DSH 插件内；仪表盘是本体的原生操作界面。现有资料工作台 `plugins/shiyu-workbench/` 和健身房 `lab/` 各自保留。

## 用户打开后首先看到什么

首页首先回答三个问题：**现在是什么状态、正在做什么、是否需要我处理。** 模型参数、内部 ID 和详细日志放在展开详情中，不占据首页主体。

| 区域 | 展示内容 | 事实来源与限制 |
|---|---|---|
| 当前状态 | 待命、处理中、等待、已暂停、恢复中；异常另带提示和最后更新时间 | 运行门禁、任务/Session 生命周期与健康探测共同投影；连接失效或数据过期显示“状态未确认”，不沿用旧绿色状态 |
| 正在做什么 | 简短工作标题、当前阶段、已发生的动作、等待原因；并行工作可分别展开 | 来自获准任务描述、阶段事件、工具开始/结束与核验记录；例如“读取附件”“等待工具返回”“结果待核验”，不把请求发出写成完成 |
| 需要你处理 | 待澄清、既有授权范围以外的事项、依赖失败、无法核对的效果 | 展示具体原因及已有证据；不能为了填满区域制造待确认事项 |
| 目标与任务 | 当前目标、活跃任务、排队/等待项、完成结果及产物入口 | DSH Goal 是目标生命周期权威；任务、Assignment 和结果来自控制账本；进度有分母才显示完成项数量，不猜百分比 |
| 最近活动 | 接收请求、开始工作、工具结果、已核验完成、发送待核对等简短时间线 | 对真实事件作受限投影；生成草稿、获准发送与实际送达分别表示 |
| 依赖状态 | 模型、记忆、embedding、渠道及设备的可用性摘要 | 显示最近探测或调用结果及时间；配置存在不等于当前可用，未接入模块明确标记未接入 |

首页采用“状态与当前工作在上、目标/任务居中、最近活动在下”的信息顺序。多个并行工作以任务项展开，不强行合成一段会丢失细节的状态文案。“大概在做什么”通过任务阶段和可验证动作表达，不展示模型逐 token 内部推理，也不为每次刷新调用模型写播报。

## Session 与缓存详情

用户可从任务或角色进入详情，看到所属 core / worker / replyer、模型与 effort、对应原生 Session、最近活动、上下文预算与压缩记录。原生 Session 查看、恢复与历史浏览优先使用 DSH 已有入口；具体跳转接口在宿主适配切片核实，不假定不存在的 URL。

| 详情 | 展示规则 |
|---|---|
| Session 绑定 | 展示该业务对象绑定的原生会话；只索引识雨自己的绑定，不默认汇总宿主所有私人会话 |
| 上下文 | 区分 provider 上报 token、宿主估算值与角色上限；未知显示未知，不把模型最大窗口当实际占用 |
| 压缩 | 最近一次时间、压缩前后可取得的输入量、摘要来源范围与状态；原始事件日志和业务状态不会因压缩被当作已删除 |
| 缓存 | 优先展示已上报的缓存读取 token 与未缓存输入；统计区间和有效样本数明确，缺字段不填 0 |
| 命中比例 | 只有确认该适配器输入字段是否已扣除缓存、分母完整且统计口径一致后才计算；不能对不同含义的字段直接相除 |
| 用量 | 各用途请求、重试、压缩与模型调用的实际用量；订阅剩余额度只在取得可信来源时展示 |

缓存统计服务于成本与延迟判断，不驱动权限、删除或业务状态。仪表盘刷新与事件订阅不启动模型、不更新长期记忆、不自动创建或恢复 Session。

## Session 默认复用规则

**优先使用 DSH 原生 Session、Agent 生命周期、历史投影、持久恢复和压缩。** 识雨维护业务绑定、权限与预算；不再默认建设另一套会话历史、摘要存储、压缩循环或模型重试器。replyer 也先验证受限原生 Session 路线，默认 tools=[]，在创建/恢复与执行入口落实限制。

| 用途 | 绑定与续接 |
|---|---|
| 持续目标 core | 一个 Goal 一个专用原生 Session，连续决策周期与压缩保留会话身份 |
| 临时 core | 同一业务事项、同一作用域内复用，事项结束封存 |
| worker | 一个 Assignment 一个受限 Session；该执行实例的工具循环和合法请求重试复用，新实例通过核验过的交接材料起步 |
| replyer | 按 conversation 和受众/权限作用域稳定绑定；新消息追加，generation 只控制本轮草稿失效，不导致每条消息新建 Session |
| 抽取、回顾与评审 | 使用有明确来源范围的内部任务或短作业；复用固定模板，不拼接无关业务历史求缓存 |

多频道与多人私聊的进一步建议见[话题与后台协作](<A方案全景/多频道话题与后台协作.md>)：简单会话沿用上述绑定；持续独立话题可细化到 conversation + topic + scope。话题可以跨会话关联 Task，原生历史仍按受众分开。背景更新按需读取，必要时定向通知；仪表盘按对话和任务分别查看。该细化尚未实现，也不表示每个话题都创建一个常驻 Agent。

在角色与授权范围内保持系统规则、人格配置、工具 schema 与顺序稳定。DSH 的静态 sections 承载稳定规则，动态 contexts 承载必要变化，实际序列化在适配验证中检查；时间、检索材料和本轮状态放入追加上下文，避免频繁重写 system 前缀。

压缩复用宿主机制，保留完整工具往返、待解决问题、来源与核验状态；摘要是推理上下文投影，不自动成为长期事实。压缩属于额外模型调用并计入预算，模型/effort 的实际解析需验证，不能假定自动继承原请求。删除、撤权、受众变化先使相关上下文失效并重建，不能为命中缓存继续外发旧正文。

DS-Bot 的旁路调用只保留为条件备选及局部机制/测试参考。只有实际验证发现原生 Session 的权限隔离或表达行为不能满足约束，才评估所需闭包；不因为已有旁路代码就默认自管第二套会话。详见[模型与会话](<A方案全景/03-DSH宿主进程/02-DSH运行底座/01-模型与会话/README.md>)与[replyer](<A方案全景/03-DSH宿主进程/01-识雨插件/01-外层-对话与表达/03-replyer-表现/README.md>)。

## 状态怎样进入界面

数据链为：**DSH Session/Goal 事件、任务账本和依赖探测 → 按当前用户裁剪的运行状态投影 → DSH 原生 Client 仪表盘。** 模型生成的进度说明只能作为有来源的说明，不能覆盖权威状态、回执或完成核验。

复用宿主现有事件与前后端通信能力；首次打开读取快照，再接收更新。刷新和重连先校验游标/版本，发现缺口重取快照；卸载释放监听与 UI 资源。不另启 Web 服务、定时模型心跳或观测集群。

运行展示组合既有 `health_summary` 与 `task_status` 等受限视图；如需新增 purpose，须先同步公共契约与权限测试，不能只在 Client 添加一个字符串就扩权。每块包含来源、采样/生成时间及 current / stale / unavailable 状态；不同后端不伪装同一原子快照。日志只读展示必要摘要，省略密钥、完整提示与其他会话正文。

首页首批交互是查看详情、查看成果及进入对应 DSH 会话。后续暂停、恢复和取消均走既有可信控制入口，分别展示“请求已受理”“新派发已关闭”“执行已停止/仍待核对”；按钮点击不能立刻伪报所有外部动作停止。不得通过直接改前端状态或数据库绕过任务策略。

## 文件树与实施顺序

实现位于 `plugins/shiyu/`。`client/` 成为运行仪表盘入口；`src/views/` 组织状态投影，`src/health/` 提供探测事实，`src/adapters/dsh/` 只做宿主适配和原生 Session 绑定。数据所有者保持原分工，不在 Client 保存第二套 Goal、任务或 Session 权威状态。

**基础仪表盘提前到第 1 个切片，随真实功能逐步丰富。** 首批展示插件生命周期、已接入能力、真实 Session 绑定与当前可观察活动；没有可观察工作时明确说明待命/未接入，不填演示任务。此后随任务执行、内层及外部依赖落地，增加相应状态与控制入口。完整文件树和顺序见[本体文件树规划](<识雨本体文件树规划.md>)。

## 验证与当前交付

| 验证 | 判定依据 |
|---|---|
| 原生会话复用 | 连续输入不因 generation 更换 Session；压缩/重启保留正确业务绑定；恢复前重新校验授权 |
| 只读展示 | 反复打开、刷新与切换详情不新增模型请求、记忆写入或任务派发 |
| 状态准确 | 待命、运行、等待、断连、恢复、unknown 等合成场景显示对应来源与更新时间；无事实依据不显示成功 |
| 活动摘要 | 工具开始、结果返回、核验、外发回执阶段可区分；迟到或已取消草稿不记为已送达 |
| 作用域与新鲜度 | 只展示当前用户获准的识雨绑定；撤权/删除后立即抑制旧内容；事件丢失和重连后不会永久显示旧状态 |
| 缓存展示 | 覆盖有上报、零值和缺字段；缺失不计入伪造的命中比例；压缩与重试用量纳入对应类别 |
| 原生界面 | 在固定 DSH 核对生命周期、会话跳转、主题与窄屏；工作台与健身房保持可用 |

沿用 V04 / V05 / V09 / V13 / V14 / V23 / V24 等既有验收项，不以截图或演示状态替代运行验收。2026-11-01 的首版专题只完成方向登记、界面职责和 Session 优先路线；当时没有新增运行组件、修改已安装插件或调用模型。后续实际实现与限定验证如下，完整 V 项仍未验收。


### 当前已验范围与显示边界

基础 Client、Task/Conversation、原生上下文加载、受控记忆及 Goal/判断/共享预算控制已逐片接线。早期 replyer 两轮复用、worker 任务、原生 Goal 零推理生命周期与 3F 记忆加载/撤回换代的历史证据见[九系统实施与验证计划](<九大系统实施与验证计划.md>)；3G 原 168 项全量模拟 UI 与后续 3 项定向保留为独立历史批次，本轮误标修补的 26 项定向模拟 UI 另批通过，未在宿主重载复验，不与旧全量相加。

3G B 轮在修补后的固定宿主完成单个 owner 预授权 local-note Goal：两次 Core 判断使用同一专用原生 Session，worker 在自己的 Session 内执行两步，实际产物经独立核验后 native Goal confirmed complete。首轮 cwd runtime-context 的持久 snapshot seq=12，第二轮沿用原生历史，没有为续评创建新 Session。随后有序重载的控制证明、Task、预算、产物以及旧 9 个与新增 2 个自有 Session 文件均未变化，限定范围内无重放。见 [B 轮宿主成功证据](<../plugins/shiyu/artifacts/phase3g-core-host-success.json>)。

运行状态需要区分三个事实：native Goal 的已确认生命周期、控制层是否允许新派发、当前实际工作。B 完成后，本地 `paused=true` 是收紧授权的栅栏，目标结果仍是“已完成”；不能将它显示为 owner 暂停或等待继续。A 则仍是 owner 取消且 native pause confirmed，首轮 unknown hold 保留，不能从 B 的成功推定 A 已完成或费用已结清。本轮发现的本地栅栏误标已通过定向离线修补，尚未重载到宿主复验；批次证据以[实施记录](<../plugins/shiyu/实施记录.md>)为准。

B 的 4 次已观测主调用 reported 3813 tokens、1 effect、0 held 可以作为该目标的账本摘要；完整 provider 请求/重试/费用仍不能由此推定。缓存字段与比例必须按独立审计的实际口径显示。同 Session 复用和有序重载通过也不等于完整压缩、崩溃恢复、缓存收益或多频道业务已验收。
