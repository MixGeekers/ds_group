## 用户确定的方向

内层由记忆、关系、情绪、认知、人格、能力六部分组成；外层负责表现、链接与串行/并行对话队列。外层对内部权威状态只读，不能直接保存、更新或删除内部记忆。内外双工允许传递观察、查询、视图、通知和回执，不赋予额外写权限。

角色使用 core / worker / replyer。当前规划将 core 设为内部判断与受控提交的组织者，worker 设为按授权执行任务并返回提案的角色，replyer 使用裁剪视图进行表达。六个状态模块不固定对应六个模型；模型路由与执行位置由任务及能力选择。

识雨要能在预留空间维护数据、知道实际运行状态、主动推进持续目标、分层自愈并连接多设备。当前单一权威核心在 DSH 插件内，宿主退出时判断暂停；外部监督器仅恢复进程。B 独立核心留作明确需求出现后的备选。

## 当前工程基线

持续目标直接复用 DSH `ctx.goals`：每个目标绑定一个专用 Session，原生 Goal / Session 日志是生命周期权威。控制库保存 GoalBinding、授权、停止原因与操作回执，不维护第二套独立 Goal 状态机；目标变更按原生 revision 调用并核对，不能把跨存储两次写入当作原子提交。DSH 同时提供模型、Session、工具、事件和插件生命周期。

控制任务账本采用 SQLite，优先局部复用 Superagent 的事务、任务聚合、effects/outbox 与执行生命周期；本地状态、回执及待派发效果只在该后端内原子提交。Ombre 优先承接长期记忆、情感记忆 / feel、回顾与 I 自我认识候选，并使用自身存储与检索；稳定人格配置和执行权限仍由识雨控制。Mem0 是替代后端，SQLite/FTS5 是独立对照 / 回退，均不与 Ombre 并行维护同一份可独立修改的记忆。

跨后端保存使用 `MemoryOperation` 记录批准、派发、已应用、未知或拒绝；已批准不等于已经记住。`commitSeq` 只表示控制账本提交，组合视图另标投影版本及各组件版本 / 来源摘要，不能宣称全局原子快照。外部效果同样保留独立身份、重放类别和未知状态，结果不明时先核对。

设备接入直接使用 DSH SSH / MCP、浏览器与 CUA 等现成能力，区分 `direct` 与 `gated`。direct 由中心授权并核对单次效果，不声称现成工具已有端侧 fencing；持续排队或跨重启续接的有副作用执行，须验证端侧 gate。DeviceGateway 只补设备绑定、范围和资源协调。

OS 监督托管进程；唯一 CheckpointService 调用各后端原生备份 / 导出，封存控制 SQLite、Ombre 数据及承载 Goal 的 DSH Session 日志与必要附件，再交 restic 保存到独立故障域。恢复先核对组件版本、世代、删除、撤权及 unknown 效果，不能只恢复控制库就开放派发。全部边界及失败回退见 v1.1 完整方案。

现有资料工作台 `plugins/shiyu-workbench/` 保持原样。当前目录只有设计与证据，不是运行数据根。识雨本体代码与模块测试在对应实现模块中维护，首个实施切片记录实际路径；隔离候选实验仍在 `测试/`，健身房仍在 `lab/`。真实模型、设备和备份沿用各自明确的任务与资源范围。
