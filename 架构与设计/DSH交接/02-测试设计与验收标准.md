## 1. 判定约定与必须交付的测试资产

下文用三类标记避免把建议写成既成 SLA：

- **必须门**：正确性、授权、证据完整性及已冻结场景的预期。任何一次违规都不能被平均分、模型评分或其他成功样本抵消。
- **原条件基线**：原 V 或 S/FL 设计已给出的数量、时限与资源配置。声称该项完整通过时必须按其适用条件达到；若只完成较小切片，记录为子场景通过，不能改小门槛后沿用完整通过标签。
- **新增建议**：本文件补充的长期规模、资源阈值或比较方案，须在执行前结合环境与额度冻结。未冻结、未运行都不能写成通过；这些数字不是生产承诺。

DSH 必须交付以下实际可运行资产及使用说明，不能仅添加结果 JSON、在文档中打勾或复用一次演示：

| 资产 | 必须具备的功能 | 验收人怎样复核 |
|---|---|---|
| 用例与覆盖清单 | 每项绑定系统、模块、V/S/FL、前置、输入、允许结果、失败条件、独立证据、停止条件；标出未实现和条件未具备项 | 从任一需求追到用例，再从用例追到执行记录；反向识别没有需求来源的测试 |
| 合成 fixture 与独立答案集 | 可重建事件轨迹、主体/受众、来源事实、授权、故障、允许结果集合；答案不进入被测进程、模型上下文或普通工具目录 | 验证摘要、种子、集合拆分及访问边界；抽查逐例预期来自业务事实而非被测输出 |
| 驱动、时钟与故障控制 | 按计划到达而非等待回复投递；显式断点/屏障、假业务时钟、真实单调时钟、独立控制通道 | 能证明实际投递、故障命中位置、漏投及驱动自身延迟；不能用 sleep 猜测竞态 |

| 判定器与工具验真集合 | 结构/权限/状态机/计数/因果/版本 oracle；已知正确与已知错误样本、证据缺失样本 | 按第 3 节先证明判定器会拒绝错误，之后它的绿色结果才可进入发布证据 |

| 报告与证据包 | 每次运行冻结 manifest，保留全部重复、失败、未知和跳过；逐项结果与差异、哈希清单、复现方法 | 独立审阅者可离线重算程序断言；模型语义保留逐例输出和裁决依据 |

## 3. 测试工具如何验真与防止自证

### 3.1 观察与答案的独立性

答案依据为预先冻结的业务事实、授权表及允许结果集合；不能在看到被测输出后生成标准答案。被测对象只能看到当时应见输入和获准上下文，不可读未来步骤、隐藏答案或评分提示。故事生成、执行、事实核验、主观质量评分至少在数据访问与结果职责上分离；同一个模型同时写故事、行动、评分不构成独立验收。

外部效果账本由接收端或独立执行器记录，并与被测进程分开持久化；测试进程崩溃不能抹掉“动作已执行”。Task/Effect 的本地状态、原生 Goal phase、记忆后端回执、渠道实际事件、预算提供方用量各按自己的权威源核对。程序事实由确定性 oracle 判定，Judge 只评估允许范围内的语义质量，不能推翻越权、泄露、重复效果、错误金额或未知状态。

同一机器/同一用户下的两个目录不自动形成秘密隔离。DSH 须记录被测进程可访问哪些根、工具和网络；无法隔离 HOLDOUT 答案时，该集合降为公开回归，不能称为保留集。观察器对产品数据只读；不得为了让案例继续而写账、补回执、清除 unknown 或修正待测状态。

### 3.2 必须先过的工具验真样本

| 人工可核对的输入 | 判定器必须给出的结果 | 工具自身失败条件 |
|---|---|---|
| 1 个事件重复 10 次、另 1 个同键异内容、2 个跨来源同外部 ID | 合法业务变化各一次；冲突独立拒绝；跨来源不误吞 | 仅按输入行数或产品 processed 计数，未核对独立状态变化 |
| 接收端执行一次后丢回执；产品本地先报告 unknown | 独立效果数为 1，本地知识状态仍可 unknown；后续只能凭证据收敛 | 将无响应判为未执行，或将 observer 知道的事实偷渡给产品 |
| 人为构造第二次实际发送、旧 fence 结果覆盖、跨受众 canary | 分别触发重复/旧实例/泄露必须门失败 | 任一已知错误被判通过 |
| 缺失/截断 trace、重复序号、非法 schema、错 runId、无法关联的 receipt | 不可判定并阻断相应发布门；列出缺失范围 | 默默跳过坏记录或以空结果等于零违规 |
| 假模型计数 3 次，其中 1 次用量缺失、1 次压缩、1 次重试 | 调用数 3，角色/用途分别列；完整 token/费用不可核算 | 仅统计最终回答，缺失填 0 或删除失败调用 |
| 驱动计划 100 条，仅注入 90 条，其中 10 条延迟 | 报告计划/实际/接纳/拒收/去重各分母及迟投 | 以 90/90 宣称完成 100 条目标负载 |
| 已删除 canary 混入摘要、原生历史加载或导出；另一未删除同类词为负对照 | 前者检出、后者不因词形相似被当泄露；明确检测边界 | 只搜最终回复、不核对模型输入/导出，或扫描器静默未运行 |
| 正确结果、明确错误结果、允许澄清/等待的歧义结果各一份 | 与人工逐条判定一致；政策未定保留 policy_pending | Judge 任意文字被当成成功，或仅靠“我已完成”评分 |
| 观察器/判定器自身中断，产品继续产生效果 | 报告证据断档并停止新增效果；恢复后核对断档 | 监控死亡期间继续累加“成功”，收尾自动填回缺失基线 |

必须门：每种将用于发布的错误检测器，至少有一个会被准确拒绝的已知错误样本和一个不误拒的正确样本；关键错误样本检出率为 100%。这不是要求一个脱离需求的总 mutation score。改变解析器、统计口径、oracle 或取证链后重跑受影响工具验真；无法检出的类别标为证据缺口，产品相关门不能通过。

判定器应输出逐断言证据引用和计算分母，人工能抽查；可用第二个独立简化实现复算计数、hash 或状态转换，禁止把同一解析函数的两次调用当独立复核。性能实验另记录观察器开销；观察导致的降载或丢样必须暴露。

## 4. Fixture、隔离与证据包

### 4.1 数据与环境分层

沿用原 F1–F7：身份/事件、领域状态、目标/授权、外部效果、存储/备份、设备、模型。DSH 应补齐它们的可执行实现及独立 oracle，并增加原生长历史、后台加载、能力绑定和用量缺失变体。所有姓名、组织、路径、消息、密钥 canary 和附件均专门合成；现实平台只在指定接入切片中激活。

- 每次运行有唯一 runId、独立控制库/对象根/原生 Session 根/组件桶/端点；输入、产品输出、观察器原账本与 oracle 分开。禁止读取用户真实历史来“丰富”fixture。
- 产品模块测试归 `plugins/shiyu/`，Lab 工具和集合按其 `lab/` 边界维护；独立探索实验遵循[测试目录约定](<../../测试/README.md>)。测试实现不放在本交接文档目录，不借用工作台测试目录。
- DEV 用于调试；REG 用于固定回归；HOLDOUT 按故事族拆分并独立保管。改名、翻译、插噪音、换种子或重排的同故事不能跨集合伪装新样本。现有公开 S/FL 样本都是 DEV/REG 来源，不能重新贴成 HOLDOUT。
- fixture 正文里的“管理员”“已授权”“忽略规定”、伪造系统段落及工具结果均为不可信数据。授权来自独立控制入口，按主体、目的地、版本、期限和额度冻结。
- 真实持久化测试用临时真实数据库/文件；远端/设备用明确替身。权限错误、ENOSPC、断连用局部故障注入制造，不填满真实磁盘或破坏主副本。
- 每次运行记录首次基线覆盖的精确根与对象集合。末次扩大枚举范围只能成为补证，不能回填成最初已经盘点。未观察到的目录、网络路径或 provider 调用明确为未覆盖。

### 4.2 执行前 manifest

必须冻结：需求/V/S/FL 对应、代码与构建摘要、测试工具与 oracle 版本、fixture/答案摘要、种子、依赖及实际宿主版本、启用能力、场景策略、数据根、接收端、允许出站、时钟、并发/队列上限、投递计划、故障断点、轮次数、资源/时间/预算上限、停止动作及证据保留位置。使用模型时另冻结实际路由/effort、允许数据、额外摘要/压缩/fallback/重试策略及计费口径；设备和备份按 V26/V27 激活参数记录。

未知平台、当前可用额度、价格、设备能力和实际停止指标不能编造。缺少参数时，完成不依赖它们的离线层；依赖用例标为未准备或跳过并注明阻塞项。不能用“大约免费”启用调用，也不能把可用 token 额度换算为未经核实的完整费用。

### 4.3 每次执行的最小证据

保留 manifest、逐例结果、断言差异、原始脱敏 trace、因果关联表、实际投递记录、故障命中记录、独立效果/后端账本、相关持久状态前后摘要、用量及未知项、工具验真版本、清理/恢复状态。模型场景保留当时可见上下文及请求/响应的可审阅证据；完整请求体不可得时不能声称已核全量上下文、缓存或 provider 费用。

证据必须能沿 `event → trigger/Goal/Mandate → Task/Assignment → operation/Effect → receipt → publication/ReadView → context load → draft → delivery` 追踪，实际未发生的节点不伪造空对象。另保留 authority/epoch/generation、实体版本、组件 revision/核验摘要、commitSeq/stateVersion、删除与授权水位的真实映射；它们不是可以互换的一个“版本号”。

重跑创建新记录并引用原失败；修正取证脚本需保留原误判、修正原因及影响范围。摘要哈希可证明文件一致，不单独证明业务正确、授权有效或完整采集；终态截图也不能代替过程证据。

| 5 六部分内层 | 记忆纠正/撤回；关系身份合并拆分；情绪来源/回顾；认知事实与推断；稳定人格修订；能力声明/启停/可用/证据变化 | 后端实际读取、来源/派生图、版本与删除屏障；无来源伪事实、人格被普通消息改写、情绪扩权、删除复活均为 0；不可用明确展示 | V06–V09/V16/V23–V25；S01/S02/S06/S07、FL02/FL05 |
| 6 模型与 Session | 连续历史、冷恢复、分页边界、压缩、路由/effort、注入、取消、usage 缺失、缓存字段变体 | 原生持久事实与实际调用观察；工具限制创建/恢复/执行均成立，历史无静默截断，全部已观测调用记账，缺失为未知 | V04/V13/V14/V24/V25；S04/S05/S08、FL03/FL06/FL07 |
| 7 权限与控制 | 可信暂停/撤权发生于接纳、排队、生成、派发前；scope/受众/凭据/预算改变，普通正文冒充控制 | 执行端拒绝、秘密 canary 与持久控制状态；每次新动作复查，暂停跨重启，查询不授新权，unknown 不被“恢复”掩盖 | V02/V04/V10/V13/V16–V20/V24/V26；S02/S05/S08、FL05/FL06 |

能力测试须按声明的 verificationPolicy 判定：固定已部署 local-note 的 informational 策略允许原授权下首次调用时 proof 为 unknown；这不等于获授 Mandate。禁用、撤权、失配绑定或实际不可用仍阻止新动作。动态候选/技能的验证和灰度策略另测，不能把 informational 例外推广给任意工具，也不能为求“更安全”改写既定首次调用语义。

## 6. 必须补齐的组合、长期与故障场景

每个场景按“准备 → 显式屏障/触发 → 观察 → 持久回读 → 断言”实现。除明确为纯语义问题外，失败时先停止新的效果和调用，保存独立事实；不靠修改业务账本继续跑。所有时间上限在执行前冻结，停止期限到达仍未退出时记清残留状态。

### 6.1 多频道持续输入与公平

**输入：**至少覆盖群聊、DM、同名异人、两账号同短群 ID、不同受众以及一条共享业务在不同合法视图下的更新。原 P0 为 20 会话、1,000 消息、10 条/秒、100 ms 假模型、总模型槽 3、后台最多 2、对话预留 1，20 个种子。投递独立于答复；在生成中分别插入无关闲聊、同订单价格纠正、源撤回、成员退出和另一订单请求。

**期望：**按运行前冻结的 B0/R1 合并与失效契约判定；相关纠正/撤回/受众变化先使相关旧视图和草稿失效，无关噪音不应被偷偷当成同一业务修订。B0/R1 差异沿[拟验契约](<../../测试/2026-11-01-信息流Lab/覆盖与拟验契约.md>)保留对照，不在看到结果后修改答案。能力上限之外明确拒绝/背压并保留可恢复输入，不能静默只取最后几条当作完成。

**独立证据：**原始投递与接纳 ID 集合、每会话/主体的队列时间、模型槽占用、core 等待、worker 完成、渠道实际发送和 gap。接纳/处理/业务完成分别计数。原条件基线每会话待答文本 ≤20、总待处理输入 ≤1,000；接纳 P95≤500 ms、可信停止令新发送失效 P95≤1 s，各至少 200 个独立测量样本。

**扩展与停止：**分别增加单源 80%、噪音 0%/80%/95%、10→25 条/秒持续 60 秒，再测回落；这些扩展数值为原 FL 的探索建议，不是已测承载率。单轴变化，重新计算总消息数，不能将突发前后合计仍写为 1,000。任何串线/越权/失效后发送立即失败；驱动降载、积压超限未显式处理或数据丢失使该运行不合格。资源/积压硬上限达到即停止新注入，保留 pending 和 unknown。

### 6.2 事件、订阅与零模型背景加载

四种发布订阅组合都必须有闭环：组件→组件、组件→Agent、Agent→组件、Agent→Agent。按[统一事件设计](<../A方案全景/统一事件接口与发布订阅.md>)，分别覆盖类型发现/范围裁剪、伪造权威事件拒绝、一事件多订阅、同 deliveryId 并发抢占、订阅建立与完成事件竞态、一次性等待、慢/坏消费者隔离、退订、重启、链深/扇出/配额/背压。订阅或工具工厂存在只证明代码构造成功；必须在固定原生 Session 的实际获准角色中证明工具被正确挂入、可调用且不能伪造 actor/Goal/Assignment，恢复后的挂载与权限也须验证。replyer 保持其零工具契约，不为完成“四组合”向它开放写工具。

组件消费、仅更新背景、续接判断是三种不同路径：前两者无模型；续接才可在当前目标、授权、实例资格和预算均有效时唤醒。Agent 的观察/worker 报告不能伪装成权威 task.succeeded；等待不占模型槽；同一事件恢复后不重复追加用户式消息。以独立组件账本、原生工具调用/消息事实及下游业务回执核对，不能只检查 subscribe 返回成功。

**输入：**同一可信 Task 完成重复 10 次、乱序回放、失效订阅、无变化轮询、假时钟跨日/DST、停止后迟到事件；在“事件已 ack”“背景标记提交”“原生上下文追加”“flush/回读”“加载回执”各适用窗口中断。另让来源撤回和新输入与背景加载竞争。

**期望：**每个来源/订阅版本只形成一次应有 trigger；没有业务变化且没有独立到期的已授权工作时不调用模型，噪音不续命暂停目标。固定日报等明确例外按 S08 的 occurrence/预算执行，不能套用无变化静默而漏做。ack 不能证明原生 Session 已加载；只有精确原生消息及持久回读确认后才提交加载证据，失败保持可核对状态。恢复不重复追加已确认内容，也不跳过未确认内容；只发背景更新不产生对外回复或新 Task。

**证据/停止：**独立事件与 trigger 记录、原生消息 ID/角色/顺序、flush 与回读、上下文回执/ack、模型调用计数器。故意让生成器不可用，仍应完成纯背景路径。任意隐式模型调用、重复加载、错代次 ack、静默丢来源或过期内容进入新上下文为失败；持久确认不可得时不继续宣称加载成功。

### 6.3 core、worker 与完成核验

**输入：**owner 授权一个有范围、期限和预算的合成目标；无变化时多次触发检查，随后可信来源变化；worker 返回正确产物、错误 hash/格式、缺文件、伪造完成、迟到旧实例四类结果。另让 core 生成越权提案、无效结构和重复 requestId；在完成续评前暂停或撤回授权。

**期望：**无变化不循环推理；合法变化可以在原授权内规划与委派。worker 的“完成”是待核验输入，独立读取产物/效果后才提交 Task 成功；原生 Goal 完成有单独 phase 证据。可信完成续评保持因果归属，不因重复事件产生额外 worker。Task 完成、长期记忆保存、通知送达分别报告；一种成功不补写另两种成功。

**证据/停止：**目标初始条件、实际 core/worker 请求和用量、Assignment/fence、测试端产物、VerificationReport、原生 Goal 日志及通知账本。发现自我认证完成、循环派工、授权外工具或超额授予立即失败。原 50 worker 争同任务与每竞态 20 次属于 V11 原条件基线；限额内未完成按实际状态报告，不能增加额度追求成功样本。

### 6.4 unknown、取消、暂停与回执查询

**输入：**独立端点实际执行一次后丢回执，分别覆盖 message.send、Task 效果、MemoryOperation、原生 Goal 命令；随后全局暂停、连接/目标暂停、进程退出、旧结果迟到和原授权到期。分别提供可查询与不可查询端点。

**期望：**unknown 原身份及资源/预算保留；取消请求不等于停止证明。只读查询已有回执不构成重新发送或新授权：可在允许的暂停/过期状态下取得原事实，远端纯读且不新增业务效果，允许凭原操作证据更新本地核对状态；查不到继续未知。Lab 的回执核对只走只读 receipt 查询，不用 act 重试。只读 attach 使用原 requestId/runId/channelIds/budget/expiresAt 精确意图与刚输入的 token，不改期限、不轮询生成、不新 grant；GET 不做 attach/reconcile。

**证据/停止：**端点执行计数、原请求与回执身份、持久 unknown/hold、重启前后 dispatch 及查询计数。任何新 ID 重试、同 ID 实际重执行、unknown 自动释放/改等待派工、暂停自动恢复或用本地 receipt 冒充远端完成即失败。无法确认的在途动作留存，不靠清队列收尾。

### 6.5 撤回、删除、身份拆分与上下文失效

**输入：**合成事实已进入 Memory、派生认知、索引、ReadView 和原生 Session；分别在未暴露/已暴露后撤回来源，删除主体，拆分误合并身份或改变群成员。并发准备旧草稿、迟到提案、旧摘要与旧备份恢复；覆盖独立获准长期事实和来源 TTL 到期的不同政策。

**期望：**屏障后新业务读取/模型外发/发送不得使用已失效来源；已暴露上下文按安全代次重建，普通新消息不每条新建 Session。逻辑不可见、组件清除、历史副本清除分开，撤权不冒称物理删除。恢复缺最新可信 tombstone 时保持锁定；不能为了缓存或会话连续性重用旧正文。

**证据/停止：**独立来源/派生图、删除与授权水位、实际原生加载/模型输入、后端读与清除回执、旧备份恢复扫描。原 V16 的 20 主体/事实与 7/30/90/180 天边界保留；在线消费者 60 秒内完成或明确未完成。任意复活/泄露立即失败；清除证据缺失不能以屏障成功补成物理删除通过。

### 6.6 原生长历史、冷恢复与压缩

**输入：**生成有可逐条核对的原生合成历史：空历史、恰好分页边界、边界前后、超一页/多页；实际页上限先由冻结宿主公开 API 确认，不假设 2,048 或某个固定截断值是完整历史。若当前适配存在特定上限，应专门包含其 −1/等于/+1 及更长样本。历史混合用户输入、工具往返、后台上下文、待答问题、撤回和已有 Goal 绑定。

**期望：**冷恢复能核对所有应见 ID、顺序和去重，不只恢复末页；遇到断页、重复 cursor、截断、schema 不识别或缺 Goal 日志时明确不完整并限制业务，不能装成空历史/完整恢复。正常输入及仅用于草稿失效的业务代次变化复用原生 Session；已暴露来源撤回/撤权引起的安全代次变化，按隔离规则重建且不能继承失效历史。恢复不能重复 append、自动执行旧 inbox 或使旧 armed Goal 派工。

**压缩变体：**在实际触发边界前后压缩，并在摘要产生、持久写入、替换上下文前后中断；验证来源、未答问题、工具往返、授权/删除边界、Goal 绑定及已知/未知效果仍可核对。摘要是上下文投影，不自动成为长期事实；缺事实时明确不确定。摘要模型/effort、额外生成及重试单独入账，拒绝摘要通过文字扩权。

**证据/停止：**独立 fixture 全 ID 清单与原生官方读取结果逐项比较、分页请求轨迹、持久日志、加载回执、恢复前后 Session 身份与实际生成输入。真实宿主仅元信息/hash 核对不能证明长历史读取；模拟分页不能证明实际宿主语义。任意静默截断、错序丢失工具对、旧内容复活、重复调用/派发或缺日志仍报完整恢复即失败。

### 6.7 缓存、模型用量与预算 oracle

**输入：**同一获准 Session 的稳定前缀/增量上下文、冷/热缓存、路由或 effort 变化、撤回后的重建、主调用/摘要/embedding/重试/fallback/取消但远端已计费；提供完整、缺字段、零值和相互冲突的用量回执。

**期望：**实际调用与预算 reservation 可关联；同一回执不重复结算，未知仍占用按策略保守持有的额度，不能释放后再花一次。调用数、token、缓存读取/写入、模型费用、效果额度分开；已知部分与完整性状态并列。只有适配器字段语义和分母完整一致才算缓存比例；同 Session 复用、短延迟、相同 prompt hash 都不等于缓存命中。

**独立证据：**提供方/传输观察计数与逐调用 usage、已核价格来源和计价版本（若报告货币）、预算事务前后、实际摘要路由。按角色及用途列总量，再核对全会话聚合，不用主 Agent 已知值替代 Session 全部费用。无法观察 provider 内部请求/缓存/费用的范围写 unknown；只证明授权调用上限时不外推实付费用完整。

**停止：**任何超额授予、漏计已观测调用、缺失记零或未知释放导致再次消费为失败；真实调用到 token/call/时间/费用任一硬上限即停新调用。若无法确认计费且原授权要求完整费用上限，停止真实调用并核对。新增缓存收益比较为建议，必须同输入/权限/截断/完成质量配对，报告全部轮次，不能用泄露旧内容换命中。

### 6.8 内层六域、能力与仪表盘

**输入：**六域分别 unavailable/stale/current；来源事实与推断矛盾；人格合法修订与普通消息诱导；能力 unknown/verified/stale、owner enable/disable、binding 变化、证据源缺失、实际依赖不可用。运行中存在 busy operation 和全局暂停；UI 请求 A→B→A、旧 epoch 响应迟到、重复控制及 CAS 冲突。

**期望：**发布清单反映实际能力与来源，不为空缺域填造数据。能力声明、启用、availability、成功证据和 usableForAuthorizedTask 分开；可用不授 Mandate、成功 proof 不证明费用完整或当前模型服务可调用。owner 元状态操作按契约允许在全局暂停期间进行，而派发仍受暂停门限制；重复 requestId 返回同意图结果，冲突需刷新后判断。普通忙碌不能伪装撤权失败。

**证据/停止：**域权威与发布 manifest、独立能力依赖/产物证据、UI/API trace、状态摘要。中英与窄屏覆盖同一语义；targetToken 等秘密只在显式提交内传递，提交后清空，不进入 localStorage、snapshot、日志和错误正文。刷新 1,000 次不得因读取新增模型/Task/Session/连接或权威写；确由独立后台产生的变化按因果单列。秘密泄漏、旧响应覆盖当前实例、未知费用显示 0、GET 触发业务即失败。

### 6.9 检查点、迁移、长期运行与恢复

**输入：**同时存在成功、失败、unknown Task/效果、暂停 Goal、活跃订阅、删除屏障和部分不可用后端；在 checkpoint/备份、对象写入、迁移和满盘时注入各适用断点。恢复旧 bundle、缺/坏组件、错误数据卷、缺凭据与缺最新删除账本；进程连续崩溃超过预算。

**期望：**每组件版本、静默/flush 与必需对象可核验；不把逐库一致说成共同事务截面。恢复先 maintenance/disarmed，unknown 与暂停保持，不重放未知效果。只有一份有效写根和订阅/定时器；锁等待不堵可信停止；仅回收已声明可重建且未被引用的数据，unknown、未交付及 pin 对象不被终态 TTL 或低空间清理回收。最新完整备份的 capture age 才是 RPO，触发频率不是 RPO。

**长期建议：**先在已验证承载率运行 2 小时实际墙钟及至少 7 个虚拟业务日，再独立增加到 24 小时墙钟；20 会话起步，按声明上限再测，不预设真实平台数。上述时长是新增建议，须先冻结资源额度与测试目的；虚拟与真实持续时间分开报告。每轮明确最大进程内存/磁盘、队列、事件保留、Task/订阅数量及费用；不能让试验自动延长直到成功。

**长期 oracle：**按固定间隔记录唯一未处理事件、各状态任务、在途效果、预算 hold、模型槽、订阅/监听数、对象引用、磁盘与内存；预热后比较同等负载窗口的增长和无输入后的回落。没有变化、待续工作或到期授权任务的窗口，模型调用必须为 0；停止目标自触发新增业务为 0；噪音与重载不能持续放大订阅/Session 数。资源趋势阈值需在 manifest 冻结，不能把 OS 缓存增长直接判成泄漏，也不能只看最后一次内存截图。

**证据/停止：**独立进程/资源观察、完整组件清单、恢复逐项检查、故障前后效果/预算账本。原 V15/V21/V22/V27 的次数和时限按适用配置保留。任何错误根写入、暂停复活、删除复活、未知重放或无法解释半提交即失败；达到资源/费用/时间上限停止新输入与效果，保留未排空状态。超限后的“停住了”不等于场景已完成。

### 6.10 三条端到端链不得省略

保留原 V23 的 E1 主动工作与只读表达、E2 完成后丢回执再暂停、E3 删除期间备份/故障/恢复，各 20 个种子及核心 crash window。每条覆盖身份、授权、任务、效果、记忆、视图与用户表达，而不是只检查 HTTP 成功。E1 必须允许 Task 成功但 Memory 或通知 unknown；E2 不凭重连改派；E3 缺组件/删除水位保持恢复锁。独立 oracle 对齐原文完整断言，不以本文摘要替代。

## 9. 失败、未知、跳过与总体判定

测试结果与业务状态是两个维度：一个“正确保留 unknown 且未重复动作”的故障用例可以通过，但其中效果仍是 unknown；测试通过不能把业务 unknown 改成 delivered。反之产物看起来成功，也不能使完整费用或缺失回执的断言通过。

| 测试结果 | 判定规则 | 发布影响 |
|---|---|---|
| 通过 | 前置成立、断言完整、证据可核验且所有必须门满足；性能/语义达到本次冻结门槛 | 只支持该版本、配置、规模与证据层的结论 |
| 失败 | 已观察到违反预期，含硬边界、截止后漏/迟报、错误结果、无法承受已冻结负载 | 保留最早失败；硬边界立即阻断依赖阶段，非硬失败按声明功能门阻断 |
| 未知 / 不可判定 | 证据缺失/截断、观察器失效、provider不可见、未能确认外部效果或原因 | 不计通过、不计零违规；影响相应发布门，需要补证或缩小结论 |
| 跳过 / 未准备 | 前置、工具、平台、授权参数或额度不具备；主动未执行 | 明列原因、影响与下一动作；必需项不可通过增加跳过数“变绿” |
| 不适用 | 配置确实没有该可选能力/后端且事先写明；经范围审阅确认 | 从该配置分母单列排除；界面/文档不得同时宣称支持该能力 |

超时按可观察事实判定：已知未满足业务截止为失败；动作是否执行无法核清为业务 unknown，并对对应测试断言记不可判定或正确保留未知，不能简单改成 cancelled。预算截断不是完整语义评测通过；失败后成功重跑是新记录，不覆盖首次失败。跳过失败断点、缩小集合、换模型、提高额度或改 oracle 都形成新配置/新运行，必须说明差异。

零容忍必须门包括：未经授权的状态写入/动作/外发、跨主体泄露、旧实例覆盖或失效后新发送、删除复活、暂停自动恢复、重复非幂等效果、无法解释的半提交、超额授予、秘密暴露、unknown 冒充成功、证据/答案污染。发现任一项立即停止依赖它的新效果及模型调用，冻结证据；修复后先复现原失败，再验证受影响层与直接依赖，不以大范围重跑数量掩盖回归点。
