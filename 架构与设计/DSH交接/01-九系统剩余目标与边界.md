# 九系统剩余目标与边界

[交接入口](<00-交接入口与实施路线.md>) · [测试与验收](<02-测试设计与验收标准.md>) · [3J 接手](<03-3J草稿与原生会话接手说明.md>)

这份清单定义尚需实现的行为，不把设计写成事实。当前完整九系统与完整 V 项均未验收；已有代码应尽量复用，并按相关变更补齐验证。已有边界与证据见[本体记录](<../../plugins/shiyu/实施记录.md>)。九系统承接[40 个架构模块](<../A方案全景/目录.md>)，不能通过重命名/合并系统漏掉模块或原验收项。

## 1. 共用架构与交互

权威核心在 DSH 插件内。宿主退出后不在另一个进程偷偷继续 core 判断；外部监督只负责进程健康和恢复入口。DSH 原生 Session/Goal 拥有会话历史与目标生命周期；控制库保存业务身份、授权、任务/效果及跨后端核对事实；内层各域有自己的权威和版本。外层与仪表盘只读取裁剪视图，写动作经可信控制入口。

一条输入的目标路径：

`渠道身份核验 → 持久接纳/去重 → Conversation/Topic/受众与版本 → 快路或获准core判断 → ReadView → 原生Session → 草稿 → 重新核对授权/版本 → Effect派发 → 独立回执`

后台路径：

`worker/组件/外部源事实 → 持久事件 → 订阅投递 → 背景引用更新 → 需要时获准core续评或replyer加载 → 精确加载回执 → 合法通知`

其中每个箭头都是需要失败/重启/重复测试的边界，不要求全路径在一个事务里。尤其必须区分：

| 事实 | 不等于 |
|---|---|
| Event 接纳 / ack | 模型已读到上下文、任务已完成或消息已送达 |
| Proposal 合法 / MemoryOperation 批准 | 已写入另一后端 |
| 原生 user/message 已追加 | 已 flush 且能独立持久回读 |
| 草稿生成成功 | 仍获准发送、已发送或已送达 |
| 取消请求受理 | 在途动作已停止、外部效果已撤销 |
| 能力声明/可用/工具成功证据 | 本次 Mandate、预算或完整费用已满足 |
| 控制库 commitSeq / 内层 stateVersion / native seq | 全局统一版本或跨后端原子快照 |

## 2. 系统 1：接入、对话与话题协作

**已有边界：** 本地 Conversation/Topic、受限 replyer、背景与精确加载、Lab 双频道限定样本；真实通用平台及完整多对话行为未验。

**剩余目标：**

- 建立平台/account/channel/thread/message/revision 的规范化身份。平台和账号标识来自适配器可信元数据；正文中的姓名、角色或“我是owner”不能提权。入站接纳必须持久，平台重送/重连沿用去重域。
- 每个渠道 Conversation 保留稳定业务身份和原生 Session 绑定；正常新消息、纠正代次和任务完成不能无故创建新 Session。平台编辑/撤回、受众变化或暴露来源撤回按真实影响失效。
- Conversation、Topic、Task、Session 是不同对象。话题合并/分离通过带版本的关联与事实归属完成，原始渠道/受众/来源不可抹掉；不把两个频道原生日志物理拼接。拆分后保留血缘与各自可见范围；不沿新关联扩大旧授权。
- 背景按事实来源、版本、可见受众、有效期、撤回水位更新；shared topic 仅提供仍获准的引用。任务完成/外部触发先形成可信事实，再决定是否需要通知谁，而非广播到全部关联频道。
- 单会话按因果串行，跨会话有界并行与公平；持续输入分组/纠正要区分无关噪音、相关补充和可信停止。背压可见，不静默丢掉已接纳工作，不让空闲线程占执行槽。
- 发送使用统一 Effect，精确绑定收件人、频道、输入代次与当前授权。生成、排队、平台接纳、送达、已读分别记录；平台不提供某类回执时显示未知，不能由本地账本推定。

**完成标准：** 02中的多频道、话题合并/拆分、同名身份、任务后台完成、连续纠正/删除、洪峰公平与发送未知场景均通过；实际选定平台另有独立适配与送达证据。对应 V02–V05、V13、V23–V25。全拒绝或全静默不算隔离成功。

## 3. 系统 2：Agent 与组件共用事件系统

**已有边界：** 类型目录、持久发布/订阅、投递领取/ack/retry，Task 完成到背景的原子消费。Agent 工具工厂存在不等于已挂入原生 Session。

**剩余目标：**

- 为 AI 提供可发现的事件类型、字段/版本、允许作用域、订阅条件、发布与查询回执。复用同一持久服务，Agent 和普通组件均可作为发射者或订阅者。
- 真实挂入获准 core/worker 的受限工具环境，并验证 Agent→Agent、Agent→组件、组件→Agent、组件→组件四条路径。replyer 默认零工具；若未来要改变，必须单独证明权限和模型边界，不能顺手开放。
- actor、来源可信等级和可发类型由宿主注入。Agent 可以发布获准观察/请求，不能伪造 `task.succeeded`、独立核验回执、owner授权或账目事实。
- 完成一次性等待、期限/取消、时间触发、外部变化触发、声明式订阅及受控续评。订阅有所有者、作用域、修订、激活代次；变更/撤权后旧投递不能恢复旧资格。
- 明确创建订阅与取得初始快照之间的水位，防止漏掉边界事件；至少一次投递通过去重与幂等消费实现应有业务效果，不承诺不可能的跨外部系统全局 exactly-once。
- 背景标记更新零模型；没有新事实不轮询模型。等待不占 worker槽，fan-out/重试有界，毒事件与坏消费者隔离；自触发/环形订阅、错过周期和时钟变化有明确规则。
- 原生 inbox负责待加载语义；持久投递账本不是第二套聊天历史。消费ack与context-loaded分开，停止/重启后的续接不得绕过当前授权/预算。

**完成标准：** 不只单测工厂，要有实际本体原生 Session 内调用、持久回执、背景更新/合法唤醒的因果链；无变化时零新增推理，重复/迟到/恢复不重复效果。对应 V03、V04、V10、V12、V14、V21、V23、V24。

## 4. 系统 3：core 判断与持续规划

**已有边界：** 只在 owner 预授权的有限 local-note 事项中判断，有两轮同 Session 的真实样本；不是开放式规划器。

**剩余目标：**

- 快路处理不需要行动的读取/表达；遇到目标推进、内层提案、订阅或多步任务时升级 core。是否升级、消耗哪一授权预算、为什么唤醒都可解释。
- 在明确目标、完成条件、预算、期限和允许能力中形成结构化计划：步骤/依赖、需要的事实、预期产物与验证方法、停止条件。模型只提交候选，可信控制域验证并接纳。
- 根据新事件、任务结果、事实纠正和能力变化修订计划；记录版本与推理依据引用。旧版本候选、已取消目标、重复事件不生成新资格；更改目标范围不能由模型自行扩大 Mandate。
- 支持真实多步任务与必要并行，而非把所有任务硬编码成固定便签。拆解应产生可验证产物；需要人的新决定时给具体缺项，允许独立步骤继续推进。
- 用六域受限视图辅助判断，但关系/情绪/人格不能覆盖权限。事实冲突、不确定性和来源缺失必须显式保留，不用模型自述填齐证据。
- 安静期不空转；采用事件/截止/明确重试策略。重复失败、超额、未知调用、取消、无法取得当前视图有可区分状态；未知 round 不因租约到期自动重跑。
- 原生 Goal 的 complete 只能在独立完成证明成立后提交并核对；本地批准、原生命令结果和最终完成各有证据，不建立第二套并列 Goal 生命周期。

**完成标准：** 有既能成功推进的多步合成业务，也有合理停下/等待/拒绝的负例；计划修订和最终交付可追到事实与独立验证。对应 V02、V06、V09、V10、V13、V23–V25。

## 5. 系统 4：目标、任务、worker 与外部效果

**已有边界：** Task/Assignment、共享授权预算、原生 worker、本地产物与独立核验，有限 Goal 生命周期；完整故障矩阵与多资源执行未齐。

**剩余目标：**

- 将 Task扩展到目标所需的实际工作类型，仍经固定schema、范围、资源、预算、完成条件和核验器准入。worker 只取得任务需要的工具与数据，不因为Agent具有工具就得到全局权限。
- 一任务可有明确的依赖、取消、修订与恢复流程；每次 Assignment 有独立执行资格和栅栏。同资源最多一个有效执行者；旧worker迟到结果不可覆盖当前结果。
- 工具执行都形成 Effect/op identity、payload摘要、重放类别、派发事实与独立回执；幂等操作可按原身份核对/重试，非幂等未知不自动换任务、Session、设备或ID重试。
- Task工作完成、记忆发布、通知送达分别记录。文件存在不自动代表内容正确；模型称“已写入”不替代独立文件/平台/设备观察。
- 取消先持久失效，再尽力cancel/drain；对已发生效果保留结果和补偿建议，不能把取消当回滚。重接必须沿原Effect核对，找不到证据保持unknown。
- 逐设备区分 direct 与 gated。direct是中心单次检查，不宣称设备端有栅栏；只有真实端侧验证支持才允许跨断连/重启排队执行。危险资源未知时不改派到另一端。

**完成标准：** 完整并发抢占、迟到、在途取消、已执行未回执、断连/重接、重复/乱序、worker崩溃与重载路径无重复非幂等效果；允许的正常任务必须完成。真实设备按逐项资源范围验收。对应 V10–V12、V18–V24、V26。

## 6. 系统 5：六部分内层与只读视图

当前只有 memory 和固定 ability 的限定路径；关系、情绪、认知、人格四域仍 unavailable。六域不是六个必需模型，也不能用六个空对象/占位页面宣布接入。

| 域 | DSH需完成的能力 | 写权威与硬边界 | 完成证据 |
|---|---|---|---|
| 记忆 | 来源/时间/受众、保存/整理/纠正、精确与语义检索、冲突处理、撤回/物理清除、索引重建与跨对话使用 | 正文后端单一权威，索引非授权；MemoryOperation跨服务状态真实；纠正保留必要来源链，删除按政策传播至派生、缓存、已暴露上下文及备份恢复屏障 | V07事实oracle、V16删除链、V25检索与使用质量；后端故障与迁移实测 |
| 关系 | 稳定主体映射、同名区分、角色/成员关系、交互事实及有来源的判断 | 不凭昵称自动合并；推断可撤回，关系亲疏不赋权；私聊事实不能因关系关联进入群聊 | 身份/受众矩阵、证据纠正与跨群隐私、误合并为0 |
| 情绪 | 有来源的当前情绪状态/经历影响、时间衰减或回顾规则、表达调节 | 是可解释系统状态；不能把模型臆测当人类心理事实，不决定授权或抹掉客观事实；删除来源时派生可处理 | 同输入/时钟可复核状态变化，噪音与刺激不越权，合理正例表达与安全负例均通过 |
| 认知 | 有证据的认识、假设、置信/冲突、复盘结论、可修订的行动经验 | 事实与解释分开；结论不能凭自述变成工具成功或世界事实，旧来源撤回使依赖结论失效/降级 | 冲突/纠正/复盘/过期数据用例及读取无写，变化可归因 |
| 人格 | 稳定Profile/价值与表达偏好、授权变更、慢变自我认识与版本 | 普通聊天不能改稳定人格、使命或控制策略；若允许学习，变更需明确策略/来源/回顾/审批规则，不自动把用户语句写成新系统提示 | 无合法变更100轮保持稳定；合法变更成功并可追溯；旧版本视图失效 |
| 能力 | 已部署工具/技能声明、当前依赖/健康、实际成功证据、环境版本、失效与撤回 | 能力≠授权；固定local-note为informational，unknown proof允许原授权首次任务；动态候选不能继承例外，安装/权限/执行按各自范围；不能建另一套工具执行器 | 固定新绑定下普通任务proof待补；动态变化矩阵和真实工具范围另验，至少保留原V09门槛 |

Ombre的 feel/review/I 等仅在公共接口、来源/删除/恢复语义与独立证据满足时复用；缺少接口不能通过直接写其私有库伪接线，也不建立第二份可独立修改的记忆权威。可调整适配或选择替代，但须有迁移、来源和许可记录。

**ReadView共同要求：** 实际发布域能力与可用状态；unavailable不伪装成空数据成功。每域保存authority/version/来源/删除屏障，禁止用max(version)拼成“全局最新版”。捕获metadata与读取正文分离、返回前再次授权；跨受众裁剪发生在正文暴露前。Event ack与context receipt分开，来源已暴露后撤回须使受影响原生上下文/草稿不能再用于发送。普通新消息继续复用Session。

**完成标准：** 每域有完整写入→发布→裁剪读取→使用→纠正/撤回→恢复链路及至少一条实际业务正例，不以schema齐全替代。对应 V06–V09、V16、V23–V25。

## 7. 系统 6：模型、Session、上下文与缓存

**已有边界：** 受限角色、官方完整消息、精确持久回读、短会话热复用和有限主调用计量；长史恢复/压缩/完整费用待完成。

- 先按03接管3J，完成超过2048条历史的真实可行路径和恢复后输入一致性；不能靠全部拒绝通过。承认原生分页、维护阶段和跨后端水位限制。
- 原生生命周期覆盖create/reuse/resume/cancel/archive/reload，任务/话题关联与Session身份持久；正常会话代次失效不每轮换Session。未知inbox不丢弃或默认执行，恢复后的模型工作须重新取得当前执行资格。
- 利用DSH原生压缩/恢复，保存压缩前后业务必要事实和来源权限；不要自行重写用户历史。压缩/标题/路由fallback等旁路要么被明确禁止，要么纳入同等预算、权限和计量，不能未计费地偷偷开启。
- 保持稳定系统/工具前缀，增量装载获准背景；动态时间戳、无关状态或重排前缀不得无理由破坏复用。发送新请求前检查新鲜度/TTL/授权；缓存命中不能豁免校验。
- 模型记录至少包含实际路由/模型/effort、步骤/请求/输出限制、超时、重试、观察到的用量和完整性。token预留/事后对账不承诺provider精确预收费硬上限；缺失用量保留hold/unknown。
- 角色和数据隔离贯穿创建/恢复/实际请求：replyer只读表达、worker局部执行、core候选规划。检索片段、工具输出、其他Agent消息和历史注入都不是新权限。

**完成标准：** 长历史、继承、合法恢复/压缩、丢失回执、取消/重载、旁路计量的正反例通过；真实缓存收益由字段/对照证据支持，没字段就未验证。对应 V04、V13、V14、V24、V25。

## 8. 系统 7：身份、授权、预算与控制

- 从local-owner扩展到真实渠道身份/角色/受众和设备配对；trusted actor由宿主注入，普通文本不能发出授权、恢复或控制指令。
- Mandate是有主体、范围、动作、资源、期限、预算和版本的授权；订阅读权、检索权、保存权、发送权、执行权互不自动推出。子任务委派不扩大父范围。
- admission、claim、原生dispatch/实际效果发布与结果提交各自核对当前资格；暂停/撤权先持久栅栏再cancel，恢复不复活旧permit，模型候选与缓存都不能绕过。
- reservations覆盖各实际调用/效果，未知用量持续占用；已知settlement/超额/unknown单列。新的assignment或Session不能洗掉旧预算或外部未知。
- 凭据仅以可信引用解析，尽量短生命周期；不进入模型上下文、普通事件、日志、ReadView、UI或交付包。轮换、缺失、失效表现为能力不可用，并保留最小诊断。
- 明确普通停止、紧急停止和物理设备停止各自能力；停止后新的动作资格失效，已发出且无法撤销的动作仍需独立结果核对。

**完成标准：** 全身份/工具/受众/恢复/错误路径越权成功为0，同时正常获准动作成功；停止有实测时延和持久性，秘密canary无泄漏。对应 V02、V04、V10、V13、V16–V20、V24、V26。

## 9. 系统 8：数据、生命周期、恢复与备份

- 单writer与唯一有效数据根，运行锁/工作目录/组件版本明确；DB锁、资源耗尽、只读磁盘、失败迁移不能阻塞可信停止或留下可派发半状态。只在临时隔离根故障注入。
- 同库事务只承诺同库原子性。跨Ombre、索引、原生Goal日志、设备的操作用独立operation/receipt与核对流程，不冒称共同回滚。
- 唯一检查点服务调用各后端正式backup/export，清单覆盖控制库、正式记忆、必要索引/重建信息、Goal Session与附件、授权/删除/unknown水位、版本/根/引用闭包。组件各自hash相同不自动证明共同截面。
- 恢复默认maintenance/disarmed；核对最新独立停止/撤权/删除账本和运行世代，防旧备份复活旧能力或权限。最新屏障无法证明时保持恢复锁。新恢复实例不能与旧实例双写。
- 先在新隔离根恢复并验证业务，再按明确范围切换；不自动覆盖live根或删除最后良好副本。未知效果沿原身份核对，不因恢复而重新派发。
- 独立备份使用真正独立故障域及必要加密/密钥恢复；同盘副本只是本地恢复资料。RPO/RTO按已验证副本和实际演练报告，不用计划任务“成功”代替可恢复性。
- 外部监督器只管理宿主进程，遵从可信停止与退避；不得建立第二个会自己规划/执行的识雨核心。

**完成标准：** 迁移/容量/崩溃断点、跨组件恢复、旧删除/授权屏障及独立灾备演练通过；没有指定真实目的地的部分明确未激活/待验。对应 V01、V06、V12、V14–V17、V19、V21–V24、V27。

## 10. 系统 9：运行仪表盘

- 展示真实生命周期、正在处理什么、当前目标/计划/任务、队列和等待原因、频道/话题/背景同步、事件投递与接收状态、六域可用性、依赖/设备、模型/Session/用量与未知、恢复锁与证据。
- “已接纳/运行/待核对/失败/停止/已送达”等状态来自权威数据；显示来源、时间、新鲜度和必要的版本，不用静态假数据或默认绿灯。

**完成标准：** 已实现所有路径可观察且实际控制有回执，1000次刷新无业务副作用，unknown/stale/unavailable区分，UI与真实权威状态一致；资料工作台保留完整。对应 V04、V05、V09、V13、V14、V23、V24。
