## 2. 为什么需要3J

已提交实现的 `coldNativeInbox` 一次读取最多2049条事件，超过2048条直接拒绝。它使用官方reader/projector，已检查连续seq和尾读，但未核对投影水位和完整继承元数据。随着同一个Session长期复用，合法历史也会触发拒绝；短会话、两轮回忆或一次停止后重载无法证明长期可用。

本轮草稿开始加入有界分页、两遍逻辑历史比较、EOF/尾事件检查、Snapshot元信息与结构化错误。默认草案为512事件/页、32768事件、32MiB序列化事件、256次read、10秒协作期限，并取业务更早取消。这些是**待验证工程限额**，不是用户需求中的永久最大历史长度，也不是SDK内存硬上界。DSH可以按真实性能调整，必须保留明确失败/容量行为；长期目标还要评估DSH正式压缩/检查点能力，而非不断调大数组或无声丢历史。

## 3. 已静态核实的固定SDK契约

证据为已安装 DSH `0.2.1-rc.5` 的六个公开包源码；[可移植静态元数据](<资料/3J-原生契约静态核查.json>)包含版本、精确源文件SHA256及行号。只读源码，不是执行过SDK或宿主探针。若宿主升级，重新核对相关契约。

| 接口 | 已确认含义 | 禁止推断 |
|---|---|---|
| `read(offset,length)` | offset是逻辑事件seq；length是最多返回事件数；全历史从0读，包括继承前缀 | 短页不必然是EOF；`eventState`不是事件数 |
| `session.seq` | 下一个事件序号，也就是当前逻辑日志长度 | 不等于最后一条已投影seq；不等于控制库commitSeq |
| `restore({},events,0,header,inheritedEventCount)` | 官方投影对传入完整连续前缀工作；返回snapshot/checkpoint | 不能据此证明传入历史完整或已持久化 |
| `snapshot.asOfSeq` | inclusive最后seq；N事件为N−1，空历史为−1 | 不能当eventCount，不能只看inbox存在就忽略它 |
| header / inherited | header.id绑定Session；preset需匹配；继承计数是独立字段，需要合法整数/范围校验 | 不能缺失默认0；不能从header任意推导。已核品牌拒绝−0、非seededSession继承长度应为0 |
| JSONL reader handle | 每次read可观察新追加；header/inherited在open捕获；长度倒退可拒绝 | 不是固定快照，不能检测所有同长度早段变化。底层可能整日志读入再切片，且有revision缓存 |
| native resume | 可能在setup前追加中断收尾、`session/end-seed`，setup/publish也可能追加 | 不能猜固定+1，不能无区别拒绝合法恢复后缀，也不能允许任意新user输入 |
| `runMaintenance` / flush | 前者是Agent阶段互斥；后者等待持久监听处理且需要结果为true | 都不是禁止任意组件调用Session.append的写锁，也不是跨控制库/Session原子事务 |

两遍相同完整读取能够发现观察期间的许多改写，但不是任意外写者条件下的原子快照。使用官方append-only合同及独占业务操作，并明确每次观察/使用的边界，不能写“完全没有竞态”。

## 4. DSH必须完成的设计与接线

### 4.1 reader与投影

审阅草稿，而非默认接受：验证所有seq连续、页长度不超请求、空EOF、总量/字节/次数/期限、header.id/preset/继承范围、精确投影asOfSeq。第一遍保留有界事件用于一次官方投影；第二遍可以逐页比较/摘要，不保留第二整份历史。不写另一份持久history或私有checkpoint。

取消/超时需要关闭handle并避免悬挂任务；不能通过Promise.race遗弃后台读取。SDK若只协作响应取消，报告真实限制，不宣传硬实时超时。读/投影/close错误均不得给出加载成功回执。

### 4.2 恢复前后身份连续性

保留恢复前未知inbox拒绝。恢复后在原生维护阶段flush、重新冷读，并同步核对live Session对象/id/header/preset/继承/inbox与seq；使用水位必须与原生观察对应。

**仍待DSH定案：** 恢复前已检查历史与恢复后新基准如何保持前缀身份，以及哪些是可信原生恢复/固定标题后缀。直接丢掉恢复前基准、无条件相信恢复后基准，会吞掉冷读→resume窗口的异源输入；只比较count、tail或空inbox也不足以证明全史未变。需要精确、可解释的规则与正反例，不能仅把所有变化拒绝来凑安全成绩。

### 4.3 await与输入边界

所有授权等待之后、本次写入或followup之前重核基准；固定标题等合法写入也要纳入已观察新基准，不能假定它们不改seq。

已发现但**未实测、未修复**的静态反例：load-only在`authorize('append')`等待时，另一组件直接追加foreign `user/message`；它可能不改inbox，旧hook也可能只拦生成相关事件。仅精确回读本次消息和检查空inbox，仍可能错误ack。需对本次允许的完整message ID/hash建立边界，记录异源输入并阻止错误加载/发送回执；不能删除未知消息来恢复“干净”。

Core判断中的bound/onDispatch/dispatch回调也可能await；恢复基准检查不能只放在进入execute前。派发前与真正进入模型后的状态分别处理：未发生调用可据可信证据结算零；可能已派发却无回执时保持unknown，不能以错误类型猜零费用。followup后继续原有pre-step/cwd/精确消息/单主调用约束。

### 4.4 明确未完成的接口

agent暂停时报告：`assertNativeColdInboxCurrent`尚未实现/导出；`resumeFrom/expectedPrefix`前缀证明没有实现；−0和非seeded继承长度规则尚未补入；旧测试仍假设2048上限且部分夹具缺header.id/asOfSeq。以上是审阅入口，不要求DSH保留这些拟议名称；必须保留其行为目标。

## 5. DSH需实现的测试集合与验收

| 场景 | 必须观察到的结果 |
|---|---|
| 空史、2048边界前后、远超一页的合法史、页间inbox插入/移除、继承seed | 恢复到正确官方投影；同业务Session身份保留；不能只证明超限拒绝 |
| 短页、缺号、重复/乱序、页超量、坏header/preset/继承、−0 | 合法短页继续；其他失效无接受回执/派发，资源释放 |
| 读取中/EOF后/投影中追加；同长度早段变化、缩短 | 被检测变化拒绝或按明确受信规则重取；不默默拼成混合历史 |
| 原生合法中断收尾/end-seed/固定标题与异源user混入 | 合法恢复能成功；未知输入不能被当作恢复噪音丢弃或自动执行 |
| 授权await、onDispatch await、冷读后live.seq/inbox变化 | 最终接纳门拒绝失效基准，不生成错误context receipt或草稿发送资格 |
| 取消、期限、读/投影/关闭失败、关闭后迟到 | handle/agent生命周期可核对；无静默新Session、无重试未知效果；错误可诊断不泄漏正文 |
| load-only、replyer、Core各自正常长史路径 | 精确本次原生消息+flush+独立回读才给receipt；生成路径在明确预算下正常推进，且已有权限/主调用限制不退化 |
| 源码/编译/宿主证据 | 模块夹具、固定SDK静态、编译产物、零模型宿主、后续有界真实长对话/压缩分层，不相互冒充 |
